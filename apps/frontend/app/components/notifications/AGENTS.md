# Notifications — Agent Instructions

Loaded with the [frontend guide](../../../AGENTS.md); its § numbers are referenced here. Edit here, not there.

- **Notification center** (`components/notifications/NotificationCenter.tsx`, responsive `NotificationsSheet.tsx` at `?notifications=true`): derivation is client-side (`reminder-engine.ts`, 60s scan in `use-notification-center.ts`, reads start after workspace reveal; routine reminders read today's range data and fire only while today's log is open); read/dismiss/defer state is a localStorage-backed module store with best-effort notification-state API sync. Device delivery is one shared state (`use-device-delivery.ts`, `lib/notifications/device-delivery.ts`): every device registers by a stable `installId` with a `kind` and a platform-derived `label`, and the server's device list is the truth for whether reminders are on here (a localStorage mirror only covers a cold start with no network). `deviceStatus`: unsupported · install (iOS tab) · denied · off · local (Cadence alerts itself while running; desktop always) · connected (Web Push subscription saved, so reminders arrive with Cadence closed). `DeviceDeliveryRow` (Settings → Notifications) enables, sends a test through the real path and turns this device off; `DeviceList` manages any device from any device. `duplicateRisk` flags a desktop app plus a pushed browser on one computer and only ever suggests, never silences (a missed reminder is worse than a repeated one). Enabling requests permission straight from the tap; a granted device re-registers on load; sign-out forgets this device. `use-browser-notifications.ts` alerts only in `local` status, via `dueAlert` from `@cadence/domain/reminders` (the server's policy: lead time, 15-minute late bound, dismissal/deferral; quiet hours and pause hold alerts until they end, never hiding list items), with a per-account persisted claim that a failed send gives back and the occurrence key as the notification tag, so a local and a pushed alert collapse into one. Nothing polls for freshness: `use-live-sync.ts` (mounted once in `providers.tsx` `AccountSync` with the zone and wake syncs, every signed-in client but the quick-capture window) holds a WebSocket to `/api/v1/live` (its `PAGE_ORIGIN` rides along, as on every API request's `X-Cadence-Origin`, so its own writes don't ping it) and, when the server's version `v` changes, marks the live roots (tasks, projects, inbox, tags, habits, sections, subtasks, settings) stale and refetches those on screen once the WAL and in-flight mutations are idle, hidden windows included; a socket's first `v` refetches only if it changed or a live read had failed. It pings every 45 s, reconnects with backoff (cap 30 min) using the server's in-memory reconnect ticket, a JWT only without one (a failed token fetch retries too; after `4429` not sooner than 60 s), stops for good on `4001` (account deleted) and, on a second `4401` (token rejected), until the window is shown, online or woken. `NotificationsTab.tsx` groups settings by what alerts; Pause sets `notifications.pausedUntil`; "My day" morning/evening drive deadline/event alerts and the Defer choices (`computeDeferUntil`); Daily summary is shown inert (no sender exists). Windows only: `backgroundDelivery` in `use-desktop-command-preferences.ts` (device preference, not account settings) keeps delivery after the window closes; the Rust half is in `apps/desktop/AGENTS.md` and takes effect on the next launch.
