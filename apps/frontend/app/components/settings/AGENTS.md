# Settings — Agent Instructions

Loaded with the [frontend guide](../../../AGENTS.md); its § numbers are referenced here. Edit here, not there.

- **Settings:** `?settings=` opens the desktop dialog or compact `SettingsSheet`; `menu` shows categories (Shortcuts hidden on phones) and sign-out, with Profile & Security inside Settings. Compact details replace the same history entry; close returns to the underlying route. `SettingsContent.tsx` shares tab content (deep-linkable tabs: about, account, appearance, assistant, privacy, datetime, integrations, location, notifications, shortcuts, tasks; `settingsTab` sends moved ids, like the old `ai`, to their new tab) and each category's `keywords` (its row titles, kept in step with the tab) so desktop search finds settings, not only tabs. Each setting has one home: no row appears in two tabs. Merged optimistically, cached locally. Photo background: `settings.appearance.backgroundImage` is server-owned (upload/delete routes only); the file comes through authenticated RPC and is cached in IndexedDB (`lib/themes/background-image-cache.ts`, cleared on sign-out; writes serialized and guarded against same-tab sign-out/deletion); the provider keeps the active image's object URL alive across routes; choosing a mode or preset leaves photo mode without deleting the photo; `BackgroundSettings` mounts `PhotoCropDialog` (`react-easy-crop`: drag, pinch, wheel or sliders), and only confirmation uploads. Cadence accents are disabled in photo mode. `settings.location` is owned by the Location tab and read through `useUserLocation` (weather, holidays); only an explicit user action may call `navigator.geolocation`, and location/weather queries carry `meta: { persist: false }`.
