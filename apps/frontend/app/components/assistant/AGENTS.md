# AI Assistant — Agent Instructions

Loaded with the [frontend guide](../../../AGENTS.md); its § numbers are referenced here. Edit here, not there.

- **AI Assistant** (`components/assistant/`, `hooks/ai/`, `lib/ai/`, `stores/assistant-store.ts`): `AssistantSidePanel` composes header/thread/composer and overlays; `use-assistant-conversation` owns chat/history/cross-tab recovery, `use-chat-attachments` owns uploads; the chat lives in `lib/ai/live-chat.ts`, not the panel, so closing the panel never drops a reply mid-stream; while the last thread loads the thread shows `RestoringThread` (a skeleton), never the empty welcome, and `assistant.resumeLastChat` off makes the first open after start a new chat; a reply finishing unseen (panel closed, tab hidden) sets `replyUnread`, which `use-assistant-reply-watcher` clears on open and which feeds to the rail's `ActivityBadge` and the dock sigil's `notice` morph. Streaming uses `chat-transport.ts` over `@ai-sdk/react`. Tool results render as widget cards (`components/assistant/widgets/`) dispatched from `tool-registry.tsx` (reads are a chip, except `find_time` and `fit_day`, which get `widgets/PlanCards` once answered: Fit today's own preview, or one gap with Place · Another time, placed only by the person's tap); each card's `ctx` is typed by its tool (`ToolRenderContext<"create_tasks">`, from the backend's `ToolIO`), so a renamed field fails tsc. Every write runs on the server; a write card (`ApprovalCard` shell; captures in `CaptureCards`, lists/tags/focus views in `OrganizeCards`) renders from `part.input` and, while the server waits (`approval-requested`, latest reply only), answers with `addToolApprovalResponse`; unticked rows send a decline naming them so the assistant re-proposes the rest. `useChat({ sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithApprovalResponses })` then sends only the answers (`chat-transport.ts` `approvalAnswers`) and the reply continues; caches refresh as each write lands (`refreshAfterWrites`, once per call; `onFinish` catches the rest). In dev each turn logs one `[cadence:ai-turn]` line, the client half of the server's `ai_turn`. Parts that didn't wait render settled; an older reply's open request shows "Not answered". A new-task card shows every field it sets (list and section via shared `TaskDestination` queries; words read from a photo under "From your image"). Retired `propose_*` parts render read-only (`RetiredProposal`); writes the server no longer offers keep their old card through `RETIRED_WRITES`. Capture-to-inbox never waits. `ask_user` renders `AskCard` (latest reply only); the answer goes as the next user message (`replyToQuestion`, leaving the draft alone). The composer's approval mode (`assistant-store` `approvalMode`: `ask` default · `auto` · `full`) is sent with every turn; the server decides which calls wait. `assistant-store` `surface` (not persisted) marks an embedded chat: `weekly-review/ResetChat` composes `AssistantThread` (its own `empty` greeting) + `AssistantComposer` with `useAssistantConversation({ open: true })`, closes the side panel, sends `surface: "weekly_reset"` and keeps its one thread id per device until Done. Assistant markdown never renders images; `/…` and `?settings=<tab>` links navigate in-app (closing the sheet on compact), everything else (including `//…`) opens externally. The assistant's guide lives in `apps/backend/src/prompts/help/*.md`: a user-visible change that makes it wrong edits it in the same change. Turns render parts in stream order (`buildSegments`). Photos (picker, paste, drop) are compressed on device (`compressChatImage`: 1600px WebP ≤ 1MB, EXIF dropped) and uploaded on attach to `POST /ai/images`; Send waits for them and the turn carries only `cadence-image:<id>` file parts (no filename). `ChatImages` loads them through an authenticated fetch, or shows "Image expired"; photos open in `shared/ImageViewer`. The per-message cap comes from `GET /ai/usage` (`images.perMessage`); the attach control warns near the 20/day cap and blocks at it (`describeImageAllowance`). `AI_IMAGE_LIMITED`/`IMAGE_NOT_FOUND` offer "Send without images". Slash commands (`lib/ai/slash-commands.ts`, `SlashCommandMenu`; exact match only, anything else sends) run in the app: `/usage` (`UsageOverlay`), `/clear`, `/history`, `/memory` (opens "What Cadence knows"), `/settings` (via `useStepOutOfAssistant`, shared with in-chat links). `UsageMeters` (`describeUsageMeters`, `use-ai-usage.ts`) is shared by that overlay and Settings › Assistant. History rows archive in one click; `ClearArchiveButton` (confirm, then `DELETE /ai/conversations/archived`) sits under Archived and in Settings › Assistant. **Memory:** the mode is server-owned (`hooks/ai/use-memory.ts`, `POST /ai/memory/mode`; never part of the settings patch). `MemoryCard` is a labelled region above the thread while the stored mode is `null` (Basic is already on; the message box works underneath): Switch to Full / Keep Basic / Turn off, no toast (it points to Settings, where any choice changes back); `MemoryOverlay` is "What Cadence knows" (header brain button, `/memory`, or Settings › Assistant via `assistant-store.memoryOpen`): Full's 3-month catch-up as a rough bar (`catchUp.progress`) then a Done line for a week, plain sentences, tap for source and Forget (Undo toast), changes by chat through its pinned box, 30 facts at a time (Show older), search past 30 items; an unchosen memory reads "Basic (default)". `RememberReceipt` renders `remember` as one line with Undo (none for `kept`, a fact already known), and reads the memory page for what still exists, so after a reload an undone save says "No longer remembered"; the per-chat "Don't learn from this chat" switch is in a conversation's menu. In Full, `useUpdateTask` calls `offerDuration` (`lib/ai/duration-prompt.tsx`) on a completion; the server decides and reserves the day (`POST /ai/memory/duration/ask`) and the toast (`DurationChips`: About right / Shorter / Longer against the person's own plan, never Cadence's guess or the 60-minute default (`relativeReference`), else 5 min … 2 hr, More…, Other taking `90`, `1h20` or `30-60`) shows Saving…, then "Saved · Change" only from the stored row, or "Couldn't save · Retry" with the value kept; a 409 (task reopened) closes it quietly, and its countdown waits while saving, failing, hovered or focused. A done task shows `TookRow` in Full ("Took 45 min", or "Took · Add" with no answer; same states); a routine's day marked done shows `RoutineTookRow` (one per marked time) in its detail with "Usually about 30 min" when the estimator supports it, and Place's minutes count a due routine by that length. `TakesRow` (untimed, not Fixed, not done) is the task's one length: the estimate, else the guess from `useDurationGuess` (`GET /ai/memory/duration-evidence` through `@cadence/nlp/duration`, client-side like Effort) shown muted as "about 45 min" (supported, already the working length) or "about 45 min?" (tentative, sizes nothing); any chip stores the estimate with Undo, never the guess on its own. The mode it reads comes from the settings cache, which mode changes patch.
