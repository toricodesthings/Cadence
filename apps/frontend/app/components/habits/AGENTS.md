# Routines — Agent Instructions

Loaded with the [frontend guide](../../../AGENTS.md); its § numbers are referenced here. Edit here, not there.

- **Routines:** one range query (`useHabitsRange` → `/habits/weekly`, any start/end, under the `weeklyAll` prefix, keyed by start/end/timezone/archive state) feeds week, month and History, so every optimistic resolve covers them all; the week start comes from settings. `RoutineTodayBand` (ring + `shared/RoutineAgendaList`, current period only) leads the month and compact views; on a desktop week the grid's today column is the check-in instead, never both. Order is `sortRoutines` by this device's choice (the header ⋮: Date added default, Time of day, Name, Custom), never by today's progress, so a check-in never moves a row; each row's grip drags (`habits/SortableRoutines`), which switches to Custom and saves `sortOrder` (a midpoint, or the list laid out again; new routines go last). Week is `RoutineWeekRow` (done count only, never "of N"); month is `RoutineMonthGrid` (footer: check-ins, plus longest run when streaks show; never misses). Every day is a `RoutineDayCell`: any past scheduled day can be logged; click/tap toggles done (touch adds Undo), right-click/long-press opens Done · Skip · Clear (the Weekly Reset reuses it with `openRing`, so open earlier days show a ring); grids are one roving tab stop (`hooks/ui/use-roving-grid.ts`: arrows, Space, `S` skip, `E` edit). A routine's `colorAccent` uses the list palette via `routineTone` (default moonlit); a personal event's `color` uses the same palette via `eventToneStyle` (`--event-ink` stays AA); composers pick either with `shared/ColourDot`. Pauses run from today (`isRoutinePaused`), never hiding logged days. Menus and the editor share `useRoutineActions` (pause, archive, delete with Undo); a routine's saved app is its App pane under the summary (see **App links**). Steps (`habits/RoutineSteps`): a cell tap still sets every step, the day menu lists them, partial days show "2/3" (`stepProgress`). A routine **at set times** (`habit.times`, 2+ daily times; one time stays `targetTime`; never combined with steps; the usual time and `targetTimes` stay underneath for when it's turned off) is composed with `habits/RoutineTimes`: its cell tap (or, with a mouse, hover) opens `RoutineTimeChecklist` instead of toggling the day; steps and times share `RoutineCheckList` rows, Today/Routines show one row (`routineAgendaItems`), Schedule shows one block per open time (`habit-{id}--{day}--{time}`), and any whole-day COMPLETED sent through `useResolveHabit` becomes the next open time (`withNextTime`; `timeAction` stamps `at`).
