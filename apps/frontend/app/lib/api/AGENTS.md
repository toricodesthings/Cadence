# Offline Queue — Agent Instructions

Loaded with the [frontend guide](../../../AGENTS.md); its § numbers are referenced here. Edit here, not there.

- **Offline:** everyday writes go through `withOfflineSupport(toOp, apiFn)` (`lib/api/offline-mutation.ts`): offline, on a network failure, or while earlier changes wait, the op is queued in the per-account WAL (`offline-wal.ts`: Web Lock + BroadcastChannel across tabs) and the call resolves `undefined`, so `onSuccess` guards it and `onSettled` skips refetches via `wasQueued`. Each op type needs a `toRequests` case in `mutation-executor.ts`; replay is ordered, stops on network failure, drops edits to deleted items, holds later changes behind a failed one and sends no `expectedUpdatedAt` (last write wins per field). Note saves differ: they carry `expectedVersion`, an `opId` (the Idempotency-Key, fixed per payload) and their tab's `branch`; unsent saves fold only within one branch + base, a frozen (`attempted`) entry is never replaced, and a 409 is merged by `lib/notes/note-reconcile.ts` or parked as a `conflict` entry for Sync review (never appended to the note). Online-only: the assistant, settings, uploads, deleting lists/tags/sections. After reveal, `useOfflineWindow` warms the phone views (−7…+21 days) through their own cache keys (open lists via one bounded `GET /tasks/batch`, ≤3 transports at once), skipping fresh or in-flight lists and unsynced edits, and stops when hidden, offline, replaying, or while foreground queries fetch; it runs on start, showing, reconnecting and after reads, never on a timer (a tray window can report visible); the persisted cache lives 14 days (`gcTime` matches). Rows show `shared/PendingMark`; the banner's Review opens `SyncReviewSheet`; sign-out with queued changes or unsaved note text asks first (`useSignOut`).
