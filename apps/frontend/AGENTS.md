# Cadence Frontend — Agent Instructions

React Router v8 SPA (`ssr: false`, intentional) deployed as static assets on Cloudflare Workers. Consumes the shared backend ([`@cadence/backend`](../backend)) exclusively through a typed Hono RPC client — never invent client-only API contracts. This is also the source codebase for the [desktop app](../desktop): a `platform/` runtime boundary swaps web-vs-desktop behavior, so most code must stay platform-neutral. It embodies the **Twilight Sanctuary** design language; functional correctness and aesthetic integrity are equally non-negotiable.

## 1. Non-Negotiables

- Client-rendered SPA. Do not introduce SSR assumptions.
- All server data flows through **TanStack Query**; all API calls through the one typed Hono RPC client (`apiClient` in `app/lib/api/client.ts`, built on `authenticatedFetch`; `useApiClient()` returns it) — never raw `fetch` for backend calls and never `as any` on the client. Only the transports (`mutation-executor.ts` WAL replay and its Background Sync twin in `public/sw.js`, the assistant's `chat-transport.ts`) sit below it.
- Reusable hooks → `app/hooks/`; non-UI logic → `app/lib/`; shared UI → `app/components/` grouped by domain; Radix always through `app/components/primitives/`, never imported raw into domain components.
- No sterile SaaS styling: no white cards, harsh borders, gray dashboards. Prefer glass, shadow, ambient color, breathing room; readability and usable controls take precedence over effects. Never hardcode a one-off hex when a semantic token belongs in `app/app.css`.
- Notification settings fields are required in the settings schema — never optional.
- Mutations are optimistic-first: snapshot → update immediately → rollback on error → reconcile on settle. The screen shows only the end state, never a step on the way (a capture saved as a task appears as that task, never first as a thought).
- Toasts answer one question: "where did it go?" A happy path the person can see in place (a row appears, a check flips, a field saves) gets none. A toast is for: a failure (`toastError`); something that just left the screen (placed, moved, discarded, restored, converted, bulk), which names it (`toastName`) and says where it went in the description, with Undo when reversible (`toastUndo`); or a result that lands out of sight (email sent, clipboard, export, update ready). Reversible destructive actions have a working Undo; truly irreversible ones require confirmation (§7). Touch may add an Undo toast where a stray tap is likely (routine marks).

## 2. Tech Stack

React 19 · React Router v8 (SPA mode) · Cloudflare Workers + Wrangler assets · Tailwind CSS v4 (`@theme` in `app/app.css`) · Framer Motion + `tw-animate-css` · TanStack Query · Hono RPC (`hc<AppType>`) · Neon Auth (`@neondatabase/auth`) · Radix UI (wrapped) · Lucide icons · dnd-kit · Zustand · `react-markdown` + `remark-gfm` · `date-fns` · Vercel AI SDK (`@ai-sdk/react`, `ai` v7) for the assistant · TypeScript 7.

## 3. Runtime Shape

- Shell: `app/root.tsx` (HTML shell, fonts, error boundary, iOS home-screen meta: `viewport-fit=cover`, opaque `black` status bar since `black-translucent` leaves a bottom gap on iOS 26, iOS-only `maximum-scale=1` against focus zoom; `RESUME_ROUTE_SCRIPT` (`lib/resume-route.ts`) reopens the installed app's last workspace screen from the past 6 hours; dev unregisters leftover preview service workers) · `app/providers.tsx` (account-keyed query persistence + auth, persistent background, `WorkspaceStartup`) · `worker.ts`: serves SPA assets; proxies `/api/v1/*` through the `BACKEND` service binding (same-origin, no CORS preflight) and Neon Auth at `/api/auth/*` (cookie values forwarded verbatim, kept `SameSite=None; Secure`); exchanges the single-use `neon_auth_session_verifier` on the `/auth/callback` navigation, then leaves via a script `location.replace`. Both auth paths and `/api/v1/*` are in `assets.run_worker_first`; hashed assets get immutable caching from `public/_headers`, and a missing one gets a non-cacheable 404, never SPA HTML.
- `public/sw.js`: bypasses `/auth` and `/api`; serves navigations from the validated cached shell and refreshes it in the background, so Reload (update toast, chunk-error) first asks it to refetch (`cadence-refresh-shell`). Caches only the offline shell and validated hashed build assets (all precached, including shared desktop-named chunks: `react-router.config.ts` writes the entry closure first; activate keeps this build's and the previous one's), never auth responses, dev modules or mutable CSS; respects `no-store`. On Chromium its `sync` handler replays the offline queue while no tab is open. Reminders show through the SW registration (iOS has no `Notification` constructor). `push` shows what the server sent (a Declarative Web Push message or the older flat payload) and raises the icon badge while no window is visible; a tap posts `cadence:open` to a running tab (`useNotificationTapRouting`) or opens the target.
- Installed app: `platform/installed-app.ts` (`isInstalledApp`, which counts iOS's `fullscreen`; the icon badge; persistent storage) driven by `hooks/ui/use-installed-app.ts` in `MainLayout`: saves the screen to resume, mirrors the bell's unread count on the icon, asks once to keep storage; sign-out forgets both. Icons derive from `logo.png` (`icon-maskable-512.png` keeps the art inside the safe zone).
- Build env: `VITE_NEON_AUTH_URL`, `VITE_API_BASE_URL`. Deployed web builds ignore both: the API is `${origin}` (the Worker forwards `/api/v1`) and auth is `${origin}/api/auth` (`lib/env.ts`), so auth cookies are first-party — iOS/WebKit blocks third-party cookies and OAuth never completes; dev and desktop call Neon Auth directly. Worker runtime: `NEON_AUTH_BASE_URL` (var). App version/changelog are **not** env vars — `vite.config.ts` reads root `package.json` + `CHANGELOG.md` at build time (`release-info.ts`); `lib/constants/changelog.ts` holds no entries; it also stamps a per-build `CADENCE_BUILD_ID` and emits it as `/version.json`, which `providers.tsx` polls on the web (tab visible, every 10 min) to show a sticky Reload toast after a deploy.

## 4. Routes (`app/routes.ts`)

`/` (Capture — thoughts and tasks with no day), `/today`, `/schedule`, `/events`, `/upcoming`, `/completed`, `/trash`, `/project/:projectId`, `/tag/:tagId`, `/routines` (`/habits` redirects), `/weekly-review`, `/auth/:pathname`, `/connect` (MCP consent, §10), `/desktop/quick-capture` (desktop-only capture window), plus `/browse`, `/changelog`, `/help-feedback`. The privacy policy and terms live on the landing site (`CADENCE_PRIVACY_URL` / `CADENCE_TERMS_URL` in `lib/constants/app-info.ts`): in-app links use `components/shared/ExternalLink.tsx` (system browser on desktop), and the old `/privacy-policy` and `/terms` routes redirect there. Primary routes call `useRouteFocus()` to restore keyboard focus on navigation; a task whose row never shows there opens in its editor instead.

## 6. Design System

- **Purpose and hierarchy:** make the screen's next step obvious; keep routine information quiet and exceptions distinct. Group by the user's intent, with consistent alignment and spacing. Use the existing surface ladder to separate content, controls and overlays; decoration must earn its attention.
- **Agency and discovery:** choose useful defaults without setup; keep optional detail behind a labelled control. Every essential action must be reachable without hover, dragging, a gesture or a shortcut. Keep Back, Cancel and dismissal predictable; preserve drafts, and use the recovery rules in §7.
- **Familiarity and continuity:** the same action keeps its name, icon and outcome across surfaces. Adapt presentation to the platform and input through shared primitives and `useShellMode`, preserving drafts, selection, the viewed day and scroll position when resizing or opening details. Restore focus to the trigger on close, or a logical neighbour if it disappeared.
- **Calm craft:** motion explains what opened, moved or changed; it is interruptible, respects the existing motion preference, and never delays input. Delight means relief and dependable feedback, without celebration, attention loops or extra steps.
- Tokens live under `@theme`/`:root`/`@layer base|utilities` in `app.css`. Accent tokens (`--accent-primary|-soft|-dim`, etc.) are also Tailwind colors; `data-palette` on `<html>` re-tints everything (`lantern` default, `ember`/`rose`/`violet`/`sapphire`/`jade`/`copper`/`frost`, each with a daylight variant) — don't reference `--color-lantern` directly in new surfaces. Text on a solid accent fill is `text-[var(--primary-foreground)]`; bare `twilight`/`midnight` are not colors (they silently fall back to inherited text).
- Every surface must work under every mode combo: `data-theme="daylight"`, `data-accent="soft|vivid"`, `data-theme-preset`, `data-bg-mode="custom"`, `data-bg-image="on"` (photo background: tone + accents derived in `lib/themes/image-palette.ts`), `data-density="compact"` (target rules below still apply), `data-motion="reduced|full"`. Weekly Reset uses the shared background with tinted step panels; shared glass, utility overlays and Settings surfaces use these semantic tokens; `photo-shell-surface` gives persistent photo-mode chrome a light tint without a separate backdrop blur. Never patch per-mode inside a component.
- Surfaces climb one ladder, tuned per mode only in `app.css`: ground (the background) · `capture-surface` (Capture's composer, the page's top surface: `--hero-tint`, a step above cards) · `surface-shell` (page headers, right rail) · `surface-card` (a container that holds things: day cells, Week/Day panels, board columns, routine/event cards, Capture feed groups, the DaySpine; `data-lift` for hover, `data-state="today|selected"` to step up) · `surface-item` (a thing inside a card) · `surface-row` (stacked task/capture rows, a quieter step; states set `--row-tint`/`--row-wash`, never a bg) · `surface-control` (header controls: view pickers, Today, segmented groups, chips; `surface-control-accent` + `--control-tone` for Add buttons) · float (`surface-dialog`, `.glass-surface`; menus, popovers, selects and tooltips are `surface-floating`, see-through glass whose tint `--floating-tint` photo mode raises). Tints are the `panel`/`panel-raised` colors (the background's own bases; presets derive them), never accent mixes and never a raw `bg-white/[0.0x]` for a container; photo mode raises `--card-tint` without a per-card blur. Reuse existing utilities (`.glass`, `.glass-surface`, `.surface-floating`, `.aurora-accent`, `.dialog-glow` (+ `.dialog-glow-icon`, tone via `--glow-tone`), `.glow-*`, `.focus-pulse-soft`, `.cadence-toast`, `.offline-banner`, `.mobile-sheet-*`, `.safe-*`, `.scrollbar-*`). Anything touching the top edge pads with `safe-header-top` (compact headers) or `safe-top` (full-screen surfaces); the wide shell pads itself. Put standard `backdrop-filter` after its WebKit fallback so production optimization preserves it. Z-index: only `.layer-*` utilities, never arbitrary `z-[…]`; popover/menu content is already `layer-floating-ui` (above dialogs), so never re-layer it.
- Layout and input come from one hook, `useShellMode()` (`app/hooks/ui/use-shell-mode.ts`): `mode` is `wide` ≥1440px, `laptop` ≥1120px (≥768px with a mouse or trackpad, so a tall narrow monitor keeps the desktop shell), `tablet` 768–1119px touch-first only, `phone` <768px; `isTouch` is the touch-first pointer (`useIsCoarsePointer` is gone). Never raw breakpoints, `matchMedia` or `innerWidth` in components. A bottom sheet and its drag handle are touch-only (`isCompact && isTouch`); a mouse gets `ResponsiveOverlayPanel`'s full-height side panel at any width. Wide and laptop always show `IconRail`; it owns the destinations and the panel holds only what it alone has (Today, Upcoming, lists, tags), never a copy. Through `useNavPanel` (`hooks/ui/use-nav-panel.ts`), wide docks the panel (open state persisted) and laptop opens it as a drawer over the content (never restored; closes on navigation, outside click or Escape). Help uses `MainLayout navigationMode="rail"` at every size (no header, list panel, assistant or dock); `components/help` owns the feature/Intelligence directory and `?feature=` guide shells; feedback is disabled. Phone/tablet dock is Capture · Schedule · assistant · Routines · Browse; every compact header's leading control opens `MainLayout`'s workspace menu sheet (Today, Upcoming, lists, tags); it, Browse and the Settings menu share `layout/NavigationRow` rows in `NAV_GROUP` cards; Browse owns the profile quick view, Events, Weekly Reset, Settings, Completed, Trash, search and support. Route controls open as a drill-in popover, not a sheet. Every compact sheet is a `UtilitySheet` (heading or header slot, optional band and pinned footer, whose buttons keep focus in a typed field so the keyboard doesn't close under the tap; pickers (day, emoji, colour) go through `shared/PickerSurface`: a popover, or this sheet on a touch phone; `EmojiPicker` reads its colours from Cadence's tokens) over the draggable `ResponsiveOverlayPanel` (`fit` sizes a short one to its content), whose shell alone pads the bottom safe area (dropped while a text field is focused on touch) and rides the keyboard (`useKeyboardInset`, as do phone `Dialog` sheets), so footer controls sit just above the keys; an opening overlay always makes its own portal root live, so a sheet nested in another never stays inert. Compact task ⋮ is quick actions only (pin, duplicate, trash; editing lives in task detail); task right-click/long-press menus are desktop-only. Compact creation is always the bottom-right orb, never a centred pill (Browse, Trash, Completed and Weekly Reset hide it); Capture, list and tag pages use it as a direct add (`ContextualAddOrb directCapture`); lists open a `Composer` and manage sections in `tasks/ProjectSheets`, not inline fields. Compact has no global tag filter (`tag-filter-store` is desktop-only): tags open `routes/tag.tsx` (flat, smart-sorted, never reordered), `MainLayout` turns `?tag=` links into it, and the task editor picks tags in `TagPickerSheet`. Horizontal chip rows use `shared/ChipScroller` (wheel/drag without stray clicks). Compact toasts sit top-centre, clear of the dock; the toaster is its own body child, which overlays leave out of their inert sweep, so Undo works over an open sheet. Check both compact modes. Tailwind v4 tree-shaking: conditional/prop-driven colors need `@source inline(…)` in `app.css`, or an inline `style`.
- **Readability:** no text opacity below `/90` on twilight-muted text (enforced comment at top of `app.css`); opacity alone does not prove contrast over a photo. Fonts: `Sora` (structural/body, `font-sans`), `Outfit` (display/titles, `font-display`). Keep text and actions usable with enlarged text and browser zoom; never communicate a state through colour, motion or sound alone.
- **Accessible controls:** use semantic buttons/links and labelled fields, keyboard operation and visible, unobscured focus — never `outline-none` without a replacement. Hit targets ≥44×44px; compact may use ≥36px for a fine pointer, but touch targets stay ≥44×44px even when the glyph is smaller. Icon-only controls need `aria-label` + `Tip` (`primitives/Tooltip`), never native `title=""`; a tooltip cannot be the only explanation of an essential touch action. `cursor-pointer` on every custom interactive surface.
- **Honest feedback:** show progress and failures beside the affected work when possible, with an accessible status announcement where needed. Preserve entered text and offer a concrete recovery action; distinguish saved on this device from synced. Use §1 for toasts. Ask for permissions when the person invokes the relevant feature, explain the benefit, and keep unrelated work usable after refusal.

## 7. Data & State

- `useQuery`/`useMutation` only for server state — no `useEffect`-fetch-into-local-state without a specific non-caching reason.
- `unwrapResponse(res)` takes its type from the RPC route: never pass a generic. A type that doesn't fit is route ↔ contract drift; fix the route (`tests/app/lib/api/rpc-parity.test.ts` pins each read route to its entity).
- Optimistic pattern (`createOptimisticHelpers` per domain in `hooks/{tasks,habits,projects,tags}/optimistic-helpers.ts`): creates pick their id with `clientIdFor(input)` and send it as both `id` and `Idempotency-Key` (the server keeps it), so the optimistic row is the real row; cancel in-flight queries → snapshot cache → update immediately → write the server's answer into every list (`reconcileTaskInCaches`) → rollback and invalidate on error. Task writes don't refetch on success, and invalidation only refetches what's on screen; hidden lists refetch when visited. Read one task with `useTask(id)`, never by loading whole state lists. Rate-limited reads are not retried; writes wait out `Retry-After`.
- Query keys centralized in `app/lib/api/query-keys.ts` (domains: tasks, projects, inbox, tags, habits, location, weather, appearance, settings, ai) with differentiated `STALE_TIMES` — don't invent arbitrary per-hook caching windows.
- `authenticatedFetch` refreshes and retries a 401 once for reads, writes and assistant streams; terminal expiry locks local auth and returns to sign-in, keeping unsynced work. Query errors only report failures. A request that got no answer (`NETWORK_UNAVAILABLE` from `authenticatedFetch`: offline, timeout, captive portal) is never an auth failure. Other query errors are logged there once (dev); hooks don't log their own.
- **Offline:** everyday writes go through `withOfflineSupport(toOp, apiFn)` (`lib/api/offline-mutation.ts`): offline, on a network failure, or while earlier changes wait, the op is queued in the per-account WAL (`offline-wal.ts`: Web Lock + BroadcastChannel across tabs) and the call resolves `undefined`, so `onSuccess` guards it and `onSettled` skips refetches via `wasQueued`. Each op type needs a `toRequests` case in `mutation-executor.ts`; replay is ordered, stops on network failure, drops edits to deleted items, holds later changes behind a failed one and sends no `expectedUpdatedAt` (last write wins per field). Note saves differ: they carry `expectedVersion`, an `opId` (the Idempotency-Key, fixed per payload) and their tab's `branch`; unsent saves fold only within one branch + base, a frozen (`attempted`) entry is never replaced, and a 409 is merged by `lib/notes/note-reconcile.ts` or parked as a `conflict` entry for Sync review (never appended to the note). Online-only: the assistant, settings, uploads, deleting lists/tags/sections. After reveal, `useOfflineWindow` warms the phone views (−7…+21 days) through their own cache keys (open lists via one bounded `GET /tasks/batch`, ≤3 transports at once), skipping fresh or in-flight lists and unsynced edits, and stops when hidden, offline, replaying, or while foreground queries fetch; the persisted cache lives 14 days (`gcTime` matches). Rows show `shared/PendingMark`; the banner's Review opens `SyncReviewSheet`; sign-out with queued changes or unsaved note text asks first (`useSignOut`).
- **Notes:** one `NoteSession` per account + canonical owner per tab (`lib/notes/note-session.ts`, held by `note-registry.ts`, read through `useTaskNote`): it owns content generations, the acknowledged revision, one in-flight save (≈600ms idle, ≤2s while typing), the device journal (`note-journal.ts`, per-branch drafts under a Web Lock) and the derived status (`noteStatus`: Saved · Saving… · Saved on this device · Couldn't sync · Review changes · Couldn't save). Other tabs converge through `note-channel.ts` + 10s polling + `mergeNotes` (disjoint edits only; overlap → review, both texts kept). The editor is Tiptap over a bounded schema (`note-markdown.ts`; `isFaithful` sends a note it would lose text from to Markdown source) shared by `TaskNoteRoom` and `TaskNoteInline`; every command comes from `components/tasks/note/note-commands.ts`. Stored text stays Markdown; opening a note never writes.
- Logging and failures: `lib/log.ts` only (`log.debug`/`log.warn` dev-only; `log.error` always, in production one plain sentence plus `errorRef`: `code · requestId · version`, which finds the backend's `request_failed` line). Toast mechanics (policy in §1): Undo goes through `lib/utils/undo-toast.ts` — `toastUndo` when the action is already done and reversible (Trash); `undoWindow` awaited first in `mutationFn` when the server can't reverse it, so the item leaves at once but nothing is sent until the 7s window closes (Undo throws `UndoneError`, which `onError` rolls back without an error toast; closing the tab inside the window keeps the item). An Undo toast replaces a confirm dialog; keep a confirm only for what can't be undone (Empty Trash, delete account, permanent delete from Trash, clear archive). Every toast goes through the patched `toast.*` methods (never bare `toast()`), which carry the Cadence look and stretch any "Undo" toast to `CADENCE_UNDO_DURATION`. Failures toast through `toastError(err, "Couldn't …")` (`lib/utils/error-toast.ts`: a plain reason from the status, rate limits as one shared toast, Copy details); never show `err.message`. Crash screens (`root.tsx`, `shared/RouteErrorBoundary`) show `shared/ErrorDetails`; crashes, unhandled errors and failed queries/actions send bounded error categories through `/events/errors` only with resolved Crash reports consent. Never log tokens, OAuth URLs or callback query strings.
- Local UI state: Zustand (`app/stores/`, see §5). `useSettings()` seeds from account-local storage only when cached data exists; query persistence waits for account identity before restoring, coalesces storage writes for 250 ms, drops legacy unzoned routine ranges on restore, and flushes on hide/account transition (the WAL stays independently durable). Startup reuses cached data and waits only for the entry route's missing first-screen data (`FIRST_SCREEN` in `use-workspace-startup.ts`), never for decoration, the assistant, focus views, notification state or the debug probe (`useAdminCapabilities`: only with `VITE_ENABLE_DEBUG_ROUTES=true` or dev, after reveal); the photo background gets four seconds. Boot reads the saved cache in parallel with the session check (`prefetchSavedWorkspace` in `entry.client.tsx`), and a head script starts `get-session` before the bundle loads (`lib/auth/session-prefetch.ts`). The NLP parser (chrono) and `EditSidePanel` load lazily; `@supabase/auth-js` is aliased to the four error classes the auth SDK needs (`vite.config.ts`). `WorkspaceStartup` records fixed User Timing phases with bounded categories and batches them through `/events/performance` only with resolved, enabled usage diagnostics; each privacy opt-out clears its queued reports, and account changes clear both gates. Keep durable preferences in Query, Zustand, or local cache.

## 8. Domain Behavior to Preserve

- **Tasks:** tasks, events, habits and capture clarification use `EditSidePanel`, shared title/header/section controls and a type label (Task, Fixed or Routine); domain editors own their fields. The route's select handler toggles: opening the open item again closes it (compact sheet included); explicit Edit actions only open. All edit rails animate and resize through `EditSidePanelRail`; smaller layouts use overlays. Event cards open the editor outside interactive controls. Creation (tasks, thoughts, schedule blocks, events, routines) goes through `shared/Composer.tsx`: dialog on desktop, `UtilitySheet` on compact, in place with `inline`, built-in Cancel with a discard guard; each draft sets a header `icon` and a `tone` (nav wayfinding shade) that colours the icon, submit and the `dialog-glow` surface. Each creator is a `use…Composer` hook returning a `ComposerDraft` (`useTaskComposer`, `useCaptureComposer`, `useRoutineComposer`, `usePersonalEventComposer`), so one shell can host several (Quick Add, the schedule popover) or wrap one; never rebuild a creator's fields elsewhere. Parsed titles fill date/time fields through `useTypedWhen`, and typed tasks are saved with `buildTypedTaskInput`. Composer parts: plus `ComposerTitle`, `ComposerTabs` (segmented), `WeekdayPicker`, `ComposerToggle` and a `ComposerMore` fold; `CadencePicker` is built from them. "Waiting" is a first-class state, not a hack. Ordering uses fractional indexing — `app/lib/utils/order-index.ts` (`computeNextOrderIndex`, `computeMidpointIndex`); never renumber whole lists unnecessarily. Upcoming buckets the next 7 days; every later task goes to `upcoming/FurtherOutSection` (folded to one line, grouped by `groupFurtherOut`: four calendar weeks, then months), kept folded or open per device and opened for one visit by a route focus inside it or `?further` (Weekly Reset's look-ahead). Per-device view flags (folds, hidden columns) go through `useDeviceFlag`.
- **Schedule:** `schedule.tsx` composes `use-schedule-*` hooks, `ScheduleCalendar` and `ScheduleOverlays`; `use-schedule-data` reads the active month/week/day/year range; holidays reuse cached years for 7 days per country, subdivision and locale. Compact shells change period by dragging the calendar body (`hooks/ui/use-period-swipe.ts`) through the same path the header arrows use. Trash on a recurring block uses whole-series wording; Undo restores the task and reopens its details through `useTaskDetailsRequest`. Habit logs hydrate into **virtual habit tasks** on some schedule surfaces — intentional hybrid behavior, don't simplify away. **Phones** (`components/calendar/phone/`) zoom Day → Month → Year (no Week; `?view=week` shows Day, which fetches the whole week): `DayStrip` (`day-<iso>` drop targets) over `DayAgenda`, and `MonthFold`. Rows are `ScheduleRow`, grouped by kind in one place (`lib/utils/calendar/schedule-day.ts`, routines included); swipe right completes, left offers next day / Pick day. Routines open `EditSidePanel kind="habit"` in the overlay on compact. Clutter toggles are per kind (`calendar.clutter.showFixed` etc.); Day and Week open at `calendar.timelineStartHour` (default 7). Desktop Month folds repeating Fixed blocks into one line per cell (`splitMonthDay`).
- **Repeats:** three kinds, told apart by "if I miss one…" (`shared/RepeatKindPicker`): **Fixed** (`interactionMode: "timetable"`, no check-off, never overdue), **Routine** (a `habits` row; misses let go, never carried over or shown as catch-up), **Task** (carries over). The UI says Routines and Lists, never Habits or Projects; code and DB keep `habit` and `project`. Switching Task ⇄ Routine goes through `hooks/habits/use-convert-repeat.ts` (create new, then trash/archive old, one Undo). Routine times per day come from `routineTimeOn` (`@cadence/domain/repeats`); show a routine with `habits/RoutineMark` (emoji or glyph) and respect `settings.tasks.showStreaks`. Today = `today/DaySpine` (Fixed only, now/next: a strip in list view, the first board column as a vertical timeline in board view) over Still open (carried-over tasks, only when non-empty) · Today · Routines (`shared/RoutineAgendaList`, done ones folded).
- **Routines:** one range query (`useHabitsRange` → `/habits/weekly`, any start/end, under the `weeklyAll` prefix, keyed by start/end/timezone/archive state) feeds week, month and History, so every optimistic resolve covers them all; the week start comes from settings. `RoutineTodayBand` (ring + `shared/RoutineAgendaList`, current period only) leads the month and compact views; on a desktop week the grid's today column is the check-in instead, never both. Week is `RoutineWeekRow` (done count only, never "of N"); month is `RoutineMonthGrid` (footer: check-ins, plus longest run when streaks show; never misses). Every day is a `RoutineDayCell`: any past scheduled day can be logged; click/tap toggles done (touch adds Undo), right-click/long-press opens Done · Skip · Clear; grids are one roving tab stop (`hooks/ui/use-roving-grid.ts`: arrows, Space, `S` skip, `E` edit). A routine's `colorAccent` uses the list palette via `routineTone` (default moonlit); a personal event's `color` uses the same palette via `eventToneStyle` (`--event-ink` stays AA); composers pick either with `shared/ColourDot`. Pauses run from today (`isRoutinePaused`), never hiding logged days. Menus and the editor share `useRoutineActions` (pause, archive, delete with Undo); a routine's saved app is its App pane under the summary (see **App links**). Steps (`habits/RoutineSteps`): a cell tap still sets every step, the day menu lists them, partial days show "2/3" (`stepProgress`). A routine **at set times** (`habit.times`, 2+ daily times; one time stays `targetTime`; never combined with steps; the usual time and `targetTimes` stay underneath for when it's turned off) is composed with `habits/RoutineTimes`: its cell tap opens `RoutineTimeChecklist` instead of toggling the day, Today/Routines show one row (`routineAgendaItems`), Schedule shows one block per open time (`habit-{id}--{day}--{time}`), and any whole-day COMPLETED sent through `useResolveHabit` becomes the next open time (`withNextTime`; `timeAction` stamps `at`).
- **App links:** a task or routine can save one app (`linkedAppId`, a `@cadence/contracts/app-link` id; never a URL) that its details open with one tap. The catalogue (`lib/app-links/catalog.ts`: label, fixed initials, category, aliases, per-platform routes) is the only list; `platform/app-links.ts` `resolveAppLaunch` picks the route for this device before the tap (iPhone/iPad: the app's scheme; elsewhere the HTTPS destination; desktop is always HTTPS through `openExternalUrl`). Or a typed website (`linkedUrl`, the client clears the other field): `resolveWebsite` re-checks it with `parseWebsite` before it becomes a link and labels it by host (punycode, so look-alikes show), and `AppAnchor` re-checks before the desktop `openExternalUrl`. A route is offered only when `verified` (device-tested, vendor-documented, or the app's long-standing scheme); a new candidate ships `verified: false`, seen only in dev/`VITE_SHOW_UNVERIFIED_APPS=true` builds. `shared/AppPane` is a detail pane like Notes (under the title or summary; Fixed blocks show it only when one is attached): collapsed with an app it is the app's row plus an `AppLaunchLink` Open pill (a plain anchor; a native scheme never goes through `window.open`/`ExternalLink`), and opened it is `AppChooser` inline, led by the dashed **Website** option (globe tile; one field starting at `https://`, Open saves and opens, Enter saves); choosing saves, never launches, and collapses; Remove has Undo. Rows rank per visit with `lib/app-links/picker.ts` (current choice, then `@cadence/nlp/app-suggestions` from the title unless `nlpEnabled` is off, then A→Z; typed search is `@cadence/search`); a repeating task's app is written to its series (`getTaskSeriesId`), and Task ⇄ Routine conversion carries it.
- **Natural language:** every composer (inline add, Task dialogs, calendar block, routine, yearly event, capture → task, Weekly Reset) reads typed words through `useNlpParse` → `@cadence/domain/nlp-draft`: computed during render, so what shows is what Enter saves (`ready`/`finalize()` only cover the parser module still loading). The hook takes the user's hand-set fields as `manual`, plus `dismissed`/`accepted` ids, `literal` ("Keep as written") and the surface's `capabilities`; `DraftRow` shows only what has no control of its own and the few choices. Writes that carry `nlp.resolved` are stored as sent, never reinterpreted. Weekly Reset places captures through `useProcessInboxToTask` and changes tasks with a typed `InstructionField` (+ bounded batch, `useApplyInstruction`; a row passes its list so a shared section name resolves). Inside a list the inline add does not read list names. The Effort suggestion (`useEffortSuggestion`, opt-out `tasks.intelligence.effortSuggestions`; task composers, calendar block, inline add) is a recommendation only; the draft's own Effort always wins, and a hand or accepted choice sends `effortOrigin`.
- **Inbox / Capture:** `useCaptureFeed` owns the shared badge and feed filters (New thoughts, No day yet tasks, Older after 14 days, kept Notes folded and excluded from counts). `CaptureRow` shares menu calendar, completion, roving focus and selection across thoughts and tasks; its subtasks use `SubtaskChip` + `InlineSubtaskPanel` from `tasks/InlineSubtasks.tsx`, shared with `TaskCard` — never restyle them per row. Desktop sidebar `TagBubble`s drag onto a row (native `TAG_DRAG_TYPE`) to add that tag; clicks still filter. `CaptureGreeting` (template from `lib/constants/greetings.ts`, weather from `useWeather` only once ready) sits above the `capture-surface` field, which takes focus once startup reveals the page and keeps its draft per account in `sessionStorage` until saved; its `Reveal` row stays open while focus stays, so repeated saves don't jolt the feed. Row styles, `⋮` menu and section headers match Today/Upcoming; desktop has Rows/Board through `SortMenu` (view only); Focus owns persistent Newest/Oldest/Priority ordering. Enter saves in the inline field and Thought composer. A day means a task: a picked day, or a typed one on a single line of ≤12 words (longer drafts keep days as words), saves a task (`useCaptureDraft` reads the line live through `useNlpParse`; Enter waits for the parser only on a draft that could be a task); an undated draft's `taskControl` (⌘↵ keycaps, "As task" on touch) saves it as a task with no day; the toast names where it landed (`placementReceipt`). Clarify persists title, List, Section, Tags and dismissed NLP chips. Where a thought lands is `placementFor` everywhere (Clarify, a row's Done, bulk placing, Sort all): the user's pick, then a cue word, then the stored `analysis.suggestedPlacement`; changing the list clears the section; Sort all places every thought with a list, one toast, one Undo. Placement rows reuse `TaskEditor`'s `DetailPanelSections` (`DetailGroup`/`FieldRow`/`FieldBlock`, `ValueSelect`) and `TagField`; detected times survive placement. Process/complete has transactional unprocess Undo; kept/discarded changes have Undo. Search's empty state asks `useDidYouMean` (only while `smartPlacement` is not off) for one "Did you mean…" row. Navigation uses `ActivityBadge` for indicators and `PlainNavCount` for Capture/List totals; `useRoutineDueCount` shares today's pending routine totals, respecting the due-count setting.
- **Settings:** `?settings=` opens the desktop dialog or compact `SettingsSheet`; `menu` shows categories (Shortcuts hidden on phones) and sign-out, with Profile & Security inside Settings. Compact details replace the same history entry; close returns to the underlying route. `SettingsContent.tsx` shares tab content (deep-linkable tabs: About, Account, Appearance, Assistant, AI, DataPrivacy, DateTime, Integrations, Location, Notifications, Shortcuts, Tasks). Merged optimistically, cached locally. Photo background: `settings.appearance.backgroundImage` is server-owned (upload/delete routes only); the file comes through authenticated RPC and is cached in IndexedDB (`lib/themes/background-image-cache.ts`, cleared on sign-out; writes serialized and guarded against same-tab sign-out/deletion); the provider keeps the active image's object URL alive across routes; choosing a mode or preset leaves photo mode without deleting the photo; `BackgroundSettings` mounts `PhotoCropDialog`, and only confirmation uploads. Cadence accents are disabled in photo mode. `settings.location` is owned by the Location tab and read through `useUserLocation` (weather, holidays); only an explicit user action may call `navigator.geolocation`, and location/weather queries carry `meta: { persist: false }`.
- **AI Assistant** (`components/assistant/`, `hooks/ai/`, `lib/ai/`, `stores/assistant-store.ts`): `AssistantSidePanel` composes header/thread/composer and overlays; `use-assistant-conversation` owns chat/history/cross-tab recovery, `use-chat-attachments` owns uploads. Streaming uses `chat-transport.ts` over `@ai-sdk/react`. Tool results render as widget cards (`components/assistant/widgets/`) dispatched from `tool-registry.tsx`; each card's `ctx` is typed by its tool (`ToolRenderContext<"create_tasks">`, from the backend's `ToolIO`), so a renamed field fails tsc. Every write runs on the server; a write card (`ApprovalCard` shell; captures in `CaptureCards`, lists/tags/focus views in `OrganizeCards`) renders from `part.input` and, while the server waits (`approval-requested`, latest reply only), answers with `addToolApprovalResponse`; unticked rows send a decline naming them so the assistant re-proposes the rest. `useChat({ sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithApprovalResponses })` then sends only the answers (`chat-transport.ts` `approvalAnswers`) and the reply continues; caches refresh as each write lands (`refreshAfterWrites`, once per call; `onFinish` catches the rest). In dev each turn logs one `[cadence:ai-turn]` line, the client half of the server's `ai_turn`. Parts that didn't wait render settled; an older reply's open request shows "Not answered". A new-task card shows every field it sets (list and section via shared `TaskDestination` queries; words read from a photo under "From your image"). Retired `propose_*` parts render read-only (`RetiredProposal`); writes the server no longer offers keep their old card through `RETIRED_WRITES`. Capture-to-inbox never waits. `ask_user` renders `AskCard` (latest reply only); the answer goes as the next user message (`replyToQuestion`, leaving the draft alone). The composer's approval mode (`assistant-store` `approvalMode`: `ask` default · `auto` · `full`) is sent with every turn; the server decides which calls wait. Assistant markdown never renders images; `/…` and `?settings=<tab>` links navigate in-app (closing the sheet on compact), everything else (including `//…`) opens externally. The assistant's guide lives in `apps/backend/src/prompts/help/*.md`: a user-visible change that makes it wrong edits it in the same change. Turns render parts in stream order (`buildSegments`). Photos (picker, paste, drop) are compressed on device (`compressChatImage`: 1600px WebP ≤ 1MB, EXIF dropped) and uploaded on attach to `POST /ai/images`; Send waits for them and the turn carries only `cadence-image:<id>` file parts (no filename). `ChatImages` loads them through an authenticated fetch, or shows "Image expired"; photos open in `shared/ImageViewer`. The per-message cap comes from `GET /ai/usage` (`images.perMessage`); the attach control warns near the 20/day cap and blocks at it (`describeImageAllowance`). `AI_IMAGE_LIMITED`/`IMAGE_NOT_FOUND` offer "Send without images". Slash commands (`lib/ai/slash-commands.ts`, `SlashCommandMenu`; exact match only, anything else sends) run in the app: `/usage` (`UsageOverlay`), `/clear`, `/history`, `/memory` (opens "What Cadence knows"), `/settings` (via `useStepOutOfAssistant`, shared with in-chat links). `UsageMeters` (`describeUsageMeters`, `use-ai-usage.ts`) is shared by that overlay and Settings › Assistant. History rows archive in one click; `ClearArchiveButton` (confirm, then `DELETE /ai/conversations/archived`) sits under Archived and in Settings › Assistant. **Memory:** the mode is server-owned (`hooks/ai/use-memory.ts`, `POST /ai/memory/mode`; never part of the settings patch). `MemoryPicker` is the first-start question over the panel until answered (Basic preselected, Off a link); `MemoryOverlay` is "What Cadence knows" (header brain button, `/memory`, or Settings › Assistant via `assistant-store.memoryOpen`): Full's 3-month catch-up as a rough bar (`catchUp.progress`) then a Done line for a week, plain sentences, tap for source and Forget (Undo toast), changes by chat through its pinned box, search past 30 items. `RememberReceipt` renders `remember` as one line with Undo (none for `kept`, a fact already known), and reads the memory page for what still exists, so after a reload an undone save says "No longer remembered"; `MemoryPicker` makes the panel behind it `inert` until answered; the per-chat "Don't learn from this chat" switch is in a conversation's menu. In Full, `useUpdateTask` offers `DurationChips` (`lib/ai/duration-prompt.tsx`) on a completion, once a day at most, skippable. The mode it reads comes from the settings cache, which mode changes patch.
- **Shortcuts/search:** `Cmd/Ctrl+K` (command palette; memoized `@cadence/search` index over tasks/lists/routines/thoughts, sections/tags/subtasks and compact canonical note tokens; identifiers stay exact), `T` (quick-add), `Cmd/Ctrl+Shift+S` (manual sync), `G` chords for navigation. Don't add conflicting shortcuts casually.
- **Notification center** (`components/notifications/NotificationCenter.tsx`, responsive `NotificationsSheet.tsx` at `?notifications=true`): derivation is client-side (`reminder-engine.ts`, 60s scan in `use-notification-center.ts`, reads start after workspace reveal; routine reminders read today's range data and fire only while today's log is open); read/dismiss/defer state is a localStorage-backed module store with best-effort notification-state API sync. Device delivery is one shared state (`use-device-delivery.ts`, `lib/notifications/device-delivery.ts`): every device registers by a stable `installId` with a `kind` and a platform-derived `label`, and the server's device list is the truth for whether reminders are on here (a localStorage mirror only covers a cold start with no network). `deviceStatus`: unsupported · install (iOS tab) · denied · off · local (Cadence alerts itself while running; desktop always) · connected (Web Push subscription saved, so reminders arrive with Cadence closed). `DeviceDeliveryRow` (Settings → Notifications) enables, sends a test through the real path and turns this device off; `DeviceList` manages any device from any device. `duplicateRisk` flags a desktop app plus a pushed browser on one computer and only ever suggests, never silences (a missed reminder is worse than a repeated one). Enabling requests permission straight from the tap; a granted device re-registers on load; sign-out forgets this device. `use-browser-notifications.ts` alerts only in `local` status, via `dueAlert` from `@cadence/domain/reminders` (the server's policy: lead time, 15-minute late bound, dismissal/deferral; quiet hours and pause hold alerts until they end, never hiding list items), with a per-account persisted claim that a failed send gives back and the occurrence key as the notification tag, so a local and a pushed alert collapse into one. While local, `use-local-reminder-refresh.ts` re-reads open/waiting tasks, today's routines and settings every 2 minutes even when hidden (skipped while writes are queued or in flight). `NotificationsTab.tsx` groups settings by what alerts; Pause sets `notifications.pausedUntil`; "My day" morning/evening drive deadline/event alerts and the Defer choices (`computeDeferUntil`); Daily summary is shown inert (no sender exists). Windows only: `backgroundDelivery` in `use-desktop-command-preferences.ts` (device preference, not account settings) keeps delivery after the window closes; the Rust half is in `apps/desktop/AGENTS.md` and takes effect on the next launch.
- **Quick add:** `QuickAddSurface.tsx`, one `Composer` switching the task, capture and routine composer hooks (drafts kept per tab), triggered by `T`, the sidebar or the phone orb; navigates + `useRouteFocus()` on submit.
- **Place:** the shared `CaptureDayChips` (wrapping pills, `DAY_PILL` tokens) accents the detected day or lightest day (`useWeekLoad`: effort-weighted, unknown effort counts as middling, timed blocks by length, each routine block as 1); Pick day uses the shared date picker. `HoldingPlannerPanel` shows two weeks and the selected day at the persisted rail width; `PlaceDndProvider`/`PlaceDraggable` let both row kinds drop onto days. Task placement and thought placement offer Undo; explicit No day yet never infers a date.

## 9. Component Patterns

- `app/components/primitives/`: `AlertDialog`, `Button`, `Collapsible`, `ContextMenu`, `Dialog`, `DropdownMenu`, `Input`, `Popover`, `ScrollArea`, `SegmentedControl` (header view switchers, the compact board column chooser in `shared/BoardCanvas`, short choices: `size`, per-option `tone`), `Select`, `SearchSelect` (a `Select` with a search box for long lists: countries, regions, time zones), `SearchField` (the one search box: leading icon, Clear button, `loading`, `variant` field|bare, `size` sm|md|lg, `trailing`; `SearchTrigger` is the same look as a button that opens search elsewhere; never hand-roll a search `<input>`), `Separator`, `Skeleton`, `Switch`, `TimePicker`, `Tooltip`. Check here before styling a new Radix wrapper. Every date field is `shared/DatePicker` (built on `MonthCalendar`, which the task schedule surface also uses) and every time field is `TimePicker`: both use the native picker on a coarse pointer and a custom popover otherwise. Never render a raw `<input type="date|time">`. `Dialog` and `AlertDialog` share `primitives/dialog-styles.ts` (themed `surface-dialog` glass, layout, header/footer/title type) and use `Button` size `md` for actions; on a touch phone `DialogContent` is a docked sheet (`DIALOG_SHEET`: grabber drags it closed, and a `DialogFooter` with its own Cancel hides the corner X; `phoneSheet={false}` for full-screen surfaces like `ImageViewer`), while `AlertDialog` stays an inset action sheet; consumers set size, layout and padding only, never their own background, border or shadow, and use `DialogCloseButton` when a header needs an inline close. `ContextMenu`, `DropdownMenu`, `Popover` and `Tooltip` share `primitives/menu-styles.ts` (the see-through `surface-floating`, motion, menu rows, `GenericMenu`); `Select` content uses `surface-select`, the same glass. Primitives import `cn` from `lib/utils`.
- Reuse primitives through composition; remove duplicate controls, layouts and animations. One home per helper: date formatting, calendar grids, month/weekday names and `TimePicker` values in `lib/utils/date-format.ts`, formatting only via `formatInZone` (days are LocalDates from the API, instants are converted with `@cadence/domain/time` in `useUserZone()`, today is `useToday()`; never `Date` local getters, slicing or `toISOString()` for a day); motion (`EASE_OUT_EXPO`, `slideVariants`) in `lib/constants/motion.ts`, and `shared/Reveal` for every expand/collapse (never a bare conditional render); a collapsed `BoardCanvas` column is one rail button (`onExpand`); module stores via `lib/utils/external-store.ts`; `useOnlineStatus`, `useIsCoarsePointer` and `useReducedMotionSetting` (the Motion setting, else the OS) in `hooks/`. Routes stay thin; domain components own rendering. `MainLayout.tsx` owns the shared shell and active-panel close control; every page header (including Schedule and Routines, which hide the shell header) uses `layout/PageHeader.tsx`: shell-header height, `surface-shell` (shared with right-rail panels), icon + eyebrow + title + optional meta, and period pages navigate with `layout/PeriodNav` (‹ Today ›, Today greyed out on the current period); on phone every header, the shell's included, is `PhonePageHeader` (no icon, 22px display title, controls in `.header-glass` capsules, the same glass `app.css` gives every labelled icon-only button on phone (icon+text buttons carry a `gap-*` class; in-content arrows like a calendar's month nav opt out with `glass-none`); Schedule and Routines put their view choice in `PhoneViewPicker` under its sliders icon) and `PeriodTodayPill` floats Today bottom left while off the current period; optional dialogs, search, bulk actions and note room defer mounting until needed, preserving exit motion with `DeferredMount`. The assistant is code-split and never part of startup (plain `Suspense` with its glass shell, even when persisted open); other visible lazy content uses `StartupSuspense` so startup includes its requests.

## 10. Auth

Neon Auth via `authClient` (`app/lib/auth-client.ts`, 20-second SDK deadline), account-validated session JWT seeding (`lib/api/client.ts`), and lazy `AuthUIBoundary` + `AuthView` on auth routes; workspace controls use `useAuthState`. Pages outside the workspace (sign-in/up, auth callbacks, consent, route and root error boundaries) share `shared/CardPage` (stars, glass card with the diagonal sheen, logo, optional title/description/actions); third-party UI themed via `.neon-auth-wrapper` in `app.css`. Web callbacks restore through `useAuthState` with serial retries for up to 15 seconds; only a resolved session permits workspace navigation, except status `offline`: when the session can't be checked for lack of a connection, the last signed-in identity (`lib/auth/offline-identity.ts`, no tokens) opens its cached workspace until the connection returns. Web warm starts do the same while the session is checked (status `provisional`, workspace paths only): API calls and WAL replay wait in `client.ts` (`holdForSession`) and writes queue; desktop waits for the session before revealing its workspace; an anonymous answer goes to sign-in, another account remounts and aborts the held calls. Fresh recovery bypasses the SDK cache; desktop callbacks consume the handoff once across remounts and the callback listener lives above the account cache. Auth UI session changes invalidate queries; account identity changes remount the isolated cache. Do not introduce a parallel auth stack. Legal acceptance: sign-up (`routes/auth.tsx`) gates the whole form behind two ticks (16+, Terms and Privacy Policy; `shared/ConsentCheck`), and `layout/MainLayout` mounts `legal/LegalConsentGate`, a blocking panel for any signed-in account whose `privacy.legalVersion` isn't `LEGAL_VERSION` (`@cadence/contracts/settings`; bump it to ask everyone again, and match the `updated` date of the landing policies). It covers new Google/GitHub accounts made from sign-in and accounts from before the step, and records quietly when the sign-up ticks were just made (`lib/legal-consent.ts`). Client-side only: the API doesn't refuse an account that hasn't accepted. `routes/connect.tsx` is the consent page for outside assistants (MCP): signed-out visitors go to sign-in with `redirectTo` back to it; approving or declining (`hooks/core/use-connections.ts`) returns a URL on the MCP origin that the page opens with `location.assign` (that origin checks the cookie this browser got when the assistant started; never navigate there any other way). Settings › Integrations lists them (`settings/ConnectedAssistants.tsx`, Disconnect behind a confirm); scope wording lives in `lib/constants/mcp.ts`. Calendar/notes sync controls below it stay disabled Coming Soon. Managed Neon Auth pins its client plugins (JWT, admin, organization, email OTP, magic link, phone number); anything else (2FA, passkeys) isn't callable, so don't build UI for it. Settings › Active Devices lists sessions only within a day of sign-in (Better Auth `freshAge`; `/list-sessions` returns 403 after), then offers `revokeOtherSessions`.

Browser E2E (agents, Playwright): sign in at `/auth/sign-in` with `E2E_EMAIL`/`E2E_PASSWORD` from `apps/frontend/.env` (git-ignored), a password user on the dev Neon branch only. Missing after a branch reset? `POST {VITE_NEON_AUTH_URL}/sign-up/email` with `Origin: http://localhost:8788` and `{email,password,name}` recreates it, then set `neon_auth."user"."emailVerified"=true` for it (dev DB, `MANAGEMENT_DATABASE_URL`) and add its id to `ADMIN_USER_IDS` in `apps/backend/.dev.vars` (admin tools + `POST /debug/seed`). Use a fresh browser context so a real session isn't signed out.

## 11. Web vs. Desktop Boundary (`app/platform/`)

`runtime.ts` (web/desktop switch plus the only Tauri-window and storage checks: `hasDesktopWindow`, `getDesktopStore`, `getWebStorage`), `desktop.ts` (Tauri implementation), `desktop-shell.ts`, `desktop-auth-handoff.ts` + `lib/desktop-auth-session.ts` (native OAuth/deep-link handoff), `desktop-keyring.ts` (OS credential storage vs. browser storage), `patch-desktop-fetch.ts` (native HTTP transport), `desktop-update-state.ts` (updater), `desktop-e2e.ts`, `web.ts` (browser counterpart). `routes/desktop.quick-capture.tsx` + `hooks/ui/use-desktop-layout-scale.ts` / `use-desktop-command-preferences.ts` back the native quick-capture window and OS menu commands (see [`apps/desktop/AGENTS.md`](../desktop/AGENTS.md)). `desktop-shell.ts` also carries the native frame theme (`syncNativeWindowTheme`), cold-start launch commands (`takeLaunchCommand`) and native Save As (`saveTextAs`, used by note export). `hooks/core/use-wake-refresh.ts` refetches active queries and fires `cadence:wake` after a sleep gap, for windows that wake without focus (the tray). Settings › About's "Reload fresh" (`repairWorkspaceCache`) drops only the saved query snapshot, never the WAL. New platform-divergent behavior belongs behind this boundary — never an inline `if (Tauri)` scattered in domain components.

## 13. Anti-Patterns

Hardcoded hex in components · raw `@radix-ui/*` in domain components · raw `fetch` for backend calls · spinner-only flows replacing optimistic ones · duplicated query keys · reusable hooks outside `app/hooks/` · giant route components with business logic · generic SaaS panels/tables breaking the atmosphere · unnecessary full-list renumbering · breaking auth/session invalidation · conflicting keyboard shortcuts · inline platform checks outside `app/platform/` · raw `console.*` outside `lib/log.ts` and `worker.ts` · `toast.error(err.message)` · a success toast for something the screen already shows · a reversible destructive action with no Undo or an irreversible one without confirmation · a hand-rolled search `<input>`.

## 14. Checklist

- Build: owning domain → ease check (fewer decisions, less to scan, nothing twice, no capability lost) → thin routes + shared primitives → semantic tokens → Hono RPC + TanStack Query → optimistic updates.
- Review the changed flow: one obvious next step; discoverable secondary actions; keyboard and touch access; context and focus after close/resize; empty, pending, offline and error states; Undo or recovery. Check enlarged text, daylight/photo backgrounds, compact density and reduced motion as relevant.
- Verify behaviour with appropriate checks and typecheck for code changes. Browser resizing proves layout only; distinguish it from physical-device, assistive-technology and native desktop evidence.

If this document conflicts with a proposed change, this document is the baseline.
