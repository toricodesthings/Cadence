# Cadence Frontend — Agent Instructions

React Router v8 SPA (`ssr: false`, intentional) deployed as static assets on Cloudflare Workers. Consumes the shared backend ([`@cadence/backend`](../backend)) exclusively through a typed Hono RPC client — never invent client-only API contracts. This is also the source codebase for the [desktop app](../desktop): a `platform/` runtime boundary swaps web-vs-desktop behavior, so most code must stay platform-neutral. It embodies the **Twilight Sanctuary** design language.

## 1. Non-Negotiables

- Client-rendered SPA. Do not introduce SSR assumptions.
- All server data flows through **TanStack Query**; all API calls through the one typed Hono RPC client (`apiClient` in `app/lib/api/client.ts`, built on `authenticatedFetch`; `useApiClient()` returns it) — never raw `fetch` for backend calls and never `as any` on the client. Only the transports (`mutation-executor.ts` WAL replay and its Background Sync twin in `public/sw.js`, the assistant's `chat-transport.ts`) sit below it, plus the live-sync WebSocket (`hooks/core/use-live-sync.ts`, which carries no data, only "something changed").
- Reusable hooks → `app/hooks/`; non-UI logic → `app/lib/`; shared UI → `app/components/` grouped by domain; Radix always through `app/components/primitives/`, never imported raw into domain components.
- No sterile SaaS styling (white cards, harsh borders, gray dashboards): glass, shadow, ambient color; readability and usable controls outrank effects. Never hardcode a one-off hex when a semantic token belongs in `app/app.css`.
- Notification settings fields are required in the settings schema — never optional.
- Mutations are optimistic-first: snapshot → update immediately → rollback on error → reconcile on settle. The screen shows only the end state, never a step on the way (a capture saved as a task appears as that task, never first as a thought).
- Toasts answer one question: "where did it go?" A happy path the person can see in place (a row appears, a check flips, a field saves) gets none. A toast is for: a failure (`toastError`); something that just left the screen (placed, moved, discarded, restored, converted, bulk), which names it (`toastName`) and says where it went in the description, with Undo when reversible (`toastUndo`); or a result that lands out of sight (email sent, clipboard, export, update ready). Reversible destructive actions have a working Undo; irreversible ones confirm (§7). Touch may add an Undo toast where a stray tap is likely (routine marks).

## 2. Stack

Versions live in `package.json`. Tailwind v4 has no config file: tokens are `@theme` in `app/app.css`.

## 3. Runtime Shape

- Shell: `app/root.tsx` (iOS home-screen meta: `viewport-fit=cover`, opaque `black` status bar since `black-translucent` leaves a bottom gap on iOS 26, iOS-only `maximum-scale=1` against focus zoom; `RESUME_ROUTE_SCRIPT` (`lib/resume-route.ts`) reopens the installed app's last workspace screen from the past 6 hours; dev unregisters leftover preview service workers) · `worker.ts`: serves SPA assets; proxies `/api/v1/*` through the `BACKEND` service binding (same-origin, no CORS preflight) and Neon Auth at `/api/auth/*` (cookie values forwarded verbatim, kept `SameSite=None; Secure`; Neon Auth sees only Cloudflare's IP, so the proxy limits per visitor: `AUTH_LIMITER` every request per IP, `AUTH_SENSITIVE_LIMITER` sign-in/up/code/reset POSTs per IP, `AUTH_EMAIL_LIMITER` mail-sending POSTs per SHA-256 of the address; over a limit, 429 `RATE_LIMITED`); exchanges the single-use `neon_auth_session_verifier` on the `/auth/callback` navigation, then leaves via a nonce-CSP script `location.replace`. Worker-made responses carry `nosniff`. Both auth paths and `/api/v1/*` are in `assets.run_worker_first`; hashed assets get immutable caching from `public/_headers`, whose CSP `buildEnd` hardens for web builds (`build-csp.ts`: each inline script of the static `index.html` by hash instead of `'unsafe-inline'`, images narrowed to the avatar hosts, dev-only connect sources dropped), and a missing one gets a non-cacheable 404, never SPA HTML.
- `public/sw.js`: bypasses `/auth` and `/api`; serves navigations from the validated cached shell and refreshes it in the background, so Reload (update toast, chunk-error) first asks it to refetch (`cadence-refresh-shell`). Caches only the offline shell and validated hashed build assets (all precached, including shared desktop-named chunks: `react-router.config.ts` writes the entry closure first; activate keeps this build's and the previous one's), never auth responses, dev modules or mutable CSS; respects `no-store`. On Chromium its `sync` handler replays the offline queue while no tab is open, sending the token only to this origin's `/api/v1/` (`isOwnApi`). Reminders show through the SW registration (iOS has no `Notification` constructor). `push` shows what the server sent (a Declarative Web Push message or the older flat payload) and raises the icon badge while no window is visible; a tap posts `cadence:open` to a running tab (`useNotificationTapRouting`) or opens the target.
- Installed app: `platform/installed-app.ts` (`isInstalledApp`, which counts iOS's `fullscreen`; the icon badge; persistent storage) driven by `hooks/ui/use-installed-app.ts` in `MainLayout`: saves the screen to resume, mirrors the bell's unread count on the icon, asks once to keep storage; sign-out forgets both. Icons derive from `logo.png` (`icon-maskable-512.png` keeps the art inside the safe zone).
- Build env: `VITE_NEON_AUTH_URL`, `VITE_API_BASE_URL`. Deployed web builds ignore both: the API is `${origin}` (the Worker forwards `/api/v1`) and auth is `${origin}/api/auth` (`lib/env.ts`), so auth cookies are first-party — iOS/WebKit blocks third-party cookies and OAuth never completes; dev and desktop call Neon Auth directly. Worker runtime: `NEON_AUTH_BASE_URL` (var). App version/changelog are **not** env vars — `vite.config.ts` reads root `package.json` + `CHANGELOG.md` at build time (`release-info.ts`); `lib/constants/changelog.ts` holds no entries; it also stamps a per-build `CADENCE_BUILD_ID` and emits it as `/version.json`, which `providers.tsx` polls on the web (tab visible, every 10 min) to show a sticky Reload toast after a deploy.

## 4. Routes

`app/routes.ts` is the list. Capture is `/` (thoughts and tasks with no day); `/habits` redirects to `/routines`. The privacy policy and terms live on the landing site (`CADENCE_PRIVACY_URL` / `CADENCE_TERMS_URL`): in-app links use `components/shared/ExternalLink.tsx` (system browser on desktop). Primary routes call `useRouteFocus()` to restore keyboard focus on navigation; a task whose row never shows there opens in its editor instead.

## 5. Source Layout

`app/` directories are self-describing; `app/app.css` is the design source of truth, `platform/` is the web/desktop boundary (§11), `types/settings.ts` re-exports the contract's `SettingsView` as `UserSettings`.

## 6. Design System

- **Hierarchy:** the next step is obvious; routine information is quiet and exceptions distinct. Every line of text costs reading: no eyebrows, kickers or labels that restate the title, icon or sidebar; a small label (like `pageName` over a date title on Schedule and Routines) earns its place only by saying something the screen otherwise doesn't. Anything empty (a page, section or board column) uses `tasks/EmptyState` (`compact` inside a section or column, which never shows the variant's page action; `title`/`description`/`icon` override a variant), never a loose italic line. **Agency:** useful defaults without setup; optional detail behind a labelled control; every essential action reachable without hover, dragging, a gesture or a shortcut. Back, Cancel and dismissal stay predictable.
- **Continuity:** an action keeps its name, icon and outcome on every surface. Resizing or opening details keeps drafts, selection, the viewed day and scroll position; closing restores focus to the trigger, or a logical neighbour if it disappeared. One meaning, one Lucide icon: more/page options `EllipsisVertical` (⋮, never a gear or sliders; one per page; in the desktop app every header ⋮ ends with the Scale row from `layout/LayoutScaleMenu`, and `MainLayout` adds a ⋮ for it where a page has none), Settings `Settings`, details `SlidersHorizontal`, edit `Pencil`, add `Plus`, sort `ArrowUpDown`, complete `CheckCircle2`, task `CheckSquare`, thought `MessageSquare`, note `StickyNote`, list `FolderOpen`, section `Columns3`, tag `Tag`, routine `Flame`, event `CalendarHeart`, reminder `Bell`, time `Clock`, takes `Hourglass`, waiting `UserCheck`, focus view `Zap`, assistant `Sparkles`, Today `Sun`, Tomorrow `Sunrise`, later `Moon`, next week `ArrowRight`, pick a day / reschedule `Calendar`, trash `Trash2`.
- **Motion** explains what opened, moved or changed; it is interruptible and never delays input. `lib/constants/motion.ts` holds `SPRINGS` (SNAP, GLIDE, bounce ≤ 0.15; the CSS `--spring-*` tokens are generated from them, `motion.test.ts` enforces), `EASE_OUT_EXPO` and `slideVariants`. Menus, popovers and sheets open and close with a fast compositor CSS ease-out (`--morph-*`, `--sheet-*`), never a JS spring. Press is the `press` utility (swells on touch, presses in slightly with a mouse; `press-none` opts out). Every expand/collapse is `shared/Reveal`, never a bare conditional render. Reduced motion is global through `providers.tsx`'s `MotionConfig` (`useReducedMotionSetting`: the Motion setting, else the OS); gestures still track the finger.
- **Tokens and modes:** tokens live under `@theme`/`:root`/`@layer base|utilities` in `app.css`, and only there are they tuned per mode, never inside a component. Accent tokens (`--accent-primary|-soft|-dim`, …) are also Tailwind colours; `data-palette` on `<html>` re-tints everything (`lantern` default, `ember`/`rose`/`violet`/`sapphire`/`jade`/`copper`/`frost`, each with a daylight variant), so new surfaces never reference `--color-lantern`. Text on a solid accent fill is `text-[var(--primary-foreground)]`; bare `twilight`/`midnight` aren't colours (they silently inherit). Every surface works under every combination of `data-theme="daylight"`, `data-accent="soft|vivid"`, `data-theme-preset`, `data-bg-mode="custom"`, `data-bg-image="on"` (photo: tone and accents derived in OKLCH in `lib/themes/image-palette.ts`; accent palettes held to 4.5:1 on panel surfaces by `accent-palettes.test.ts`), `data-density="compact"` (target rules still apply) and `data-motion="reduced|full"`. Tailwind v4 tree-shaking: conditional or prop-driven colours need `@source inline(…)` in `app.css`, or an inline `style`.
- **Surfaces** climb one ladder: ground (the background) · `capture-surface` (Capture's composer, the page's top surface: `--hero-tint`, a step above cards) · `surface-shell` (page headers, right rail) · `surface-card` (a container: day cells, Week/Day panels, board columns, routine/event cards, Capture feed groups, the DaySpine; `data-lift` for hover, `data-state="today|selected"` to step up) · `surface-item` (a thing inside a card) · `surface-row` (stacked task/capture rows, a quieter step; states set `--row-tint`/`--row-wash`, never a bg) · `surface-control` (header controls: view pickers, Today, segmented groups, chips; `surface-control-accent` + `--control-tone` for Add buttons) · float (`surface-dialog`, `.glass-surface`; menus, popovers, selects and tooltips are `surface-floating`: see-through glass taking the page's colour through `saturate(1.8) brightness(--floating-brightness)` over the lowest legible `--floating-tint`, pinned by `accent-palettes.test.ts`). Tints are the `panel`/`panel-raised` colours (the background's own bases; presets derive them), never accent mixes or a raw `bg-white/[0.0x]` container. Photo mode raises `--card-tint` (no per-card blur) and the floating tint; `photo-shell-surface` lightly tints persistent chrome without its own blur. Weekly Reset has no outer card: each step sits on the page in `weekly-review/StepShell` (large title + count, lists widening by container query), rows and cards on this ladder. `glass-edge` draws the specular rim (dock, lenses, floating glass, the phone sheet's edge; the element must already be positioned). Nested corners are concentric: inner radius = outer radius − inset (border + padding). Reuse `.glass`, `.glass-surface`, `.aurora-accent`, `.dialog-glow` (+ `.dialog-glow-icon`, tone via `--glow-tone`), `.glow-*`, `.focus-pulse-soft`, `.cadence-toast`, `.offline-banner`, `.mobile-sheet-*`, `.safe-*`, `.scrollbar-*`. Top-edge surfaces pad with `safe-header-top` (compact headers) or `safe-top` (full screen); the wide shell pads itself. Standard `backdrop-filter` goes after its WebKit fallback so production optimization keeps it. Z-index only through `.layer-*`, never `z-[…]`; popover/menu content is already `layer-floating-ui` (above dialogs), so never re-layer it.
- **Shell and input:** presentation adapts through shared primitives and one hook, `useShellMode()` (`hooks/ui/use-shell-mode.ts`): `mode` is `wide` ≥1440px, `laptop` ≥1120px (≥768px with a mouse or trackpad, so a tall narrow monitor keeps the desktop shell), `tablet` 768–1119px touch-first only, `phone` <768px; `isTouch` is the touch-first pointer. Never raw breakpoints, `matchMedia` or `innerWidth` in components; check both compact modes. Wide and laptop always show `IconRail`, which owns the destinations; the panel holds only what it alone has (Today, Upcoming, lists, tags). Through `useNavPanel` (`hooks/ui/use-nav-panel.ts`) wide docks the panel (open state persisted) and laptop opens it as a drawer over the content (never restored; closes on navigation, outside click or Escape). Help uses `MainLayout navigationMode="rail"` on wide and laptop (no header, list panel, assistant or dock; compact ignores rail mode); `components/help` owns the feature/Intelligence directory and `?feature=` guide shells; feedback is disabled.
- **Compact:** the dock is Capture · Schedule · assistant · Routines · Browse, its active tab a glass lens (`hooks/ui/use-lens-scrub.ts`) that glides on route changes and, on touch, scrubs under the finger (release over the orb cancels). Every compact header's leading control opens `MainLayout`'s workspace menu sheet (Today, Upcoming, lists, tags); it, Browse and the Settings menu share `layout/NavigationRow` rows in `NAV_GROUP` cards (on touch a link row pushes its page in from the right through a view transition, the mirror of iOS swipe back). Browse owns the profile quick view, Events, Weekly Reset, Settings, Completed, Trash, search and support. Route controls open as a drill-in popover, not a sheet. A bottom sheet is touch-only (`isCompact && isTouch`) and drags from anywhere through `hooks/ui/use-sheet-gesture.ts` (shared by `ResponsiveOverlayPanel` and the phone `Dialog`; never a hand-rolled drag-to-dismiss; `data-sheet-no-drag` opts an inner vertical gesture out); a mouse gets `ResponsiveOverlayPanel`'s full-height side panel at any width. Every compact sheet is a `UtilitySheet` (X at the header's left, the heading centred, its one primary action as a ✓ at the right via `confirm`, never a bottom Cancel/submit; optional band; a pinned footer only for other controls, whose buttons keep focus in a typed field so the keyboard stays up) over the draggable `ResponsiveOverlayPanel` (`fit` sizes a short one to its content), a Radix Dialog (focus trap, Escape, scroll lock, nesting) whose shell alone pads the bottom safe area (dropped while a text field is focused on touch) and rides the keyboard (`useKeyboardInset`, sized to the visible viewport, as do phone `Dialog` sheets; it holds that shape while closing) so footer controls sit just above the keys; a control inside that keeps Escape for itself carries `data-escape-owner`. Pickers (day, emoji, colour) go through `shared/PickerSurface`: a popover, or that sheet on a touch phone (`EmojiPicker` reads Cadence's tokens). Compact task ⋮ is quick actions only (pin, duplicate, trash; editing lives in task detail); task right-click/long-press menus are desktop-only. Compact creation is always the bottom-right orb, never a centred pill (hidden on Browse, Help, Trash, Completed and Weekly Reset); Capture, list and tag pages use it as a direct add (`ContextualAddOrb directCapture`); lists open a `Composer` and manage sections in `tasks/ProjectSheets`, not inline fields. Compact has no global tag filter (`tag-filter-store` is desktop-only): tags open `routes/tag.tsx` (flat, smart-sorted, never reordered), `MainLayout` turns `?tag=` links into it, and the task editor picks tags in `TagPickerSheet`. Horizontal chip rows use `shared/ChipScroller` (wheel/drag without stray clicks). Toasts sit top-centre, clear of the dock; the toaster is its own body child, registered as a Radix dismissable-layer and focus-scope branch with pointer events on, so Undo works over any open sheet or dialog.
- **Readability:** no text opacity below `/90` on twilight-muted text (the contrast floor atop `app.css`); opacity alone doesn't prove contrast over a photo. Fonts: `Sora` (structure and body, `font-sans`), `Outfit` (display and titles, `font-display`). **Accessible controls:** semantic buttons/links, labelled fields, keyboard operation, visible unobscured focus (never `outline-none` without a replacement). Hit targets ≥44×44px; compact may use ≥36px for a fine pointer, but touch targets stay ≥44×44px even when the glyph is smaller. Icon-only controls need `aria-label` + `Tip` (`primitives/Tooltip`), never native `title=""`; a tooltip can't be the only explanation of an essential touch action. `cursor-pointer` on every custom interactive surface.
- **Honest feedback:** progress and failures show beside the affected work when possible, announced where needed; entered text survives with a concrete recovery action; saved on this device differs from synced (toasts: §1).

## 7. Data & State

- `useQuery`/`useMutation` only for server state — no `useEffect`-fetch-into-local-state without a specific non-caching reason.
- `unwrapResponse(res)` takes its type from the RPC route: never pass a generic. A type that doesn't fit is route ↔ contract drift; fix the route (`tests/app/lib/api/rpc-parity.test.ts` pins each read route to its entity).
- Optimistic pattern (`createOptimisticHelpers` per domain in `hooks/{tasks,habits,projects,tags,inbox}/optimistic-helpers.ts`; `edit`/`fail`, and `undo` for a delete behind an Undo window): creates pick their id with `clientIdFor(input)` and send it as both `id` and `Idempotency-Key` (the server keeps it), so the optimistic row is the real row (placing a capture sends its new task's `taskId` the same way); cancel in-flight queries → snapshot cache → update immediately → write the server's answer into every list (`reconcileTaskInCaches`) → rollback and invalidate on error. Task writes don't refetch on success, and invalidation only refetches what's on screen; hidden lists refetch when visited. Read one task with `useTask(id)`, never by loading whole state lists. Rate-limited reads are not retried; writes wait out `Retry-After`.
- Query keys centralized in `app/lib/api/query-keys.ts` (domains: tasks, projects, inbox, tags, habits, location, weather, appearance, settings, ai) with differentiated `STALE_TIMES` — don't invent arbitrary per-hook caching windows.
- `authenticatedFetch` refreshes and retries a 401 once for reads, writes and assistant streams; terminal expiry locks local auth and returns to sign-in, keeping unsynced work. Query errors only report failures. A request that got no answer (`NETWORK_UNAVAILABLE` from `authenticatedFetch`: offline, timeout, captive portal) is never an auth failure. Other query errors are logged there once (dev); hooks don't log their own.
- **Offline queue:** rules live in `app/lib/api/AGENTS.md`.
- **Notes:** rules live in `app/lib/notes/AGENTS.md`.
- Logging and failures: `lib/log.ts` only, never raw `console.*` (`worker.ts` excepted; `log.debug`/`log.warn` dev-only; `log.error` always, in production one plain sentence plus `errorRef`: `code · requestId · version`, which finds the backend's `request_failed` line). Toast mechanics (policy in §1): Undo goes through `lib/utils/undo-toast.ts` — `toastUndo` when the action is already done and reversible (Trash); `undoWindow` awaited first in `mutationFn` when the server can't reverse it, so the item leaves at once but nothing is sent until the 7s window closes (Undo throws `UndoneError`, which `onError` rolls back without an error toast; closing the tab inside the window keeps the item). Confirm only what can't be undone (Empty Trash, delete account, permanent delete from Trash, clear archive); an Undo toast replaces any other confirm. Every toast goes through the patched `toast.*` methods (never bare `toast()`), which carry the Cadence look and stretch any "Undo" toast to `CADENCE_UNDO_DURATION`. Failures toast through `toastError(err, "Couldn't …")` (`lib/utils/error-toast.ts`: a plain reason from the status, rate limits as one shared toast, Copy details); never show `err.message`. Crash screens (`root.tsx`, `shared/RouteErrorBoundary`) show `shared/ErrorDetails`; crashes, unhandled errors and failed queries/actions send bounded error categories through `/events/errors` only with resolved Crash reports consent. Never log tokens, OAuth URLs or callback query strings.
- Local UI state: Zustand (`app/stores/`, see §5). `useSettings()` seeds from account-local storage only when cached data exists; query persistence waits for account identity before restoring, coalesces storage writes for 250 ms, drops legacy unzoned routine ranges on restore, and flushes on hide/account transition (the WAL stays independently durable). Startup reuses cached data and waits only for the entry route's missing first-screen data (`FIRST_SCREEN` in `use-workspace-startup.ts`), never for decoration, the assistant, focus views, notification state or the debug probe (`useAdminCapabilities`: only with `VITE_ENABLE_DEBUG_ROUTES=true` or dev, after reveal); the photo background gets four seconds. Boot reads the saved cache in parallel with the session check (`prefetchSavedWorkspace` in `entry.client.tsx`), and a head script starts `get-session` before the bundle loads (`lib/auth/session-prefetch.ts`). The NLP parser (chrono) and `EditSidePanel` load lazily; `@supabase/auth-js` is aliased to the four error classes the auth SDK needs (`vite.config.ts`). `WorkspaceStartup` records fixed User Timing phases with bounded categories and batches them through `/events/performance` only with resolved, enabled usage diagnostics; each privacy opt-out clears its queued reports, and account changes clear both gates. Keep durable preferences in Query, Zustand, or local cache.

## 8. Domain Behavior to Preserve

- **Tasks:** tasks, events, habits and capture clarification use `EditSidePanel`, shared title/header/section controls and a type label (Task, Fixed or Routine); domain editors own their fields. The route's select handler toggles: opening the open item again closes it (compact sheet included); explicit Edit actions only open. All edit rails animate and resize through `EditSidePanelRail`; smaller layouts use overlays. Task list routes take both from `useTaskDetailSelection` + `shared/TaskDetailsPanels` (`TaskDetailsRail`, `PhoneTaskDetails`). Event cards open the editor outside interactive controls. Creation (tasks, thoughts, schedule blocks, events, routines) goes through `shared/Composer.tsx`: dialog on desktop, `UtilitySheet` on compact (X and ✓ from the draft's `submit`), in place with `inline`, built-in Cancel/X with a discard guard; each draft sets a header `icon` and a `tone` (nav wayfinding shade) that colours the icon, submit and the `dialog-glow` surface. Each creator is a `use…Composer` hook returning a `ComposerDraft` (`useTaskComposer`, `useCaptureComposer`, `useRoutineComposer`, `usePersonalEventComposer`), so one shell can host several (Quick Add, the schedule popover) or wrap one; never rebuild a creator's fields elsewhere. Parsed titles fill date/time fields through `useTypedWhen`, and typed tasks are saved with `buildTypedTaskInput`. Composer parts: plus `ComposerTitle`, `ComposerTabs` (segmented; passed as `switcher` it is the compact header's centre, text only, between X and ✓), `ComposerRows`/`ComposerRow` (the iOS grouped card: label left, `ROW_PILL` date/time pills or a switch right; the when always sits here, under the title), `WeekdayPicker`, `ComposerToggle` and a `ComposerMore` fold that holds only detail (list, notes, tags, steps, priority, effort; its summary names the list); `CadencePicker` is built from them. "Waiting" is a first-class state, not a hack. Ordering uses fractional indexing — `app/lib/utils/order-index.ts` (`computeNextOrderIndex`, `computeMidpointIndex`); never renumber whole lists unnecessarily. Upcoming buckets the next 7 days; every later task goes to `upcoming/FurtherOutSection` (folded to one line, grouped by `groupFurtherOut`: four calendar weeks, then months), kept folded or open per device and opened for one visit by a route focus inside it or `?further`. Every row-view section folds from a leading › (`FoldButton` with a Collapse/Expand tip; `useSectionFold` in `shared/BucketedCollectionView`, list sections in `SectionedTaskList`, which on compact rows sit open like Today's with the `Columns3` icon, never boxed (Board boxes them); `foldable: false` for one that folds itself, like Further out). Per-device view choices (folds, hidden columns, Events' cards/list view) go through `useDeviceValue`/`useDeviceFlag`, never settings. Sorts (task pages via `useSortMode(page)`, Routines) and the focus view/Capture order (`useFocusViewUrl`) also live in the address (`?sort=`, `?order=`, `?focus=`, `?saved=`, and a custom view as `?state=&pmin=&bare=…` via `@cadence/nlp/focus-views/url`) through `useUrlState`: URL, then device, then default; Weekly Reset exits to `returnPath()` (`lib/resume-route.ts`); its steps (Welcome · Captures · Loose ends · Routines · Huddle · Your week; ids stable, `stabilize` is Loose ends, `ready` is Your week) are any-order through the clickable sidebar or the phone header's segments, Back/Next/Done live in one sticky `StepFooter` (the batch bar replaces them while rows are picked), and each row's day choices come from `dayActions` (`useWeekRoom`'s `dayFor` turns a decision-model bucket from `useResetSuggestions` into a real day; a guess only takes the primary slot, marked with a sparkle); Huddle is `ResetChat` alone (skippable); Your week is `WeekView` (7 day tiles, the picked day's view below), and a task, routine or Routines' Edit opens `EditSidePanel` beside the step (an overlay below wide), never leaving the reset; Events' list is `events/EventList` (month-grouped for date sorts).
- **Schedule & Calendar:** rules live in `app/components/calendar/AGENTS.md`.
- **Repeats:** three kinds, told apart by "if I miss one…" (`shared/RepeatKindPicker`): **Fixed** (`interactionMode: "timetable"`, no check-off, never overdue), **Routine** (a `habits` row; misses let go, never carried over or shown as catch-up), **Task** (carries over). The UI says Routines and Lists, never Habits or Projects; code and DB keep `habit` and `project`. Switching Task ⇄ Routine goes through `hooks/habits/use-convert-repeat.ts` (create new, then trash/archive old, one Undo). Routine times per day come from `routineTimeOn` (`@cadence/domain/repeats`); show a routine with `habits/RoutineMark` (its emoji, else the `Flame`; `Repeat` means a repeating task only) and respect `settings.tasks.showStreaks`. Today = `today/DaySpine` (Fixed only, now/next: a strip in list view, the first board column as a vertical timeline in board view) over Still open (carried-over tasks, only when non-empty) · Today · Routines (`shared/RoutineAgendaList`, done ones folded). Its controls menu holds **Fit into today's gaps** (see Find a time).
- **Routines:** rules live in `app/components/habits/AGENTS.md`.
- **App Links:** rules live in `app/lib/app-links/AGENTS.md`.
- **Natural language:** every composer (inline add, Task dialogs, calendar block, routine, yearly event, capture → task, Weekly Reset) reads typed words through `useNlpParse` → `@cadence/domain/nlp-draft`: computed during render, so what shows is what Enter saves (`ready`/`finalize()` only cover the parser module still loading). ## 10. Auth

Neon Auth via `authClient` (`app/lib/auth-client.ts`, 20-second SDK deadline), account-validated session JWT seeding (`lib/api/client.ts`), and lazy `AuthUIBoundary` + `AuthView` on auth routes; workspace controls use `useAuthState`. Pages outside the workspace (sign-in/up, auth callbacks, consent, route and root error boundaries) share `shared/CardPage` (stars, glass card with the diagonal sheen, logo, optional title/description/actions); third-party UI themed via `.neon-auth-wrapper` in `app.css`. Web callbacks restore through `useAuthState` with serial retries for up to 15 seconds; only a resolved session permits workspace navigation, except status `offline`: when the session can't be checked for lack of a connection, the last signed-in identity (`lib/auth/offline-identity.ts`, no tokens) opens its cached workspace until the connection returns. Web warm starts do the same while the session is checked (status `provisional`, workspace paths only): API calls and WAL replay wait in `client.ts` (`holdForSession`) and writes queue; desktop waits for the session before revealing its workspace; an anonymous answer goes to sign-in, another account remounts and aborts the held calls. Fresh recovery bypasses the SDK cache; desktop callbacks consume the handoff once across remounts and the callback listener lives above the account cache. Auth UI session changes invalidate queries; account identity changes remount the isolated cache. Do not introduce a parallel auth stack. Legal acceptance: sign-up (`routes/auth.tsx`) gates the whole form behind two ticks (16+, Terms and Privacy Policy; `shared/ConsentCheck`), and `layout/MainLayout` mounts `legal/LegalConsentGate`, a blocking panel for any signed-in account whose `privacy.legalVersion` isn't `LEGAL_VERSION` (`@cadence/contracts/settings`; bump it to ask everyone again, and match the `updated` date of the landing policies). It covers new Google/GitHub accounts made from sign-in and accounts from before the step, and records quietly when the sign-up ticks were just made (`lib/legal-consent.ts`). Client-side only: the API doesn't refuse an account that hasn't accepted. `routes/connect.tsx` is the consent page for outside assistants (MCP): signed-out visitors go to sign-in with `redirectTo` back to it; approving or declining (`hooks/core/use-connections.ts`) returns a URL on the MCP origin that the page opens with `location.assign` (that origin checks the cookie this browser got when the assistant started; never navigate there any other way). Settings › Integrations lists them (`settings/ConnectedAssistants.tsx`, Disconnect behind a confirm); scope wording lives in `lib/constants/mcp.ts`. Calendar/notes sync controls below it stay disabled Coming Soon. Managed Neon Auth pins its client plugins (JWT, admin, organization, email OTP, magic link, phone number); anything else (2FA, passkeys) isn't callable, so don't build UI for it. Settings › Active Devices lists sessions only within a day of sign-in (Better Auth `freshAge`; `/list-sessions` returns 403 after), then offers `revokeOtherSessions`.

Browser E2E (agents, Playwright): sign in at `/auth/sign-in` with `E2E_EMAIL`/`E2E_PASSWORD` from `apps/frontend/.env` (git-ignored), a password user on the dev Neon branch only. Missing after a branch reset? `POST {VITE_NEON_AUTH_URL}/sign-up/email` with `Origin: http://localhost:8788` and `{email,password,name}` recreates it, then set `neon_auth."user"."emailVerified"=true` for it (dev DB, `MANAGEMENT_DATABASE_URL`) and add its id to `ADMIN_USER_IDS` in `apps/backend/.dev.vars` (admin tools + `POST /debug/seed`). Use a fresh browser context so a real session isn't signed out.

## 11. Web vs. Desktop Boundary (`app/platform/`)

`runtime.ts` is the web/desktop switch and holds the only Tauri-window and storage checks (`hasDesktopWindow`, `getDesktopStore`, `getWebStorage`); `desktop*.ts` / `web.ts` are the two implementations. The native quick-capture window and OS menu commands are in [`apps/desktop/AGENTS.md`](../desktop/AGENTS.md). `hooks/core/use-wake-refresh.ts` after a sleep gap refetches active queries when the window is visible (only marks them stale when hidden, so a tray app doesn't wake the database) and fires `cadence:wake` for windows that wake without focus; `use-zone-sync.ts` writes the zone once per app start and then only when it changes. Settings › About's "Reload fresh" (`repairWorkspaceCache`) drops only the saved query snapshot, never the WAL. New platform-divergent behavior goes behind this boundary, never an inline `if (Tauri)` in domain components.
