# Cadence Frontend — Agent Instructions

React Router v8 SPA (`ssr: false`, intentional) deployed as static assets on Cloudflare Workers. Consumes the shared backend ([`@cadence/backend`](../backend)) exclusively through a typed Hono RPC client — never invent client-only API contracts. This is also the source codebase for the [desktop app](../desktop): a `platform/` runtime boundary swaps web-vs-desktop behavior, so most code must stay platform-neutral. It embodies the **Twilight Sanctuary** design language (full philosophy: [`docs/MANIFESTO.md`](../../docs/MANIFESTO.md), §5); functional correctness and aesthetic integrity are equally non-negotiable.

## 1. Non-Negotiables

- Client-rendered SPA. Do not introduce SSR assumptions.
- All server data flows through **TanStack Query**; all API calls through the one typed Hono RPC client (`apiClient` in `app/lib/api/client.ts`, built on `authenticatedFetch`; `useApiClient()` returns it) — never raw `fetch` for backend calls and never `as any` on the client. Only the transports (`mutation-executor.ts` WAL replay and its Background Sync twin in `public/sw.js`, the assistant's `chat-transport.ts`) sit below it.
- Reusable hooks → `app/hooks/`; non-UI logic → `app/lib/`; shared UI → `app/components/` grouped by domain; Radix always through `app/components/primitives/`, never imported raw into domain components.
- No sterile SaaS styling: no white cards, harsh borders, gray dashboards. Prefer glass, shadow, ambient color, breathing room. Never hardcode a one-off hex when a semantic token belongs in `app/app.css`.
- Notification settings fields are required in the settings schema — never optional.
- Mutations are optimistic-first: snapshot → update immediately → rollback on error → reconcile on settle.

## 2. Tech Stack

React 19 · React Router v8 (SPA mode) · Cloudflare Workers + Wrangler assets · Tailwind CSS v4 (`@theme` in `app/app.css`) · Framer Motion + `tw-animate-css` · TanStack Query · Hono RPC (`hc<AppType>`) · Neon Auth (`@neondatabase/auth`) · Radix UI (wrapped) · Lucide icons · dnd-kit · Zustand · `react-markdown` + `remark-gfm` · `date-fns` · Vercel AI SDK (`@ai-sdk/react`, `ai` v7) for the assistant · TypeScript 7.

## 3. Runtime Shape

- Shell: `app/root.tsx` (HTML shell, fonts, error boundary, iOS home-screen meta — `viewport-fit=cover`, opaque `black` status bar (`black-translucent` leaves a bottom gap on iOS 26), iOS-only `maximum-scale=1` against focus zoom; dev unregisters leftover preview service workers) · `app/providers.tsx` (account-keyed query persistence + auth, persistent background, `WorkspaceStartup` waits for the entry route's first-screen queries and suspense) · `worker.ts` (SPA static assets; `/api/v1/*` to the backend through the `BACKEND` service binding, so the web API is same-origin with no CORS preflight; transparent same-origin Neon Auth proxy at `/api/auth/*` that forwards cookie values verbatim; exchanges the single-use `neon_auth_session_verifier` on the `/auth/callback` navigation, then leaves via a script `location.replace`. Proxied cookies stay `SameSite=None; Secure` (first-party); both auth paths and `/api/v1/*` are in `assets.run_worker_first`; hashed assets are served directly with immutable caching from `public/_headers`, and a missing one (not a navigation, so it reaches the Worker) gets a non-cacheable 404 instead of SPA HTML). `public/sw.js` bypasses `/auth` and `/api`, serves navigations from the validated cached shell at once and refreshes it in the background (network only without one), respects `no-store`, and caches only the offline shell and validated, hashed build assets (all precached, including shared desktop-named chunks: `react-router.config.ts` writes the entry closure first; install uses three low-priority downloads at a time; activate keeps this build's and the previous one's); never auth responses, dev modules or mutable CSS. On Chromium its `sync` handler replays the offline queue while no tab is open. Web notifications go through the SW registration (iOS has no `Notification` constructor); `sw.js` focuses the app on click. Icons: `apple-touch-icon.png`, `icon-192/512.png` (opaque, from `logo.png`).
- Build env: `VITE_NEON_AUTH_URL`, `VITE_API_BASE_URL`. Deployed web builds ignore both: the API is `${origin}` (the Worker forwards `/api/v1`) and auth is `${origin}/api/auth` (`lib/env.ts`), so auth cookies are first-party — iOS/WebKit blocks third-party cookies and OAuth never completes; dev and desktop call Neon Auth directly. Worker runtime: `NEON_AUTH_BASE_URL` (var). App version/changelog are **not** env vars — `vite.config.ts` reads root `package.json` + `CHANGELOG.md` at build time (`release-info.ts`); `lib/constants/changelog.ts` holds no entries; it also stamps a per-build `CADENCE_BUILD_ID` and emits it as `/version.json`, which `providers.tsx` polls on the web (tab visible, every 10 min) to show a sticky Reload toast after a deploy.

## 6. Design System (full detail: `docs/MANIFESTO.md` §5)

- Tokens live under `@theme`/`:root`/`@layer base|utilities` in `app.css`. Accent tokens (`--accent-primary|-soft|-dim`, etc.) are also Tailwind colors; `data-palette` on `<html>` re-tints everything (`lantern` default, `ember`/`rose`/`violet`/`sapphire`/`jade`/`copper`/`frost`, each with a daylight variant) — don't reference `--color-lantern` directly in new surfaces. Text on a solid accent fill is `text-[var(--primary-foreground)]`; bare `twilight`/`midnight` are not colors (they silently fall back to inherited text).
- Every surface must work under every mode combo: `data-theme="daylight"`, `data-accent="soft|vivid"`, `data-theme-preset`, `data-bg-mode="custom"`, `data-bg-image="on"` (photo background: tone + accents derived in `lib/themes/image-palette.ts`), `data-density="compact"` (targets stay ≥36px), `data-motion="reduced|full"`. Weekly Reset uses the shared background with tinted step panels; shared glass, utility overlays and Settings surfaces use these semantic tokens; `photo-shell-surface` gives persistent photo-mode chrome a light tint without a separate backdrop blur. Never patch per-mode inside a component.
- Surfaces climb one ladder, tuned per mode only in `app.css`: ground (the background) · `capture-surface` (Capture's composer, the page's top surface: `--hero-tint`, a step above cards) · `surface-shell` (page headers, right rail) · `surface-card` (a container that holds things: day cells, Week/Day panels, board columns, routine/event cards, Capture feed groups, the DaySpine; `data-lift` for hover, `data-state="today|selected"` to step up) · `surface-item` (a thing inside a card) · `surface-row` (stacked task/capture rows, a quieter step; states set `--row-tint`/`--row-wash`, never a bg) · `surface-control` (header controls: view pickers, Today, segmented groups, chips; `surface-control-accent` + `--control-tone` for Add buttons) · float (`surface-dialog`, `.glass-surface`). Tints are the `panel`/`panel-raised` colors (the background's own bases; presets derive them), never accent mixes and never a raw `bg-white/[0.0x]` for a container; photo mode raises `--card-tint` without a per-card blur. Reuse existing utilities (`.glass`, `.glass-surface`, `.aurora-accent`, `.dialog-glow` (+ `.dialog-glow-icon`, tone via `--glow-tone`), `.glow-*`, `.focus-pulse-soft`, `.cadence-toast`, `.offline-banner`, `.mobile-sheet-*`, `.safe-*`, `.scrollbar-*`). Anything touching the top edge pads with `safe-header-top` (compact headers) or `safe-top` (full-screen surfaces); the wide shell pads itself. Put standard `backdrop-filter` after its WebKit fallback so production optimization preserves it. Z-index: only `.layer-*` utilities, never arbitrary `z-[…]`; popover/menu content is already `layer-floating-ui` (above dialogs), so never re-layer it.
- Layout via `useShellMode()` (`app/hooks/ui/use-shell-mode.ts`: `wide` ≥1440px, `laptop` ≥1120px, `tablet` ≥768px, `phone` <768px) — never raw breakpoints. Wide always shows `IconRail` beside the panel; laptop puts workspace nav in the panel and shows the rail only while the panel is hidden (collapsed, or Schedule/Routines/Events). Phone/tablet dock is Capture · Schedule · assistant · Routines · Browse; every compact header's leading control opens `MainLayout`'s workspace menu sheet (Today, Upcoming, projects, tags); it, Browse and the Settings menu share `layout/NavigationRow` rows in `NAV_GROUP` cards under `NAV_GROUP_LABEL` headings; Browse owns the profile quick view, Events, Weekly Reset, Settings, Completed, Trash, search and support. Header actions keep Notifications and contextual Focus/Controls, and route controls open as a popover that drills into sub-panels, not a sheet. Every compact sheet — search, schedule creation, routine creation, Settings, Notifications, the workspace menu — is a `UtilitySheet` (heading or header slot, optional band and pinned footer) over the draggable `ResponsiveOverlayPanel` (`fit` sizes a short one to its content, like Trash's task sheet), whose shell alone pads the bottom safe area (dropped while a text field is focused on touch, since the keyboard covers it); Profile & Security lives inside Settings. Compact task ⋮ is a quick-actions dropdown (pin, duplicate, trash; editing lives in task detail) and task right-click/long-press menus are desktop-only. Compact creation is always the bottom-right orb, never a centred pill (the dock owns the centre; its menu has a tap-to-close scrim; Browse, Trash, Completed and Weekly Reset hide it); Capture, projects and tag pages use it as a direct add (`ContextualAddOrb directCapture`); projects open a `Composer` and manage sections in `tasks/ProjectSheets` instead of inline fields (opened from a section header's ⋯, a full-width button under the list, or a Sections chip pinned beside the board chooser). Compact has no global tag filter (`tag-filter-store` is desktop-only): tags from the workspace menu or a task's chip open `routes/tag.tsx` (flat, smart-sorted, never reordered; ⋮ opens one name + colour sheet, or deletes), `MainLayout` turns `?tag=` links into it, and the task editor picks tags in `TagPickerSheet`. Horizontal chip rows use `shared/ChipScroller` (mouse wheel/drag without stray clicks). Compact toasts sit top-centre, clear of the dock, and are swiped away in any direction. Check both compact modes. Tailwind v4 tree-shaking: conditional/prop-driven colors need `@source inline(…)` in `app.css`, or an inline `style`.
- Contrast floor: no text opacity below `/90` on twilight-muted text (enforced comment at top of `app.css`). Fonts: `Sora` (structural/body, `font-sans`), `Outfit` (display/titles, `font-display`). Every interactive element needs a visible focus style — never `outline-none` without a replacement. Hit targets ≥44×44px (≥36px compact); icon-only controls need `aria-label` + `Tip` (`primitives/Tooltip`), never native `title=""`. `cursor-pointer` on every custom interactive surface, no exceptions.

## 7. Data & State

- `useQuery`/`useMutation` only for server state — no `useEffect`-fetch-into-local-state without a specific non-caching reason.
- `unwrapResponse(res)` takes its type from the RPC route: never pass a generic. A type that doesn't fit is route ↔ contract drift; fix the route (`tests/app/lib/api/rpc-parity.test.ts` pins each read route to its entity).
- Optimistic pattern (`createOptimisticHelpers` per domain in `hooks/{tasks,habits,projects,tags}/optimistic-helpers.ts`): creates pick their id with `clientIdFor(input)` and send it as both `id` and `Idempotency-Key` (the server keeps it), so the optimistic row is the real row; cancel in-flight queries → snapshot cache → update immediately → write the server's answer into every list (`reconcileTaskInCaches`) → rollback and invalidate on error. Task writes don't refetch on success, and invalidation only refetches what's on screen; hidden lists refetch when visited. Read one task with `useTask(id)`, never by loading whole state lists. Rate-limited reads are not retried; writes wait out `Retry-After`.
- Query keys centralized in `app/lib/api/query-keys.ts` (domains: tasks, projects, inbox, tags, habits, location, weather, appearance, settings, ai) with differentiated `STALE_TIMES` — don't invent arbitrary per-hook caching windows.
- Global query errors sign the user out on 401-ish failures and redirect to `/auth` — do not break this. A request that got no answer (`NETWORK_UNAVAILABLE` from `authenticatedFetch`: offline, timeout, captive portal) is never an auth failure. Other query errors are logged there once (dev); hooks don't log their own.
- **Offline:** everyday writes go through `withOfflineSupport(toOp, apiFn)` (`lib/api/offline-mutation.ts`): offline, on a network failure, or while earlier changes wait, the op is queued in the per-account WAL (`offline-wal.ts`: Web Lock + BroadcastChannel across tabs) and the call resolves `undefined`, so `onSuccess` guards it and `onSettled` skips refetches via `wasQueued`. Each op type needs a `toRequests` case in `mutation-executor.ts`; replay is ordered, stops on network failure, drops edits to deleted items, holds later changes behind a failed one and sends no `expectedUpdatedAt` (last write wins per field). Note saves differ: they carry `expectedVersion`, an `opId` (the Idempotency-Key, fixed per payload) and their tab's `branch`; unsent saves fold only within one branch + base, a frozen (`attempted`) entry is never replaced, and a 409 is merged by `lib/notes/note-reconcile.ts` or parked as a `conflict` entry for Sync review (never appended to the note). Online-only: the assistant, settings, uploads, deleting lists/tags/sections. After workspace reveal, `useOfflineWindow` warms the phone views (−7…+21 days) through their own cache keys: open task lists use one bounded `GET /tasks/batch`, warming runs at most three transports at once. It skips hour-fresh/in-flight task lists and unsynced edits, cancels the task transport on unmount and stops queued work when hidden, offline, replaying pending writes or fetching active foreground queries; the persisted cache lives 14 days (`gcTime` matches). Rows show `shared/PendingMark`; the banner's Review opens `SyncReviewSheet`; sign-out with queued changes or unsaved note text asks first (`useSignOut`).
- **Notes:** one `NoteSession` per account + canonical owner per tab (`lib/notes/note-session.ts`, held by `note-registry.ts`, read through `useTaskNote`): it owns content generations, the acknowledged revision, one in-flight save (≈600ms idle, ≤2s while typing), the device journal (`note-journal.ts`, per-branch drafts under a Web Lock) and the derived status (`noteStatus`: Saved · Saving… · Saved on this device · Couldn't sync · Review changes · Couldn't save). Other tabs converge through `note-channel.ts` + 10s polling + `mergeNotes` (disjoint edits only; overlap → review, both texts kept). The editor is Tiptap over a bounded schema (`note-markdown.ts`; `isFaithful` sends a note it would lose text from to Markdown source) shared by `TaskNoteRoom` (desktop/tablet toolbar, phone reading/editing with ✓ Done, `NoteQuickStrip`, Aa/+ panels, `useKeyboardInset`) and `TaskNoteInline`; every command comes from `components/tasks/note/note-commands.ts`. Stored text stays Markdown; opening a note never writes.
- Logging and failures: `lib/log.ts` only (`log.debug`/`log.warn` dev-only; `log.error` always, in production one plain sentence plus `errorRef`: `code · requestId · version`, which finds the backend's `request_failed` line). Failed actions toast through `toastError(err, "Couldn't …")` (`lib/utils/error-toast.ts`: a plain reason from the status, rate limits as one shared toast, Copy details); never show `err.message`. Crash screens (`root.tsx`, `shared/RouteErrorBoundary`) show `shared/ErrorDetails`; crashes, unhandled errors and failed queries/actions send bounded error categories through `/events/errors` only with resolved Crash reports consent. Never log tokens, OAuth URLs or callback query strings.
- Local UI state: Zustand (`app/stores/`, see §5). `useSettings()` seeds from account-local storage only when cached data exists; query persistence waits for account identity before restoring, coalesces storage writes for 250 ms, drops legacy unzoned routine ranges on restore, and flushes on hide/account transition (WAL stays independently durable). Startup reuses cached data and waits only for the entry route's missing first-screen data (`FIRST_SCREEN` in `use-workspace-startup.ts`: Capture's feed, a list's tasks/sections; other routes everything mounted), never for decoration, the assistant, focus views, notification state or the debug probe (`useAdminCapabilities` asks only in builds with `VITE_ENABLE_DEBUG_ROUTES=true` or dev, after reveal); the photo background gets four seconds. Boot reads the saved cache in parallel with the session check (`prefetchSavedWorkspace` in `entry.client.tsx`) and a head script starts `get-session` before the bundle loads (`lib/auth/session-prefetch.ts`). The NLP parser (chrono) and the entity editors (`EditSidePanel`) load lazily; `@supabase/auth-js` is aliased to the four error classes the auth SDK needs (`vite.config.ts`). `WorkspaceStartup` records fixed User Timing phases (boot, headers with their start offsets, normal JSON-body consumption, restore and reveal-frame opportunity; `provisional` cache class for warm starts revealed before the session answered), with bounded endpoint/status/error and build/revision cohorts, and batches timings through `/events/performance` only with resolved, enabled usage diagnostics; each privacy opt-out clears/aborts its queued reports; account changes clear both gates. Failures stay recoverable. Keep durable preferences in Query, Zustand, or local cache.

## 8. Domain Behavior to Preserve

- **Tasks:** tasks, events, habits and capture clarification use `EditSidePanel`, shared title/header/section controls and a type label (Task, Fixed or Routine); domain editors own their fields. The route's select handler toggles: opening the open item again closes it (compact sheet included); explicit Edit actions only open. All edit rails animate and resize through `EditSidePanelRail`; smaller layouts use overlays. Event cards open the editor outside interactive controls. Creation (tasks, thoughts, schedule blocks, events, routines) goes through `shared/Composer.tsx`: dialog on desktop, `UtilitySheet` on compact, in place with `inline`, built-in Cancel with a discard guard; each draft sets a header `icon` and a `tone` (nav wayfinding shade) that colours the icon, submit and the `dialog-glow` surface. Each creator is a `use…Composer` hook returning a `ComposerDraft` (`useTaskComposer`, `useCaptureComposer`, `useRoutineComposer`, `usePersonalEventComposer`), so one shell can host several (Quick Add, the schedule popover) or wrap one; never rebuild a creator's fields elsewhere. Parsed titles fill date/time fields through `useTypedWhen`, and typed tasks are saved with `buildTypedTaskInput`. Composer parts: plus `ComposerTitle`, `ComposerTabs` (segmented), `WeekdayPicker`, `ComposerToggle` and a `ComposerMore` fold; `CadencePicker` is built from them. Tasks are the main product unit; list + kanban views; "waiting" is a first-class state, not a hack; `notBefore`, `effort`, tag filtering, sections, subtasks all active. Ordering uses fractional indexing — `app/lib/utils/order-index.ts` (`computeNextOrderIndex`, `computeMidpointIndex`); never renumber whole lists unnecessarily.
- **Schedule:** multi-mode (month/week/day/year), task/routine reads fetch only the active range; holidays reuse cached years for 7 days by country, subdivision and locale; compact shells change period by dragging the calendar body (`hooks/ui/use-period-swipe.ts` — drag-follow, velocity commit, flat under reduced motion) into the same direction/slide path the header arrows use; task block context menus and the shared editor expose Trash with whole-series wording for recurring blocks; Undo restores the task and requests its details through `useTaskDetailsRequest` on task routes. Habit logs hydrate into **virtual habit tasks** on some schedule surfaces — intentional hybrid behavior, don't simplify away. **Phones** (`components/calendar/phone/`) zoom Day → Month → Year (no Week; `?view=week` shows Day, which fetches the whole week) under a header whose back label zooms out: `DayStrip` (week, load dots, `day-<iso>` drop targets) over `DayAgenda` (markers, any-time, timeline with now line, free gaps, "Earlier today" fold); `MonthFold` (grid folds into the selected week on the first few px of an upward swipe and reopens on a pull or a fling that lands at the list top). Rows are `ScheduleRow`: drawn by kind (`lib/utils/calendar/schedule-day.ts` — one grouping, routines included), swipe right to complete, left for next day / Pick day. Routines open `EditSidePanel kind="habit"` in the overlay on compact. Clutter toggles are per kind (`calendar.clutter.showFixed` etc.). Desktop Month folds repeating Fixed blocks into one line per cell (`splitMonthDay`: span and count, opens the day), timed chips lead with their start time, and past days rest dimmer; Day's all-day chips size to their words and wrap to two rows, Week's single slot goes to one-off tasks before routines.
- **Repeats:** three kinds, told apart by "if I miss one…" (`shared/RepeatKindPicker`): **Fixed** (`interactionMode: "timetable"`, no check-off, never overdue), **Routine** (a `habits` row; misses let go, never carried over or shown as catch-up), **Task** (carries over). The UI says Routines and Lists, never Habits or Projects; code and DB keep `habit` and `project`. Switching Task ⇄ Routine goes through `hooks/habits/use-convert-repeat.ts` (create new, then trash/archive old, one Undo). Routine times per day come from `routineTimeOn` (`@cadence/domain/repeats`); show a routine with `habits/RoutineMark` (emoji or glyph) and respect `settings.tasks.showStreaks`. Today = `today/DaySpine` (Fixed only, now/next: a strip in list view, the first board column as a vertical timeline in board view) over Still open (carried-over tasks, only when non-empty) · Today · Routines (`shared/RoutineAgendaList`, done ones folded).
- **Routines:** one range query (`useHabitsRange` → `/habits/weekly`, any start/end, under the `weeklyAll` prefix, keyed by start/end/timezone/archive state) feeds week, month and History, so every optimistic resolve covers them all; the week start comes from settings. A Today band (`RoutineTodayBand`: ring + `shared/RoutineAgendaList`, the same rows as Today in each routine's colour, side by side on desktop, current period only, collapse kept per device) leads the month and compact views; on a desktop week the grid's tinted today column is today's check-in instead, never both. Below: the week (`RoutineWeekRow`, `stacked` on phone, done count only, never "of N") or month (`RoutineMonthGrid` cards that share the row, the whole month on desktop (weeks with nothing due greyed), weeks before the routine trimmed on phone, dates kept on logged days; neutral footer: check-ins, plus longest run when streaks show; never misses); a click anywhere on a row or card outside its cells and ⋯ opens the routine (`openOnCardClick`). Like Schedule, desktop picks Week/Month from a select and the far-right gear holds view options. Every day is a `RoutineDayCell` (done is the brightest state; an open past day rests as a dot until hovered or focused): any past scheduled day can be logged; click/tap toggles done (touch adds Undo), right-click/long-press opens Done · Skip · Clear; grids are one roving tab stop (`hooks/ui/use-roving-grid.ts`: arrows, Space, `S` skip, `E` edit). A routine's colour (`colorAccent`, list palette via `routineTone`, default moonlit) tints its mark and cells; a personal event's optional `color` uses the same palette via `eventToneStyle` (`--event-tone` for surfaces, `--event-ink` text mixed toward the theme text so it stays AA; none keeps the schedule tint). Composers pick either with `shared/ColourDot`. Pauses run from today (`isRoutinePaused`), never hiding logged days. Menus and the editor share `useRoutineActions` (pause, archive, one confirmed delete); the editor (`EditSidePanel kind="habit"`) has a This week strip (plus today's steps), Notes (purpose + notes, open only when written), Steps, Details (cadence as a dropdown via `CadencePicker select`) and a tappable History, then Archive beside a Pause ▾ menu. Steps (`habits/RoutineSteps`: editor on the subtask rows, checklist to tick or skip each) are edited in the composer's More fold and the editor's Steps section; a cell tap still sets every step, the day menu lists them, and partial days show "2/3" (`stepProgress`) in the open look, count only on Today.
- **Natural language:** every composer (inline add, Task dialogs, calendar block, routine, yearly event, capture → task, Weekly Reset) reads typed words through `useNlpParse` → `@cadence/domain/nlp-draft`: computed during render, so what shows is what Enter saves (`ready`/`finalize()` only cover the parser module still loading). The hook takes the user's hand-set fields as `manual`, plus `dismissed`/`accepted` ids, `literal` ("Keep as written") and the surface's `capabilities`; `DraftRow` shows only what has no control of its own and the few choices. Writes that carry `nlp.resolved` are stored as sent, never reinterpreted. Weekly Reset places captures through `useProcessInboxToTask` and changes tasks with a typed `InstructionField` (+ bounded batch, `useApplyInstruction`; a row passes its list so a shared section name resolves). Inside a list the inline add does not read list names. The Effort suggestion (`useEffortSuggestion`, opt-out `tasks.intelligence.effortSuggestions`; task composers, calendar block, inline add) is a recommendation only; the draft's own Effort always wins, and a hand or accepted choice sends `effortOrigin`.
- **Inbox / Capture:** `useCaptureFeed` owns the shared badge and feed filters: New thoughts, No day yet tasks, Older after 14 days and kept Notes (folded, excluded from counts). `CaptureRow` shares a menu calendar, completion, keyboard/roving focus and selection across thoughts and tasks; titles clamp at three lines; the age shows only from 3 days old; a detected day shows as a pill, the lightest day only on hover; tags show under the title (`TagSignal`), then task subtasks as a plain toggle line (progress, next open one) over a tree (`SubtaskChip` + `InlineSubtaskPanel` from `tasks/InlineSubtasks.tsx`, open state persisted per task, all shared with `TaskCard` — never restyle them per row), where `stacked` rows (phone, board columns) also put the day pill; desktop sidebar `TagBubble`s drag onto a row (native `TAG_DRAG_TYPE`) to add that tag, clicks still filter. `CaptureGreeting` (one muted line: a day-part greeting template from `lib/constants/greetings.ts`, weather from `useWeather` only once ready, °F by the place's country, moon at night) sits above the inline field, the `capture-surface` hero (quiet at rest, focus ring on focus, lantern bloom only while writing; it takes focus once startup reveals the page, and its draft is kept per account in `sessionStorage` until saved): one line while empty, auto-growing as you type and on resize; the first character opens a `Reveal` row (the ⌘/Ctrl ↵ as-task hint, Capture button) that stays open, greeting faded, while focus stays, so repeated saves don't jolt the feed; a multi-line paste offers its split in the hint's place; leaving with a draft folds it to two dimmed lines with a soft `data-draft` glow (no ring), and a restored draft resumes with the caret at its end; coarse pointers get the greeting alone, aligned to the feed's section icons. Row styles, checkbox ring, `⋮` menu and section headers match Today/Upcoming; desktop has Rows/Board through `SortMenu` (view only); bulk selection is a floating bar; shortcut guidance lives below the feed. Enter saves in the inline field and Thought composer; coarse pointers use the orb with keyboard focus and repeated saves until Done (`Composer` `closeLabel`). Clarify persists title, List, Tags and dismissed NLP chips, laid out like `TaskEditor` Details with the shared `DetailPanelSections` rows (`DetailGroup`/`FieldRow`/`FieldBlock`, `ValueSelect`: `Select` on desktop, native on compact) and `TagField` (a chip click removes its tag; × on hover, always on touch); detected times survive placement. Process/complete has transactional unprocess Undo; kept/discarded status changes have Undo. Focus owns persistent Newest/Oldest/Priority ordering. Navigation uses ActivityBadge for indicators and PlainNavCount for Capture/List sidebar totals; `useRoutineDueCount` shares today-only pending routine totals across desktop and mobile, respecting the due-count setting.
- **Settings:** `?settings=` opens the desktop dialog or compact `SettingsSheet`; `menu` shows categories (Shortcuts hidden on phones) and sign-out, with Profile & Security inside Settings. Compact details replace the same history entry; swipe/close returns to the underlying route. `SettingsContent.tsx` shares tab content (deep-linkable tabs: About, Account, Appearance, Assistant, AI, DataPrivacy, DateTime, Integrations, Location, Notifications, Shortcuts, Tasks). Merged optimistically, cached locally. Notification fields are required (backend default seeds them; migration `0011` backfilled). Appearance owns the photo background: `settings.appearance.backgroundImage` is server-owned (upload/delete routes only), the file is fetched through authenticated RPC and cached in IndexedDB (`lib/themes/background-image-cache.ts`, cleared on sign-out), inactive image queries release their blobs; the provider-owned background keeps the active image and object URL alive across route changes, and choosing a mode or curated preset leaves photo mode without deleting the photo. Appearance orders mode, curated presets, accents, backgrounds, then intensity. Background has exclusive Cadence/photo choices; Cadence accents are disabled in photo mode, with automatic, sampled and custom photo accents below the image. `BackgroundSettings` owns file selection and mounts `PhotoCropDialog` for local preview, zoom and crop; only confirmation starts upload. Cache writes are serialized and guarded against same-tab sign-out/deletion. `settings.location` is owned by the Location tab and read everywhere through `useUserLocation` (weather, holidays); only an explicit user action may call `navigator.geolocation`, and location/weather queries carry `meta: { persist: false }`.
- **AI Assistant** (`components/assistant/`, `hooks/ai/`, `lib/ai/`, `stores/assistant-store.ts`): side-panel chat over `@ai-sdk/react`, streaming via `chat-transport.ts`. Tool results render as typed widget cards (`components/assistant/widgets/`) dispatched from `tool-registry.tsx`. Every write runs on the server; a write card (`ApprovalCard` shell: create/update tasks with note diffs, reminders, check-ins, hide-until and Fixed, copy and reorder, checklist edits, state, permanent delete, reschedule; capture structuring, changes and deletes in `CaptureCards`; list/tag/focus-view changes and deletes in `OrganizeCards`; list/tag create, section create/change/delete, routine create/change/log/delete, event create/change/delete) renders from `part.input` and, while the server waits (`approval-requested`, latest reply only), answers with `addToolApprovalResponse`; unticked rows send a decline naming them so the assistant re-proposes the rest. `useChat({ sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithApprovalResponses })` then sends only the answers (`chat-transport.ts` `approvalAnswers`) and the reply continues; workspace caches refresh as each write lands mid-stream (`refreshAfterWrites`, once per call; `onFinish` catches the rest). In dev each turn logs one `[cadence:ai-turn]` line (headers, ttft, first text, total, tool calls), the client half of the server's `ai_turn` line. Parts that didn't wait arrive done and render settled; an older reply's open request shows "Not answered". A new-task card shows every field it sets (time range, priority, effort, repeats, Fixed, list and section via shared `TaskDestination` queries, tags; the note clamped), and the words copied from a photo (`fromImage`) together under "From your image". Retired `propose_*` parts render read-only (`RetiredProposal`); writes the server no longer offers (`structure_inbox_item`) keep their old card through `RETIRED_WRITES`. Capture-to-inbox never waits and shows a quiet confirm chip. The composer's approval mode (`assistant-store` `approvalMode`: `ask` default · `auto` · `full`) is sent with every turn; the server decides from it which calls wait. Assistant markdown never renders images; `/…` and `?settings=<tab>` links navigate in-app (closing the sheet on phone/tablet), everything else (including `//…`) opens externally. The assistant's guide lives in `apps/backend/src/domains/ai/help/*.md`: a user-visible change that makes it wrong edits it in the same change. Turns render their parts in stream order (`buildSegments`); the assistant's icon is `AssistantSigil`. Composer photos (picker, paste, drop) are compressed on the device (`compressChatImage`: 1600px WebP ≤ 1MB, EXIF dropped; shared image decoding falls back to `<img>`, and PNG canvas output uses a lazy WebP encoder) and uploaded on attach to `POST /ai/images`; Send waits for them and the turn carries only `cadence-image:<id>` file parts (no filename). `ChatImages` shows them in the bubble through an authenticated fetch (a just-sent image is seeded into its query), or "Image expired". Bubble photos and unsent attachments open in the shared `components/shared/ImageViewer` (title/filename, size, ← → through the set). The per-message cap comes from `GET /ai/usage` (`images.perMessage`); the attach tooltip shows the count near the 20/day cap and blocks at it (`describeImageAllowance`). `AI_IMAGE_LIMITED`/`IMAGE_NOT_FOUND` offer "Send without images"; other failures on a photo turn offer "Share this image with the report". Conversations persist and resume. Composer slash commands (`lib/ai/slash-commands.ts`, `SlashCommandMenu`; typing `/` or the `/` button beside the photo button opens the menu; exact match only, anything else sends) run in the app: `/usage` opens `UsageOverlay` over the panel, `/clear` starts a new chat, `/history` opens Conversations, `/settings` opens Settings › Assistant via `useStepOutOfAssistant` (shared with in-chat links). `UsageMeters` (bars plus a live reset countdown and date, from `describeUsageMeters`, via `use-ai-usage.ts`) is shared by that overlay and the Usage section in Settings › Assistant. History rows archive in one click (⋯ keeps Rename and Delete); `ClearArchiveButton` (confirm, then `DELETE /ai/conversations/archived`) sits under Archived and in Settings › Assistant.
- **Shortcuts/search:** `Cmd/Ctrl+K` (command palette + universal fuzzy search over tasks/lists/routines/thoughts), `T` (quick-add), `Cmd/Ctrl+Shift+S` (manual sync), `G` chords for navigation. Don't add conflicting shortcuts casually.
- **Notification center** (`components/notifications/NotificationCenter.tsx`, responsive `NotificationsSheet.tsx` at `?notifications=true`): desktop bell shows up to three recent items in `NotificationPreview`, a matching-height centered empty state and an explicit expand button; the expanded dialog and direct compact sheet share search, All/Unread filters, global newest/oldest/priority sorting, incremental lists, read/unread checkmarks, a defer menu, dismissal and confirmed bulk clearing. Derivation is client-side (`reminder-engine.ts`, 60s scan in `use-notification-center.ts`, whose reads start after workspace reveal; routine reminders read today's range data and fire only while today's log is open); read/dismiss/defer state uses a module store backed by localStorage and best-effort notification-state API sync; account-keyed Query caches saved rows and shares presentation claims across surfaces after hydration. `use-browser-notifications.ts` fires native notifications when permitted.
- **Quick add:** `QuickAddSurface.tsx`, one `Composer` switching the task, capture and routine composer hooks (drafts kept per tab), triggered by `T`, the sidebar or the phone orb; navigates + `useRouteFocus()` on submit.

## 9. Component Patterns

- `app/components/primitives/`: `AlertDialog`, `Button`, `Collapsible`, `ContextMenu`, `Dialog`, `DropdownMenu`, `Input`, `Popover`, `ScrollArea`, `SegmentedControl` (header view switchers, the compact board column chooser in `shared/BoardCanvas`, short choices: `size`, per-option `tone`), `Select`, `Separator`, `Skeleton`, `Switch`, `TimePicker`, `Tooltip`. Check here before styling a new Radix wrapper. Every date field is `shared/DatePicker` (built on `MonthCalendar`, which the task schedule surface also uses) and every time field is `TimePicker`: both use the native picker on a coarse pointer and a custom popover otherwise. Never render a raw `<input type="date|time">`. `Dialog` and `AlertDialog` share `primitives/dialog-styles.ts` (themed `surface-dialog` glass, layout, header/footer/title type) and use `Button` size `md` for actions; consumers set size, layout and padding only, never their own background, border or shadow, and use `DialogCloseButton` when a header needs an inline close. `ContextMenu`, `DropdownMenu`, `Popover` and `Tooltip` share `primitives/menu-styles.ts` (floating surface, motion, menu rows, `GenericMenu`). Primitives import `cn` from `lib/utils`.
- Reuse primitives through composition; remove duplicate controls, layouts and animations. One home per helper: date formatting, calendar grids, month/weekday names and `TimePicker` values in `lib/utils/date-format.ts`, formatting only via `formatInZone` (days are LocalDates from the API, instants are converted with `@cadence/domain/time` in `useUserZone()`, today is `useToday()`; never `Date` local getters, slicing or `toISOString()` for a day); motion (`EASE_OUT_EXPO`, `slideVariants`) in `lib/constants/motion.ts`, and `shared/Reveal` for every expand/collapse (never a bare conditional render); a collapsed `BoardCanvas` column is one rail button (`onExpand`); module stores via `lib/utils/external-store.ts`; `useOnlineStatus`, `useIsCoarsePointer` and `useReducedMotionSetting` (the Motion setting, else the OS) in `hooks/`. Routes stay thin; domain components own rendering. `MainLayout.tsx` owns the shared shell and active-panel close control; every page header (including Schedule and Routines, which hide the shell header) uses `layout/PageHeader.tsx`: shell-header height, `surface-shell` (shared with right-rail panels), icon + eyebrow + title + optional meta, and period pages navigate with `layout/PeriodNav` (‹ Today ›, Today greyed out on the current period); on phone every header, the shell's included, is `PhonePageHeader` (no icon, 22px display title, controls in `.header-glass` capsules, the same glass `app.css` gives every labelled icon-only button on phone (icon+text buttons carry a `gap-*` class); Schedule and Routines put their view choice in `PhoneViewPicker` under its sliders icon) and `PeriodTodayPill` floats Today bottom left while off the current period; optional dialogs, search, bulk actions and note room defer mounting until needed, preserving exit motion with `DeferredMount`. The assistant is code-split and never part of startup (plain `Suspense` with its glass shell, even when persisted open); other visible lazy content uses `StartupSuspense` so startup includes its requests.

## 10. Auth

Neon Auth via `authClient` (`app/lib/auth-client.ts`, 20-second SDK deadline), account-validated session JWT seeding (`lib/api/client.ts`), and lazy `AuthUIBoundary` + `AuthView` on auth routes; workspace controls use `useAuthState`. Pages outside the workspace (sign-in/up, auth callbacks, consent, route and root error boundaries) share `shared/CardPage` (stars, glass card with the diagonal sheen, logo, optional title/description/actions); third-party UI themed via `.neon-auth-wrapper` in `app.css`. Web callbacks restore through `useAuthState` with serial retries for up to 15 seconds; only a resolved session permits workspace navigation, except status `offline`: when the session can't be checked for lack of a connection, the last signed-in identity (`lib/auth/offline-identity.ts`, no tokens) opens its cached workspace until the connection returns. Warm starts do the same while the session is checked (status `provisional`, workspace paths only): API calls and WAL replay wait in `client.ts` (`holdForSession`) and writes queue; an anonymous answer goes to sign-in, another account remounts and aborts the held calls. Auth UI session changes invalidate queries; account identity changes remount the isolated cache. Do not introduce a parallel auth stack. Legal acceptance: sign-up (`routes/auth.tsx`) gates the whole form behind two ticks (16+, Terms and Privacy Policy; `shared/ConsentCheck`), and `layout/MainLayout` mounts `legal/LegalConsentGate`, a blocking panel for any signed-in account whose `privacy.legalVersion` isn't `LEGAL_VERSION` (`@cadence/contracts/settings`; bump it to ask everyone again, and match the `updated` date of the landing policies). It covers new Google/GitHub accounts made from sign-in and accounts from before the step, and records quietly when the sign-up ticks were just made (`lib/legal-consent.ts`). Client-side only: the API doesn't refuse an account that hasn't accepted. `routes/connect.tsx` is the consent page for outside assistants (MCP): signed-out visitors go to sign-in with `redirectTo` back to it; approving or declining (`hooks/core/use-connections.ts`) returns a URL on the MCP origin that the page opens with `location.assign` (that origin checks the cookie this browser got when the assistant started; never navigate there any other way). Settings › Integrations lists them (`settings/ConnectedAssistants.tsx`, Disconnect behind a confirm); scope wording lives in `lib/constants/mcp.ts`. Calendar/notes sync controls below it stay disabled Coming Soon. Managed Neon Auth pins its client plugins (JWT, admin, organization, email OTP, magic link, phone number); anything else (2FA, passkeys) isn't callable, so don't build UI for it. Settings › Active Devices lists sessions only within a day of sign-in (Better Auth `freshAge`; `/list-sessions` returns 403 after), then offers `revokeOtherSessions`.

Browser E2E (agents, Playwright): sign in at `/auth/sign-in` with `E2E_EMAIL`/`E2E_PASSWORD` from `apps/frontend/.env` (git-ignored), a password user on the dev Neon branch only. Missing after a branch reset? `POST {VITE_NEON_AUTH_URL}/sign-up/email` with `Origin: http://localhost:8788` and `{email,password,name}` recreates it, then set `neon_auth."user"."emailVerified"=true` for it (dev DB, `MANAGEMENT_DATABASE_URL`) and add its id to `ADMIN_USER_IDS` in `apps/backend/.dev.vars` (admin tools + `POST /debug/seed`). Use a fresh browser context so a real session isn't signed out.

## 11. Web vs. Desktop Boundary (`app/platform/`)

`runtime.ts` (web/desktop switch plus the only Tauri-window and storage checks: `hasDesktopWindow`, `getDesktopStore`, `getWebStorage`), `desktop.ts` (Tauri implementation), `desktop-shell.ts`, `desktop-auth-handoff.ts` + `lib/desktop-auth-session.ts` (native OAuth/deep-link handoff), `desktop-keyring.ts` (OS credential storage vs. browser storage), `patch-desktop-fetch.ts` (native HTTP transport), `desktop-update-state.ts` (updater), `desktop-e2e.ts`, `web.ts` (browser counterpart). `routes/desktop.quick-capture.tsx` + `hooks/ui/use-desktop-layout-scale.ts` / `use-desktop-command-preferences.ts` back the native quick-capture window and OS menu commands (see [`apps/desktop/AGENTS.md`](../desktop/AGENTS.md)). New platform-divergent behavior belongs behind this boundary — never an inline `if (Tauri)` scattered in domain components.

## 13. Anti-Patterns

Hardcoded hex in components · raw `@radix-ui/*` in domain components · raw `fetch` for backend calls · spinner-only flows replacing optimistic ones · duplicated query keys · reusable hooks outside `app/hooks/` · giant route components with business logic · generic SaaS panels/tables breaking the atmosphere · unnecessary full-list renumbering · breaking auth/session invalidation · conflicting keyboard shortcuts · inline platform checks outside `app/platform/` · raw `console.*` outside `lib/log.ts` and `worker.ts` · `toast.error(err.message)`.

## 14. Checklist

Identify the owning domain folder → ease check (root AGENTS.md: fewer decisions, less to scan, nothing twice, no capability lost) → keep routes thin → reuse/extend a primitive before styling a new one → semantic tokens from `app.css` → Hono RPC + TanStack Query for server state → optimistic updates for visible mutations → preserve focus/pointer/a11y semantics and Twilight Sanctuary tone → typecheck.

If this document conflicts with a proposed change, this document is the baseline.
