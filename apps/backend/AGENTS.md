# Cadence Backend — Agent Instructions

Standalone Cloudflare Worker API (Hono v4 + Neon Postgres via Hyperdrive). Shared backend for web, desktop, and future mobile clients — must stay platform-neutral (no cookies/sessions), edge-safe (no Node-only APIs, no long-lived connections), schema-driven (Drizzle is truth), and parity-first (every endpoint usable by every client identically). Breaking a route contract breaks every client at once.

**Canonical shapes live upstream, not here.** [`@cadence/contracts`](../../packages/contracts) (Zod → inferred types) owns every request/response/entity shape. [`@cadence/domain`](../../packages/domain) owns pure business logic (throws `DomainError`, mapped to `AppError`). Read `packages/AGENTS.md` before touching either. No domain has a schema file: routes and services import every schema from its contract (filters and their `superRefine` included). **Never hand-write a type that mirrors a contract** — derive via `z.infer`/`.pick`/`.extend`.

## 1. Tech Stack

| Concern | Technology |
|---|---|

| HTTP | Hono v4 |

| DB | Neon Postgres via Cloudflare Hyperdrive |
| Auth | Neon Auth JWTs, verified via `jose` against JWKS |
| AI | Vercel AI SDK (`ai` v7); `@openrouter/ai-sdk-provider` for chat, titles and embeddings, plain HTTPS to OpenRouter's Decisions API for `domains/decisions`; Upstash Redis (`@upstash/redis/cloudflare`) for stream resumption |
| Scheduling | One hourly cron trigger, a `ReminderClock` Durable Object per person (reminders), Queues with delays (memory's per-person work) |
| Recurrence | Shared day-based validation/expansion in `@cadence/domain/time`; pnpm-patched `rrule` bounds sparse searches, streaks expand history once |

Zod v4 gotchas: no `.deepPartial()` (custom recursive version in `@cadence/contracts/settings`); introspect via `schema._zod.def.type`; `.unwrap()` for optional/nullable, `.element` for arrays.

## 2. Architecture

```text
src/
├── index.ts          # Worker entry, middleware chain, route mounting, AppType export
├── platform/         # Cross-cutting infra ONLY — no domain logic
│   ├── auth.ts       # Bearer JWT middleware + async user sync
│   ├── db.ts         # getDbClient(c.env) — per-request client
│   ├── rls.ts        # setRlsContext, withRls
│   ├── errors.ts     # AppError (code: contract `ErrorCode`, optional `issues`), sameVersion, createErrorBody (→ `ApiError`), throwIfNotFound, formatErrorResponse
│   ├── validation.ts # apiValidator() wrapper
│   ├── idempotency.ts, ownership.ts, metrics.ts, log.ts, request-log.ts, redis.ts, user-zone.ts, zone-mirror.ts
├── domains/           # tasks, habits, inbox, projects, tags, subtasks, sections, settings, notes, events,
│                       # push, health, proxy, account, ai, decisions, mcp, debug — one folder each
├── db/schema.ts       # Drizzle schema (SOURCE OF TRUTH): re-exports schema/{core,ai,ops}.ts; schema/columns.ts holds timestamptz + RLS helpers
├── cron/overdue-check.ts   # the gated hourly run; reminders fire from domains/push/reminder-clock.ts
└── types/             # env.ts (Env bindings), db.ts (DbClient/Tx aliases), text-modules.d.ts (.md imports)
```

**Key Principles**
| Rule |
|---|
| Each domain folder owns its routes + domain-specific utilities. |
| `platform/` = shared behavior only. `types/` = shared *declarations* only (no behavior), reused by 2+ places. A type used once stays local. |
| A route handler validates → authorizes → delegates → shapes response. Non-trivial logic goes in a named helper or `{domain}.service.ts`. Another domain imports only that service (or a `PUBLIC` module in `scripts/check-domains.mjs`, run by `lint`). |
| No `helpers.ts`/`utils.ts`/`misc.ts` catch-alls anywhere. |
| Router MUST be method-chained (`new Hono().get().post()`) and mounted via `.route(...)` on the chained `apiApp` in `index.ts` — a non-chained router silently vanishes from `AppType`. |

**UCURD (non-negotiable, mechanical, not aesthetic):** every route/DB-touching file is ordered **U**tility → **C**reate → **U**pdate → **R**ead → **D**elete, by HTTP verb (`POST`=Create even for action routes like `/:id/reschedule`, `PATCH/PUT`=Update, `GET`=Read, `DELETE`=Delete). Utility helpers/type aliases sit at the top. Multi-resource files keep primary-resource-before-sub-resource within each verb group. A UCURD violation is a defect even if it works.

## 3. Adding Code

- **New feature in existing domain:** contract in `@cadence/contracts/{domain}` → route handler → Drizzle schema + matching `xRowSchema` if persistence changed → tests in `tests/unit/` or `tests/integration/`.
- **New domain:** author contract (`packages/contracts/src/{domain}.ts` + sub-path export) → `{domain}.route.ts` importing shapes directly from `@cadence/contracts/{domain}` (chained router) → mount in `src/index.ts` on the chained `apiApp` → Row-parity line in `tests/unit/contract-parity.test.ts` + schema tests in `packages/tests/contracts` + `tests/integration/{domain}.test.ts`. Read routes return the contract entity (narrow loose columns in one mapper, like `toTask`), and each gets a line in the frontend's `rpc-parity.test.ts`.
- **Platform infra:** only genuinely cross-cutting code (auth, db, rls, errors, logging, validation, idempotency, ownership, metrics, redis).

## 4. Request Lifecycle

`createRequestContext` (request ID) → `secureHeaders()` → body size limit (100KB, `/api/v1/*`; the two photo uploads, background and chat image, are exempt and capped on their own routes) → CORS allowlist (desktop; the web app arrives same-origin through the frontend Worker's `BACKEND` service binding, headers untouched) → debug-route guard (404 in production, or unless `ENABLE_DEBUG_ROUTES=true`) → Tier-1 IP rate limit (pre-auth) → JWT auth (`userId` attached) → Tier-2 user rate limit (read/write) → Tier-3 admin rate limit (`/api/v1/debug/*`) → `apiValidator()` → handler: `getDbClient(c.env)` → `withRls(db, userId, fn)` → `{ data: ... }`.

The MCP origin is a separate boundary, dispatched in the Worker's `fetch` before the Hono app (`isMcpRequest`: the `MCP_ORIGIN` host and `/mcp`, `/authorize`, `/oauth/*`, `/.well-known/oauth-*`): Tier-1 IP limit (plus per-IP `RATE_LIMITER_WRITE` on `/oauth/register`, `RATE_LIMITER_ADMIN` on `/authorize`; `/favicon.ico` redirects to the app's) → `@cloudflare/workers-oauth-provider` (discovery, DCR/CIMD, token, revocation, bearer check on `/mcp`) → `serveMcp`. No app JWT, CORS or `{ data }` envelope there.

Uncaught errors → `formatErrorResponse()`: extracts `AppError` code/message, attaches request ID, never leaks stack traces/SQL.

## 5. Database Rules

- **Timestamps:** every `timestamp with time zone` column is declared with the `timestamptz()` helper in `db/schema/columns.ts`, which reads values as strict ISO (`2026-03-09T12:00:00.000Z`). Never use drizzle's `timestamp()` directly, or that column goes out as Postgres text. Integration tests fail on any non-ISO date-time in a response.
- **Per-request clients only.** `const db = getDbClient(c.env)`. Never a module-scope singleton — Hyperdrive pools connections, Workers don't hold them.
- **RLS is mandatory** for user-scoped work: `withRls(db, userId, async (tx) => { ... })`. Sets `request.jwt.claims` on the same connection as the queries; traces awaited transaction/context/work spans (async callbacks adopt Drizzle thenables) plus begin/commit timings, never SQL or identity. Policies compare against `rlsUserId` in `db/schema/columns.ts` (a `(select …)` Postgres evaluates once per query, not per row); never inline `current_setting` in a policy.
- **Type aliases:** import `DbClient`/`Tx` from `src/types/db.ts` — never redefine `Parameters<Parameters<DbClient["transaction"]>[0]>[0]` inline.
- **Ownership:** `assertProjectOwnership`/`assertSectionOwnership`/`assertTagsOwnership`/`assertOwnership` in `platform/ownership.ts`. Another user's row is invisible under RLS (404); 403 only fires if RLS is bypassed. Task updates use an atomic version condition for simple edits; schedule, recurrence and placement edits lock/read first. Moving lists without a section clears the old section; explicit sections must belong to the effective list.
- **Migrations:** update the schema → `pnpm db:generate` → `pnpm db:check` → `pnpm db:migrate` (dev) → `pnpm db:migrate:prod` before pushing. Never `drizzle-kit push`. `drizzle.config.ts` reads `.dev.vars` (`DB_TARGET=prod` picks `PROD_MANAGEMENT_DATABASE_URL`); migrations output to `apps/backend/drizzle/`. Everything lives in the schema files (checks included) so drizzle's snapshot matches the database; hand-written SQL only for data or what drizzle can't express (extensions, grants). `0000_baseline` builds the whole schema (existing databases skip it: the migrator only applies entries newer than the last one recorded). A new database needs the `api_worker` login role (the Worker's Hyperdrive user) created first; then `pnpm db:migrate` builds everything, grants included.

## 6. API Conventions

- All app routes under `/api/v1/`. Auth is always `Authorization: Bearer <JWT>` — never cookies/sessions. The one exception is the MCP origin (§9b): OAuth/MCP standards fix its paths, and its short-lived `__Host-` cookies only bind a consent flow to one browser.
- Success envelope: `{ "data": {...} }` everywhere, including health/debug. Errors: the contract `ApiError` (`{ "error": { code, message, status, isRetryable, requestId, issues? } }`) via `AppError`; codes come from `ERROR_CODES` in `@cadence/contracts/common`. Task responses always carry `tagIds` (`toTask`/`withTagIds` in `tasks.service.ts`).
- **Idempotency:** `Idempotency-Key` header — `getIdempotencyKey(c)` → `checkIdempotency(tx, userId, key)` (no-op if undefined; holds a transaction lock on the key so a concurrent retry waits, then sees the record) → mutate → `recordMutation(tx, userId, key)`. Supported on all POST endpoints in tasks/habits/inbox/projects/tags/subtasks/sections. Creates there also take an optional client-chosen `id` (clients send it as the key too, so offline replays are safe): insert through `insertWithClientId`, which turns an id another account holds into 409. Update schemas omit `id`.
- Read-heavy routes: `Cache-Control: private, max-age=0, stale-while-revalidate=5`. App responses expose `Server-Timing: app;dur=…`; `http.response` traces the same middleware/handler duration, excluding post-response `waitUntil` work included in invocation wall time. Auth and task writes/tags/background metrics have separate spans.

## 8. Domain Model

`tasks.linked_app_id` and `habits.linked_app_id` hold the one app a task or routine opens (a known id from `@cadence/contracts/app-link`, never a URL; null removes, omitted keeps); `linked_url` holds a typed website instead (`linkedUrlSchema`; a CHECK keeps it `https://`, ≤2048); the task copy carries both, and no assistant/MCP tool writes it. Task writes carrying `nlp.resolved` (create, inbox process) are stored as sent: the server never re-infers them (older clients without it keep the inference path). `tasks.effort_origin`/`effort_chosen_at` record who chose an Effort (`effortProvenance`; any write that changes `effort` without an origin clears it, so assistant/import/copy values never count); `GET /tasks/effort-evidence` returns only the account's own recorded choices outside Trash and repeating series. Effort set before provenance existed counts only on tasks with an NLP record (app composers), as `accepted` (migration 0008). Inbox process stores `reminderAt`/`notBefore` and a multi-day `endDate`, and a `waitingOn` makes the task WAITING.

`src/db/schema.ts` (and the `schema/` files it re-exports) is truth: **32 tables**, **17 pgEnums**. Groups: identity (`users`, `userMetrics`) · tasks ecosystem (`projects`, `taskSections`, `tasks`, `subtasks`, `tags`, `taskTags`, `taskMetrics`, `taskNotes`, `taskNlpMetadata`) · inbox (`inboxItems`, `inboxSections`) · habits (`habits`, `habitLogs`, `habitTags`) · intelligence (`aiMemories`, `aiMemorySignals`, `durationReports`, `planningRecords`, `aiMemoryNotes`, `usageEvents`, `savedFocusViews`, `notificationState`, `devices`, `pushDeliveries`) · AI assistant (`aiConversations`, `aiMessages`, `aiImages`) · connected assistants (`mcpConnections`) · infra (`mutationDedup`, `dataExports`).

**Account deletion** (`domains/account`): `POST /account/delete` (body carries `ACCOUNT_DELETE_PHRASE` plus a `password` or emailed sign-in `otp`, checked server-side against Neon Auth by `verifyPresence`, so a stolen JWT alone can't delete) erases R2 files, MCP grants, the `users` row (everything cascades), then the Neon Auth identity through the Neon API. The identity goes last so a failure leaves a signed-in user who can retry. Needs secrets `NEON_API_KEY` (project-scoped), `NEON_PROJECT_ID`, `NEON_BRANCH_ID`; without them it answers 503 before touching anything.

**Data export** (`domains/account/data-export.service.ts`): `POST /account/export` inserts a `data_exports` row (the record: email sent to, status `pending`/`sent`/`failed`, bytes, times; erased with the account), answers 202, and builds + sends in `waitUntil`. `buildExport` walks every table in `schema.ts` scoped to the user (`mutation_dedup` and embedding vectors skipped; `task_tags` through its task), so a new table is exported without edits. The file goes out as a JSON attachment through the `EMAIL` (`send_email`) binding from `noreply@mail.cadenceapp.cloud`, to the JWT's email; over 20 MB it fails (25 MiB email cap). Without `EMAIL` the route answers 503 `DATA_EXPORT_UNAVAILABLE`. Photos in R2 aren't included. Sends from the onboarded `mail.cadenceapp.cloud`.

**Settings:** the contract's `userSettingsSchema` types the `users.settings` column; reads return `normalizeSettings` → `SettingsView` (stored over defaults). `settings.appearance.backgroundImage` is server-owned: `sanitizeBackgroundPatch` (`domains/settings/background-image.ts`) lets a PATCH change only accent/blur/brightness, never the photo's identity or existence. Notification fields (`browser`, `taskReminders`, `habitReminders`, `dueDateAlerts`) are required. `settings.assistant`: `persona` is the one voice setting (it picks `prompts/assistant/voice/<persona>.md`); `tone` and `verbosity` stay for back-compat but never reach the prompt; the rest (names, emoji, proactiveSuggestions, adaptiveTone) render into the prompt's Environment. Free-text fields (names, customInstructions) are sanitized + fenced before composition — never trust them raw in a prompt.

## 9. AI Domain (`src/domains/ai`)

- `ai.route.ts` — `POST /chat` streams a turn via `createAgentUIStream`/`createUIMessageStream` (AI SDK v7), persists messages, supports resumable streams and `stopStream`. A request carries a new user message or `approvals`: answers are applied to the stored last reply (`applyApprovals`, never a client copy), the SDK runs what was approved, and the same reply continues. Replayed history turns open calls into declined ones (`settleUnanswered`). Settings/metrics overlap turn persistence; ordinary history loads once. Validated continuations skip snapshot/recall construction; new turns prepare while history commits. Images overlap resume initialization, which finishes before the transaction publishes its pointer; initialization failure streams without resumption. Each turn logs one `ai_turn` info line from `onEnd` (model, outcome, steps, tool calls, tokens incl. cache reads/writes, `costUsd`, `servedModel`, timings counted from the request's arrival, plus bounded content-free `run-diagnostics.ts` records with a unique run id, root release, preparation spans, SDK-visible model attempts and tool durations; unknown usage/cost stays null); `ai_title`, `ai_embedding`, `ai_memory_extract` and `ai_memory_match` log their own lines with the same fields; every OpenRouter call sends `user` = the hashed user id. `costUsd` (summed per step by `addStepSpend`) and `servedModel` are saved on the assistant row's metadata, never streamed, with `metadata.titleSpend` alongside, Admin sums `costUsd` + `titleSpend` over rows; continued replies overwrite that metadata, so this is not cumulative billing (memory's own calls are logged, not stored per row). Run diagnostics are log-only, subject to log sampling, and are not a durable ledger. Conversation CRUD (`GET/PATCH/DELETE /conversations[/:id]`; the patch also takes `learn`, memory's per-chat switch); `DELETE /conversations/archived` (images from storage first) is registered before `/:id`.
- `agent.ts` — model/agent construction (`getAgentInstance`; fixed `REASONING_EFFORT`, since a change invalidates the cache; no temperature override). `model-router.ts` (a leaf module: no agent imports) owns both model ids: `pickChatModel` uses `AI_CHAT_MODEL_BASIC` only for a short, single-line, image-free message matching a `BASIC_INTENT` (small talk or how-to; never the user's data) with no `COMPLEX_CUE`, and only while the thread (`ai_conversations.model`) has used nothing else; otherwise `AI_CHAT_MODEL`. Anything unrecognised stays standard, a thread never drops back (each model has its own prompt cache), and a failing basic model falls over to standard. `chatModelSettings` pins each provider route (`provider.order`: Anthropic for `anthropic/*`, else DeepInfra; fallbacks on), never `:nitro` (it hops providers and their caches). Claude caches only behind explicit breakpoints, so it gets OpenRouter's top-level automatic `cache_control` plus one on the system prompt (`chatInstructions`; tools render first, so tools + system cache together); other models cache implicitly (`tests/unit/ai-prompt-cache.test.ts` checks the wire body). `DEFAULT_CACHE_VARIANT` keeps production at 5m static/5m tail; 1h variants are internal evaluation options only. Each assistant message's metadata gets `promptHash` (prompt blocks + help files + tool names/descriptions/schemas). Writes execute on the server; `toolApproval` (`safety/approval.ts` `approvalFor`) decides which wait for a tap: Ask every write, Auto only `needsTap` (any `delete_*`, removing subtasks, whole-note rewrites, more than 5 tasks or captures), Full none; reads, `capture_to_inbox` and `ask_user` never. `ask_user` (`tools/ask.ts`, 2–4 options) ends the turn (`stopWhen` `hasToolCall`); the reply arrives as the next message. Approvals are HMAC-signed with `TOOL_APPROVAL_SECRET`, so an edited or forged one fails closed. History passes through `dropUnsignedReasoning` then `dropForeignReasoning` (`persistence/message-mapper.ts`) so unsigned reasoning never reaches the provider and a model switch never replays the previous model's thought signatures. `tools/said.ts` checks chat drafts: priority and effort need a `said` quote found in `ctx.userTexts` (this message + last 2), else they are dropped into `ignored`; a quoted effort is stored `manual`; MCP (no `userTexts`) skips the check. `decisions/decision.ts` `decide` asks named `choice`/`score` questions in one call (per-kind thresholds; `decideChoice` wraps it); `decisions/effort-guess.ts` stores a model Effort guess in `tasks.effort_guess*` (cleared in `guessAfterWrite` when effort, title or list changes); `memory/task-hints.ts` adds `effortGuess` to assistant reads.
- **Decisions (`src/domains/decisions`):** a decision model returns probabilities over options the app supplies, never text, so it can only pick the user's own ids. `decision.ts` is the one adapter (`decideChoice`: a single `choice` question to OpenRouter `/api/alpha/decisions`, opaque option keys plus `none`, no fallback providers; never throws; at most `DAILY_DECISIONS` (200) a person a day across kinds (`platform/daily-budget.ts`, Upstash, fails closed on an error: no suggestion, no model call); one `ai_decision` log line per call with kind, model, `servedModel`, tokens, `costUsd`, ms and outcome, never any text). `AI_DECISION_MODEL` (a dated decision-model ID, in `wrangler.jsonc`) is the only switch; unset or empty turns model decisions off. A shown choice needs the top probability ≥ the model's entry in `DECISION_THRESHOLDS` (from the evaluation; a model with none uses 0.9). Every call also reads `settings.tasks.intelligence.smartPlacement` (`!== false`) first, and no transaction is open across the model call. S1 (`placement.ts`): a saved capture (`POST /inbox`, MCP/assistant `capture_to_inbox`) schedules `suggestPlacement` in `waitUntil`; it picks one of the user's list or list › section pairs and merges `{ projectId, sectionId, model, probability, costUsd, ms }` into `analysis.suggestedPlacement` only if the pair still exists. S2 (`did-you-mean.ts`): `POST /search/did-you-mean` and an empty `get_tasks` query (`possibleMatch`) verify scoped spelling candidates through `@cadence/search`, then offer up to 255 model options ranked by `pg_trgm` `word_similarity` (migration 0018) and recency; both surfaces preserve numeric identifiers, and assistant suggestions preserve every filter. `GET /search/task-notes` supplies compact canonical note tokens and headings to the palette. A section sent to `/inbox/:id/process` must belong to the chosen list or the call fails 400.
- **Memory (`domains/ai/memory`):** `users.settings.assistant.memoryMode` (`off|basic|full`; null = not chosen yet, which behaves as Basic: `memoryStateOf` resolves it everywhere and only the page reports `null`) with `memoryChoiceAt`, `memoryEpoch`, `memoryLearningNotBefore` (Clear, and the release that made Basic the default, set it: nothing said before it is read back, by chats, notes or the catch-up) and `memoryBackfill` are server-owned: only `POST /ai/memory/mode` (and the jobs) write them, the settings PATCH rejects them with 400, and every mode change bumps `memoryEpoch`, which fences each background write in the writing transaction. Facts live in `ai_memories`: `halfvec(512)` embedding (exact scan per person, no ANN index), a generated `search` tsvector, and `content_hash` (unique among active rows, so `insertFact` inserts ON CONFLICT DO NOTHING and reinforces the winner; a forgotten row keeps it as its tombstone). What a turn may read is one predicate, `usableBy(userId, mode)` (`memory-store.ts`, also used by `loadContextFacts`/stored-context validation): Full reads every active fact, Basic only `explicit`/`chat` facts outside `FULL_ONLY_KINDS`; what Full learned stays stored, unused until the person returns to Full. A turn gets the **profile** (`loadProfile`: pinned · preferences, quirks, constraints · life facts due within 30 days, then life and what-helped facts while the 2,000-character budget lasts; never patterns or durations) and **recall** (`recallFacts`: full-text OR + cosine fused with RRF k=60 from the last two user messages; skipped for a bare short command). `loadProfileCoverage` establishes exact eligible-fact coverage in one RLS statement: fully covered profiles skip embedding/recall by default; candidates retain hybrid recall and lexical fallback, with no transaction held during HTTP. Both ride in `turnContext` as `(said <Month Year>) [id] text`, fenced as data. When memory is on the agent also has `remember`, `recall` and `search_past_chats` (`isMemoryTool`; MCP publishes them under the same gate; `search_past_chats` reads `ai_messages.search_text`, the person's own words, full-text only, never embedded). `remember` saves, updates or forgets at once and returns a receipt (saves/updates stop at 50 a person a day before any model call; there is no size cap, growth is bounded by that and the daily extractions; a save within `FORGOTTEN_DISTANCE` (0.15 cosine) of a forgotten fact of the same kind comes back `kept` with "You asked me to forget this"; `when` and `avoid` store a stated time of day or a help that doesn't work); the chat shows Undo, so it never waits for approval. **Learning** (`learn.ts`; started by events as delayed queue messages, §13; `runMemoryJob` is the daily backstop, work list from `memory_user_ids`): a chat idle 10 minutes is read from `metadata.memoryCursor` (user messages only, ≤ 6k tokens), `prompts/memory/extract.md` proposes ≤ 8 candidates as schema-constrained output (`Output.object`; `AI_CHAT_MODEL` must list `structured_outputs` on OpenRouter), `candidates.ts` drops flagged, unsourced, instruction-shaped, duration and activity-only ones (how long things took comes only from answers on a completion), `consolidate.ts` (the chat model over opaque keys, one call per reading; not the decision model, which abstains on changed values) names the known fact each repeats or updates, and one transaction writes the facts if `memoryEpoch` still matches (`fenceMemoryState`: the user row FOR SHARE, so a mode change waits) and the cursor is still where the reading began (it moves first, so overlapping runs write a reading once; the cursor keeps microseconds). Without `MEMORY_QUEUE` nothing is delayed and the daily backstop takes 10 random people a run. `metadata.learn = false` skips a chat; at most 15 extractions a person a day, counted only when there is something new to read (`admit` → `withinDailyCap`, Upstash; no Redis means no cap; a capped chat stays unread for tomorrow). Forget keeps the text `UNDO_WINDOW_MINUTES` (10) for Undo, then a delayed `scrub` message reduces it to a topic label and keeps its embedding, so a paraphrase is dropped at learning and at `remember` (`isForgotten`). Deleting a chat, or switching it to "Don't learn", deletes the facts only it taught (`seenCount = 1`; others lose the link, `dropChatFacts`); the nightly pass drops note and catch-up facts whose note or chat is gone (`dropOrphanedFacts`). **Full** adds: `ai_memory_signals` (written only from routes: `trackTaskChanges(…, { env })` with a reschedule's `task_id`, the habit resolve route; never by the assistant, MCP or imports; at most 150 a person a day, kept 90 days, dropped on Clear; a mode change never erases anything, it only starts or stops learning), `note-learn.ts` (changed lines only; line hashes in `ai_memory_notes`, the note is never copied), `backfill.ts` (90 days newest first, ≤ 4 batches a night, skips what the live job covers; `memoryBackfill` keeps `learned`, `doneAt` and `failedNights`: a broken batch stops the night (`LearnResult.failed`), 3 such nights in a row log `memory_backfill_stuck` as an error, finishing logs `ai_memory_backfill_done`), and the nightly pass (`nightly.ts`, local 03:00 via `runMemoryNightly`: expiry, 60-day decay of unreinforced facts the person never said (activity ones excepted), merges (no size cap), patterns and durations from `signals.ts`, and "when you plan" patterns from `planning_records` (Full), each hashed by a count-free `key` so a forgotten one stays forgotten as its numbers move: ≥ 5 events on ≥ 3 days in 28 with ≥ 70% in one bucket; a duration fact exists only when `estimateDuration` (`@cadence/nlp/duration`, the same function the app runs) is `supported` for the `group_key` of the answers: `durationGroup`, the first 3 meaningful words of a one-off title, or `series:<id>` for a repeating task). **"How long did it take?"** (`duration.ts`, policy in `@cadence/domain/duration-ask`): answers live in `duration_reports`, one per `(task_id, completed_at)` or, for a routine marked done, per `(habit_id, target_date, wall_time)` (`POST|GET|DELETE /ai/memory/duration/routine`; 409 unless that day or time is marked done; `resolveHabit` deletes the answers of an occurrence no longer done; the estimator and `GET /duration-evidence` see a routine as a repeating thing filed under its id), outside the signals' 90-day prune (kept until the task, the fact (Forget hides the group's answers, Undo restores them, the scrub deletes them after `UNDO_WINDOW_MINUTES`), Clear or the account goes). `tasks.completed_at` is the instant a task entered Done, kept by the `tasks_completed_at` trigger on every write path (set on COMPLETE, kept while Done, cleared on leaving, where it also deletes that completion's report) and checked by `tasks_completed_at_check`; it has millisecond precision so a client can name it. `POST /duration/ask` decides (Full, task Done, group not settled, not completed within 2 minutes of creation, budget open: one ask a day per person in `settings.assistant.durationAsk`, every 3 days after 3 unanswered, weekly after 6, monthly after 10) and, when it says yes, reserves the day under the user-row lock with a fresh `token` and returns `completedAt` and the person's own plan as `reference`; `POST /duration/shown` counts one miss per token; `POST /duration` stores the answer in its own transaction and returns the stored row (409 when `completedAt` no longer names the task's completion; 200 `null` and nothing stored outside Full; an answer carrying the question's token resets the misses; 200 a day per person, then 429). `GET /duration-evidence` is the estimator's input (Full only, last 365 days, ≤ 1,000). **How they plan** (`planning.service.ts`, Full, rules in `@cadence/domain/{find-time,slot-preference,planning-offers}`): `planning_records` (90 days, nightly prune; Forget on a "when you plan" pattern hides its rows, Undo restores, the scrub deletes them and the fact with no tombstone, so new choices can teach it again) are written from routes only, as `recordSlot` after `PATCH /tasks/:id`: a manual drop of an untimed task onto a time (`X-Queued-At` older than an hour: ignored), or a Find-a-time pick with `findTime.shown` (a pick among at least two parts of the day, replacing that task's pick for the day; `undo` deletes it; the first proposal kept, Later today and the receipt time write nothing), each only when another part of the day also had room; `POST /ai/memory/planning/offer` records Not now (declined) or the offered action (chosen) with a fingerprint of the task's title, open steps and `waitingOn`. `GET /ai/memory/planning-evidence` hands the device its records and the stated `when` preferences (any memory-on mode) to run the same pure rule; `GET /ai/memory/planning/offers` lists the tasks each offer may show on after the decline, 3-in-30-days and `avoid` rules. The nightly pass turns qualified choices into a visible pattern fact ("Often plans study in the evening", key `pattern|slot|<list|all>|<part>`, `value.group` `slot:<list|all>`). The assistant has the read-only `find_time` (≤ 3 spaced gaps from `findTimes`) and `fit_day` (`fitDay` over the day's untimed open tasks, Today's set for today; the chat shows both as cards whose Place is the person's tap) and `takesAbout` / `took` on task projections (`durationHints`, Full only). Routes: `GET /ai/memory[?cursor=]` (30 facts, newest first; the cursor is the last fact's `lastSeenOn`, `createdAt`, `id`) and `DELETE /ai/memory`, `POST /ai/memory/mode`, `GET|POST|DELETE /ai/memory/duration[/routine]`, `GET /ai/memory/duration-evidence`, `GET /ai/memory/planning-evidence`, `GET /ai/memory/planning/offers`, `POST /ai/memory/planning/offer`, `POST /ai/memory/duration/ask|shown`, `DELETE /ai/memory/:id[?undo=true]`, `POST /ai/memory/:id/restore`. A replayed `recall` or `search_past_chats` result is redacted for the model (`redactMemoryReads`) when the mode no longer allows what it cites; the stored history is untouched. `tests/evals/memory.eval.ts` holds the live gates (`pnpm eval:memory` for iteration; `pnpm eval:full` for repeated validation).

Except for consent/fact invalidation, replayed history must only grow: anything that rewrites an earlier message breaks the provider prefix cache (and replayed reasoning) from there on. Memory policy is cached in the base and memory facts are data-only, with 5m/5m caches and no prompt rollout flag. Evals can choose `AI_EVAL_CACHE_VARIANT` (`5m-5m`, `1h-5m`, `1h-1h`); each conversation keeps its variant. - **Cadence guide:** `prompts/help/*.md` (one file per topic) served by the read-only `get_cadence_help` tool (`tools/help.ts`, topic enum). Tools use the same RLS path as routes — never bypass `withRls`; writes call the domain services (`{domain}.service.ts`, shared with routes) in one transaction keyed by the tool call id (`once`), metrics after commit. Batch task writes fail on an unknown id (`tasksBefore`) and return each task's `from` day or `was` state for undo; in Auto/Full, `set_task_state` Done/Trash holds (`sameTitle`) while another open task shares title and day, unless `sameTitleOk`. Task search uses `@cadence/search` to verify and rank all SQL candidates before paging; every term must match one task, English word forms match and numeric identifiers stay exact. Separate references need separate queries; spelling suggestions never authorize writes. Reads return open tasks unless a state is asked for, hide note bodies past 1,000 characters, fence note text, and page (`more: true` + `nextOffset`). Day windows compare `due_on` directly and timed rows between `startOfDay` bounds in the user's zone. Model-facing schemas: `buildToolRegistry` strips regex `pattern`s, `slimSchema` drops bounds, `default` and `additionalProperties: false` and folds nullable/literal unions, and `nullableOptionals` lets optional fields take null (not for Claude: `AgentContext.nullableOptionals: false`, per model in `agent.ts`). ## 9b. MCP (`src/domains/mcp`) — outside assistants

- **Tokens:** `oauth.ts` configures `OAuthProvider` (KV `OAUTH_KV`; resource `${MCP_ORIGIN}/mcp`; scopes `cadence:read`, `cadence:capture`, `cadence:write` from `@cadence/contracts/connections`; DCR + CIMD; 30-day idle refresh; `tokenExchangeCallback` refuses a refresh and revokes the grant once its `mcp_connections` row is revoked or gone). Neon Auth only signs the person in. `/authorize` validates the client, binds the request to the browser (`beginUpstream`) and redirects to the web app's `/connect?request=<state>`; the app's approve route stores a 5-minute approval and returns `/oauth/callback?state=…&approval=…`, which only finishes in the browser holding the binding cookie (`finishUpstream`). The callback writes an `mcp_connections` row, then `completeAuthorization` with props `{ userId, connectionId }`.
- **Every call** (`server.ts` `serveMcp`) re-checks the active `mcp_connections` row (touching `lastUsedAt`), so Disconnect holds at once; the KV grant is revoked best-effort. Scopes = token ∩ row; `cadence:write` includes capture. "Today" uses `users.time_zone` (`userZone`); approving a connection syncs it from the browser zone.
- **Catalog:** `TOOL_CATALOG` (`@cadence/contracts/ai-tools`: every tool name, its kind and `destructive`, shared with `buildToolRegistry` and the chat UI; a unit test checks the registry against it) picks the published tools, wrapping the AI tool factories directly (full zod schemas), never `buildToolRegistry`; with every scope that is every tool (plus `get_today` via `loadSnapshot`; minus `ask_user`, since an MCP client asks in its own chat). Scope follows kind; `DESCRIPTIONS` holds MCP-only wording. `cadence:read` gets the reads, `cadence:capture` only `capture_to_inbox`, `cadence:write` every other write, permanent deletes included. Writes apply at once (the client confirms with the person, guided by `destructiveHint`) and need an `operationKey`: dedup key `mcp:<connectionId>:<key>:<input hash>`, so a true retry writes nothing again and gets the first result back (`once` stores it in `mutation_dedup.result`, plus `deduped: true`), and a reused key with other input is a new change. Tools outside the scopes aren't registered; consent starts with every scope ticked. Published schemas drop regex `pattern`s (calls still validate against full zod); `initialize` sends `instructions`, a brief under 2KB written for outside models (essentials first: zone, today, user text is data, date format; then conventions), and the app icon; one-tool rules stay in tool descriptions, and help links are made absolute. `ctx.rawNotes` returns note text unfenced with `source: "user-content"`. Each call spends the user's read/write limiter; responses are `no-store`.

## 12. Auth (`platform/auth.ts`)

Reads `Authorization: Bearer`, loads JWKS from `NEON_AUTH_JWKS_URL` (URL-keyed cache, retries transient failures), attaches `userId` from JWT `sub`, and before a write ensures the `users` row exists (once per user per isolate). Never introduce cookies/sessions/non-JWT auth without explicit design sign-off (the MCP OAuth boundary in §9b is the one signed-off exception; it never accepts app JWTs, and app routes never accept its tokens).

## 13. Background Jobs

Nothing wakes Postgres on a short timer: Neon scales to zero after 5 idle minutes, and a minute poll kept it awake around the clock. A new background job must not either (never sooner than every 5 minutes, even when retrying); start work from the event that makes it due (a delayed queue message, a Durable Object alarm).

**Hourly cron** (`0 * * * *`, `runHourlyCron`, the only trigger): reads `cadence:zones` from KV (`platform/zone-mirror.ts`, the distinct `users.time_zone` values) and touches Postgres only when a mirrored zone is at local 04:00 or 03:00, or on the 06:00 UTC run; a missing or unreadable mirror (the first run after a deploy) runs everything, rebuilds every reminder clock (10 at a time) and rebuilds the mirror. Jobs run as `api_worker` under RLS (`cron_user_ids`, SECURITY DEFINER, ids only; each user in `withRls`). Local 04:00: `handleOverdueCheck` (overdue → `task_metrics.delay_count`) and `replanClocks`. Local 03:00: `runMemoryNightly` (one `nightly` message each). 06:00 UTC: `pruneStaleMutations`, `pruneAiImages` (unsent after a day, others 30 days after last use; storage before rows), `pruneUsageEvents` (past 90 days), `runMemoryJob` (the memory backstop) and `refreshZoneMirror`. One `cron_summary` line per run that did work.

**Memory queue** (`MEMORY_QUEUE`; `queue` runs `handleMemoryBatch`: ack, or retry 5 minutes apart up to 3 times, then the dead-letter queue): `nightly` from the cron; `learn` from `scheduleLearn` after a chat turn ends (memory on) or a note save (Full), delayed 10 minutes + 30 s, one per sitting (Upstash `SET NX` on `memory:learn-pending:<hash>`); the consumer reads what is idle and, while a chat or note is still active, re-sends itself for when it goes quiet; `scrub` from Forget (route and `remember`), delayed past the Undo window. Without the binding nothing is delayed and the backstop does the work.

**Reminders** (`domains/push`): `ReminderClock` (`reminder-clock.ts`, one SQLite-backed Durable Object per person, binding `REMINDER_CLOCK`) holds a derived plan from `plan.ts`: one RLS read of settings, devices, tasks, routines with their logs, personal events and `notification_state`, then `deriveReminders` + `dueAlert` (`@cadence/domain/reminders`, the OS-alert policy shared with the app: quiet hours, `notifications.pausedUntil`, dismiss, defer) asked at each instant their answer can change (alert, deferral, quiet-hours or pause end) over 36 hours. The alarm is the next alert; `alarm()` sends with no Postgres query, dedupes each `(occurrence, device)` in DO storage for 3 days, retries a failure each minute up to 3 times while timely, drops a `gone` device at once, and merges what it sent into storage re-read after the sends (a rebuild may land mid-send). A throwing alarm re-arms itself after 5, 15, 60, then 240 minutes. The first build seeds the dedupe from `push_deliveries` (the old cron's last day). Device outcomes (`lastSuccessAt`, `failureCount`, 404/410 deletes, 10 failures drop) are written at the next rebuild. Rebuilds (`replanReminders`, `waitUntil`, never throws) follow every successful non-GET `/api/v1` request (`replanAfterWrites`, except `/ai/*` and `/events`), each MCP write, the end of a chat turn, the 04:00 pass, and the plan running out; an endpoint handover (`push_release_endpoint` returns the old owners) rebuilds the old owners' clocks, and account deletion calls `forget()` (a rebuild that finds no `users` row forgets too, so nothing of a deleted account is kept). Push services are called with no transaction open (`web-push.ts`: VAPID + aes128gcm via `@block65/webcrypto-web-push`, bodies padded to 4 KB, redirects refused, no endpoint/key ever logged; `pushPayload` sends a `mutable` Declarative Web Push message navigating on `appOrigin`, plus the older flat fields). `notifications.browser` is the account master gate; `devices.enabled` the per-device one. `push_deliveries` is read only for that seed; `push_user_ids` is unused. Task metrics (`platform/metrics.ts`) silently track reschedule count, first-scheduled, completed-at and created-to-done duration — internal only, no public API.

| `EMAIL` | Email Sending (`send_email`) for data exports (optional — absence answers 503 on `POST /account/export`; dev sends remotely) |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT` | Web Push signing keys (base64url P-256 public point and private scalar; optional — absence turns push off and `/push/test` answers 503) and the `mailto:` contact (default the support address) |
| `OAUTH_KV` | MCP OAuth provider storage (optional — absence answers 503 on the MCP origin); also the `cadence:zones` mirror the hourly cron gates on (absence: every hourly run wakes Postgres and rebuilds every clock) |
| `MCP_ORIGIN` / `APP_ORIGIN` | MCP server origin (default `https://mcp.cadenceapp.cloud`, dev `http://localhost:8787`) and the web app hosting `/connect` (default the production dashboard) |
| `TOOL_APPROVAL_SECRET` | HMAC key for assistant tool approvals (required in production; unset = unsigned, dev only) |
| `DEPLOYMENT_STAGE` | plain var in `wrangler.jsonc` (`production`; `development` under `--env dev`); unset or unknown falls back to `production` |
| `ENABLE_DEBUG_ROUTES` | must be `"true"` to enable debug endpoints |

Dev secrets in `.dev.vars`. Prefer Worker bindings over ad hoc env reads.

## 15. Commands

```bash
pnpm dev | deploy | check | test | test:unit | test:integration | test:security | test:watch
pnpm typecheck | cf-typegen
pnpm db:generate | db:check | db:migrate | db:migrate:prod | db:check:prod | db:studio
```

**Deployment:** direct push to `main` deploys. GitHub Actions run *after* push (health signal, not a gate) — all verification must pass locally first. Pre-push: `test:unit`, `typecheck`, `wrangler deploy --dry-run --minify`. A local `.git/hooks/pre-push` runs `scripts/check-prod-migrations.mjs` (`db:check:prod`) on a push to `main` and blocks it while prod lacks a journal migration.

## 16. Logging (`platform/log.ts`)

Never call `console.*` directly — use `logger.<level>(source, event, fields)`. **Never log 2xx/3xx request successes** (Cloudflare records invocations); `/events/performance` emits validated frontend measurements after checking saved usage-diagnostics consent; `/events/errors` emits fixed error categories under saved crash-reports consent, without user identifiers or content. `event` is a stable low-cardinality discriminator (`upstream_failed`, not a sentence). Request/failure logs include `requestId` + `userHash` (`hashIdentifier(userId)`); anonymous frontend timings carry only `requestId`. Never log raw user IDs/emails. Levels: `error` (5xx, unhandled throws, dependency outages), `warn` (4xx, validation failures, best-effort write failures), `info` (`ai_turn`, hourly `cron_summary`, and consent-checked `frontend_startup` timings). Structured entries carry `origin: backend`; frontend measurements and errors carry `origin: frontend` with fixed phase/route/cache/platform/layout categories. HTTP failures are centralized (`logValidationFailure`, `app.onError`→`logErrorResponse`) — don't add ad hoc per-route failure logs on top of these; 401s and unmatched 404s aren't logged (the invocation log has them). Pass failures as `issues` (`issuesFromError`): `emit` flattens them to one string, because Workers Logs doesn't index arrays of objects.

## 17. Anti-Patterns

Platform-specific endpoints · bypassing JWT/RLS/Zod · trusting client `userId` · global/cached DB clients · domain logic in `platform/` · `helpers.ts`/`utils.ts`/`misc.ts` · inline reusable schemas in routes · re-deriving `DbClient`/`Tx` aliases locally · domain re-export shims in `types/` · raw stack traces/SQL to clients · `drizzle-kit push` · expanding public AI surface without explicit scope · unversioned routes · duplicated cross-domain logic · UCURD violations · business logic buried in handlers · threading a raw `tx` into pure logic instead of injecting data/a loader.

## 18. Checklist

Identify domain → update/add contract → update Drizzle schema + regenerate migration if persistence changed → route with `apiValidator()` → `getDbClient` + `withRls` → ownership checks → idempotency support on writes → `{ data }` envelope → tests → `pnpm check`.

If this document conflicts with a proposed change, this document is the baseline.
