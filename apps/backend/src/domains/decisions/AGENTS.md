# Decisions — Agent Instructions

Part of the backend: see `apps/backend/AGENTS.md` §9 and `src/prompts/decisions/` for the prompts.

A decision model returns probabilities over app-supplied options, never text, so it can only pick the user's own ids.

- **Adapter** (`decision.ts`, the only one): `decide` sends named `choice` (opaque option keys + `none`) and `score` questions in one request to OpenRouter `/api/alpha/decisions`, each with its kind's threshold and one budget unit; `decideChoice` wraps one choice. No fallback providers; never throws. ≤ `DAILY_DECISIONS` (200)/person/day across kinds (`platform/daily-budget.ts`, Upstash; fails closed: no suggestion, no model call). One `ai_decision` log line per call (kinds, model, `servedModel`, tokens, `costUsd`, ms, outcome; never text).
- **Switches:** `AI_DECISION_MODEL` (dated model ID, `wrangler.jsonc`) is the only one; unset/empty = model decisions off. A shown choice needs top probability ≥ the model's `DECISION_THRESHOLDS` entry (from the evaluation; none → 0.9). Every call first reads `settings.tasks.intelligence.smartPlacement` (`!== false`); no transaction is open across the model call.
- **S1** (`placement.ts`): a saved capture (`POST /inbox`, MCP/assistant `capture_to_inbox`) schedules `suggestPlacement` in `waitUntil`. One call picks a list or list › section pair (merged as `{ projectId, sectionId, model, probability, costUsd, ms }` into `analysis.suggestedPlacement` only if the pair still exists), reads a stated priority (`priority_said`; only with NLP on and no `parsePriority` hit: `analysis.suggestedPriority`, shown in Clarify with ×, never applied by Sort) and, when E3 applies, scores Effort (`analysis.suggestedEffort`, which `processCapture` turns into the task's guess).
- **E3** (`effort-guess.ts`): after a task is created or its title/list changes (routes, `create_tasks`, `update_tasks`; `waitUntil`), a `score` question over the person's 20 nearest own `manual` choices (≥ 8 covering ≥ 2 levels in 365 days, both switches on, no similar-match guess) stores `tasks.effort_guess*` only while title, list and Effort are unchanged. `guessAfterWrite` clears it on a title/list change and on a chosen Effort (keeping a `dismissed`).
- **S2** (`did-you-mean.ts`): `POST /search/did-you-mean` and an empty `get_tasks` query (`possibleMatch`) verify scoped spelling candidates via `@cadence/search`, then offer ≤ 255 model options ranked by `pg_trgm` `word_similarity` (migration 0018) and recency. Numeric identifiers are preserved; assistant suggestions preserve every filter. `GET /search/task-notes` gives the palette compact canonical note tokens and headings.
- **Weekly Reset** (`reset.ts`, `POST /ai/decisions/reset` via `reset.route.ts`): `{ step, ids ≤ 30 }`. Rows are read under RLS by id (others' aren't found; no notes or subtask text) with the week's open minutes (`weekRoom`) and what the person said about planning (`planningSaid`, as `usableBy` allows); one `reset_disposition` question per row, one request. Only `chose` buckets return (`today · this_week · next_week · later`; waiting: `activate · keep_waiting`), never a date.
- A section sent to `/inbox/:id/process` must belong to the chosen list or the call fails 400.
