# Assistant Tools — Agent Instructions

Part of the AI domain: see `apps/backend/AGENTS.md` §9 for approvals, prompts and history; MCP publishes these tools (`src/domains/mcp/AGENTS.md`).

One file per callable surface: `tasks`, `projects` (lists, sections), `tags` (colours by palette name, `TAG_COLOR_NAMES` ↔ `TAG_PALETTE`; list/routine/event colours are `ACCENT_COLORS`), `habits` (`get_habit_history` sorts due days via `habitDays` (`@cadence/domain/repeats`), the days `/habits/weekly` shows; writes via `habits.service.ts`; repeat rules limited to the Routines picker's), `inbox` (captures become tasks via `create_tasks` with `inboxItemId`; back to New via `unprocessCapture`), `calendar` (one-offs matched on local day in SQL + expanded series, capped after expansion, paged; read-only `find_time`/`fit_day`), `events` (`settings.calendar.personalEvents.items`, rewritten whole in the transaction), `focus-views` (stored definitions read leniently by `readFocusView`, also used by `get_tasks`), `metrics`, `help`, plus `projections` (compact rows: default/null keys dropped, names beside ids; a timed repeating row shows no `dueDate`, its anchor) and `drafts` (write schemas picked from task contracts; no `isAllDay`, it follows from the values; tags by name via `findOrCreateTags`).

- **Writes:** same RLS path as routes; call domain services (`{domain}.service.ts`, shared with routes) in one transaction keyed by the tool call id (`once`); metrics and shared-list live broadcasts (`broadcastLive`) run after commit. Shared-list writes enforce roles (`requireEdit` / `requireOwner`), check `updatedAt` against the read (`assertTasksNotStale` → `409 STALE_WRITE`), and guard shared creates against duplicate open titles across all members (`sharedCreateDuplicates` unless `sameTitleOk`). A call id starting `DRY_RUN_PREFIX` (`dry:`) runs the write, then `once` throws `DryRun` so the transaction rolls back and `safeExecute` returns the result plus `dryRun: true` (post-commit tracking skips it). `create_tasks` keeps batch order: after creating it calls `reorderTasks` per list in draft order, at `settings.tasks.newTaskPlacement` (default bottom) or the call's `to`/`beforeTaskId`/`afterTaskId` (one list only), and returns `placed` (the open neighbours' titles per list). Batch task writes and `delete_tasks` fail on an unknown id (`tasksBefore`); `get_task_detail` 404s and return each task's `from` day or `was` state for undo. In Auto/Full, `set_task_state` Done/Trash holds (`sameTitle`) while another open task shares title and day, unless `sameTitleOk`.
- **Reads:** open tasks unless a state is asked for; note bodies hidden past 1,000 chars (whole over MCP, `ctx.rawNotes`, which may also rewrite them whole), note text fenced in-app; `get_tasks details` adds each row's `note` and `subtasks` (≤10 rows). One page shape: `more: true` + `nextOffset`; `get_projects` with `projectId` pages its sections, without it lists (a list with cut sections has `partial: true`), with `openTasks` counts and an exact `query` name first. Search uses `@cadence/search` to verify and rank all SQL candidates before paging: every term must match one task, English word forms match, numeric identifiers exact. Separate references need separate queries; spelling suggestions never authorize writes. Day windows compare `due_on` directly and timed rows between `startOfDay` bounds in the user's zone.
- **Model-facing schemas:** `buildToolRegistry` strips regex `pattern`s; `slimSchema` drops bounds, `default`, `additionalProperties: false` and folds nullable/literal unions; `nullableOptionals` lets optional fields take null (not for Claude: `AgentContext.nullableOptionals: false`, per model in `agent.ts`). In a `patch` null and [] change nothing; `withClear`/`applyClear` turn the model's `clear: [field]` into null (`clear` never reaches `execute`). Validation still uses the zod schema leniently (`validateLenient`; `ignored` in the result tells the model). `safeExecute` retries an unexpected failure once, and fills `code`/`status`/`isRetryable`/`issues` from `ERROR_CODES` (AppError <500 and DomainError as thrown; anything else `AI_TOOL_FAILED`, 500, not retryable). A tool's own refusal uses `refuse(code, message, status, extra)`. The chat model gets the registry minus `get_habit_status_today` (`chatTools`; the snapshot carries today's routines). Descriptions say what a tool does, returns and its limits, each rule once; when to use it belongs in `prompts/assistant/base/workflow.md`.
- **History replay:** older turns' reads shrink to `{count, ids}` (`compactOldReads`) and drop turn context and image bytes, all behind `recentStart`, which moves every `COMPACT_EVERY_TURNS` (4) turns and always keeps the previous turn whole. Window (`loadConversationMessages` `historyWindow`): latest ≤ `MAX_HISTORY_TURNS` (40) rows, moving in `HISTORY_DROP_STEP` (16) steps (`historyWindowStart`), opening on a user message (`startAtUser`).
