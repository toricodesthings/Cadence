# Memory — Agent Instructions

Part of the AI domain: see `apps/backend/AGENTS.md` §9 for the assistant it feeds and §13 for the daily run that starts the nightly pass. Queue and memory rules below are the current truth.

- **State:** `settings.assistant.memoryMode` (`off|basic|full`; null = unchosen = Basic, resolved by `memoryStateOf`; only the page reports `null`), `memoryChoiceAt`, `memoryEpoch`, `memoryLearningNotBefore` (set by Clear and by the release making Basic default: nothing said before it is read back) and `memoryBackfill` are server-owned: only `POST /ai/memory/mode` and the jobs write them; settings PATCH rejects them (400). Each mode change bumps `memoryEpoch`, fencing every background write in its transaction.
- **Facts:** `ai_memories`: `halfvec(512)` embedding (exact scan per person, no ANN), generated `search` tsvector, `content_hash` (unique among active rows; `insertFact` is ON CONFLICT DO NOTHING + reinforce; a forgotten row keeps it as tombstone). One read predicate, `usableBy(userId, mode)` (`memory-store.ts`; also `loadContextFacts`/stored-context validation): Full reads all active facts, Basic only `explicit`/`chat` outside `FULL_ONLY_KINDS`. Full-learned facts stay stored, unused, until Full returns.
- **Turn reads:** **profile** (`loadProfile`: pinned · preferences, quirks, constraints · life facts due ≤ 30 days, then life and what-helped facts within a 2,000-char budget; never patterns/durations) and **recall** (`recallFacts`: full-text OR + cosine, RRF k=60, from the last two user messages; skipped for a bare short command). `loadProfileCoverage` checks exact eligible-fact coverage in one RLS statement before recall: fully covered profiles skip embedding/recall; candidates keep hybrid recall + lexical fallback; no transaction held during HTTP; diagnostics record coverage/candidate presence. Both ride in `turnContext` as `(said <Month Year>) [id] text`, fenced as data. Replayed `recall`/`search_past_chats` results are redacted (`redactMemoryReads`) when the mode no longer allows what they cite; stored history is untouched.
- **Tools** (memory on; `isMemoryTool`; MCP same gate): `remember` saves/updates/forgets at once with a receipt (chat shows Undo, so no approval); ≤ 50 saves/updates/person/day, checked before any model call; no size cap. A save within `FORGOTTEN_DISTANCE` (0.15 cosine) of a forgotten same-kind fact returns `kept` ("You asked me to forget this"). `when`/`avoid` store a stated time of day / a help that doesn't work. `recall`; `search_past_chats` (full-text over `ai_messages.search_text`, the person's own words, never embedded).
- **Learning** (`learn.ts`; delayed queue messages, see Memory queue below; `runMemoryJob` = daily backstop, list from `memory_user_ids`): a chat idle 10 min is read from `metadata.memoryCursor` (user messages, ≤ 6k tokens). `prompts/memory/extract.md` proposes ≤ 8 candidates as `Output.object` (`AI_CHAT_MODEL` must list `structured_outputs`). `candidates.ts` drops flagged, unsourced, instruction-shaped, duration and activity-only ones (durations come only from completion answers). `consolidate.ts` (chat model over opaque keys, one call per reading; not the decision model, which abstains on changed values) names the known fact each repeats/updates. One transaction writes if `memoryEpoch` still matches (`fenceMemoryState`: user row FOR SHARE, so a mode change waits) and the cursor (microseconds) is where the reading began (it moves first, so overlapping runs write once). No `MEMORY_QUEUE`: nothing delayed, backstop takes 10 random people/run. `metadata.learn = false` skips a chat. ≤ 15 extractions/person/day, counted only when there's something new (`admit` → `withinDailyCap`, Upstash; no Redis = no cap; a capped chat stays unread till tomorrow).
- **Forget:** text kept `UNDO_WINDOW_MINUTES` (10) for Undo, then a delayed `scrub` reduces it to a topic label keeping its embedding, so paraphrases are dropped at learning and `remember` (`isForgotten`). Deleting a chat or switching it to "Don't learn" deletes facts only it taught (`seenCount = 1`; others lose the link; `dropChatFacts`). Nightly drops note/catch-up facts whose note/chat is gone (`dropOrphanedFacts`).
- **Full adds:**
  - `ai_memory_signals`: routes only (`trackTaskChanges(…, { env })` with a reschedule's `task_id`; habit resolve), never assistant/MCP/imports; ≤ 150/person/day, kept 90 days, dropped on Clear. Mode changes never erase, only start/stop learning.
  - `note-learn.ts`: changed lines only; hashes in `ai_memory_notes`; note never copied.
  - `backfill.ts`: 90 days newest first, ≤ 4 batches/night, skips what live learning covers. `memoryBackfill` keeps `learned`, `doneAt`, `failedNights`: a broken batch stops the night (`LearnResult.failed`); 3 in a row log `memory_backfill_stuck` (error); finishing logs `ai_memory_backfill_done`.
  - Nightly (`nightly.ts`, 06:00 UTC via `runMemoryNightly`, everyone): expiry; 60-day decay of unreinforced facts the person never said (activity ones excepted); merges (no size cap); patterns/durations from `signals.ts`; "when you plan" patterns from `planning_records` (Full). Each hashed by a count-free `key`, so forgotten stays forgotten as numbers move. Pattern = ≥ 5 events on ≥ 3 days in ≥ 2 distinct weeks of the last 28, ≥ 70% in one bucket. Duration fact only when `estimateDuration` (`@cadence/nlp/duration`, same as the app) is `supported` for the answers' `group_key`: `durationGroup`, first 3 meaningful words of a one-off title, or `series:<id>` for a repeating task.
- **"How long did it take?"** (`duration.ts`; policy `@cadence/domain/duration-ask`): answers in `duration_reports`, one per `(task_id, completed_at)` or, for a routine marked done, `(habit_id, target_date, wall_time)` (`POST|GET|DELETE /ai/memory/duration/routine`; 409 unless that day/time is done; `resolveHabit` deletes answers of an occurrence no longer done; estimator and `GET /duration-evidence` treat a routine as a repeating thing filed under its id). Outside the 90-day signals prune; kept until the task, the fact (Forget hides the group's answers, Undo restores, scrub deletes after `UNDO_WINDOW_MINUTES`), Clear or the account goes. `tasks.completed_at` = instant the task entered Done (ms precision, so a client can name it), kept by trigger `tasks_completed_at` on every write path (set on COMPLETE, kept while Done, cleared on leaving, which also deletes that completion's report), checked by `tasks_completed_at_check`.
  - `POST /duration/ask` decides: Full, task Done, group not settled, not completed within 2 min of creation, budget open (one ask/day/person in `settings.assistant.durationAsk`; every 3 days after 3 unanswered, weekly after 6, monthly after 10). On yes it reserves the day under the user-row lock with a fresh `token`, returns `completedAt` + the person's own plan as `reference`.
  - `POST /duration/shown` counts one miss per token.
  - `POST /duration` stores in its own transaction, returns the row (409 if `completedAt` no longer names the completion; 200 `null`, nothing stored, outside Full; a token-carrying answer resets misses; 200/day/person, then 429).
  - `GET /duration-evidence`: estimator input (Full, last 365 days, ≤ 1,000).
- **How they plan** (`planning.service.ts`, Full; rules `@cadence/domain/{find-time,slot-preference,planning-offers}`): `planning_records` (90 days, nightly prune; Forget on a "when you plan" pattern hides its rows, Undo restores, scrub deletes rows + fact with no tombstone so new choices can re-teach) are written from routes only, as `recordSlot` after `PATCH /tasks/:id`: a manual drop of an untimed task onto a time (`X-Queued-At` > 1 h old: ignored) or a Find-a-time pick with `findTime.shown` (among ≥ 2 parts of the day; replaces that task's pick for the day; `undo` deletes it; first proposal kept; Later today and receipt time write nothing), each only when another part of the day also had room.
  - `POST /ai/memory/planning/offer`: records Not now (declined) or the offered action (chosen) with a fingerprint of title, open steps and `waitingOn`.
  - `GET /ai/memory/planning-evidence`: the device's records + stated `when` preferences (any memory-on mode) for the same pure rule. `GET /ai/memory/planning/offers`: tasks each offer may show on after the decline, 3-in-30-days and `avoid` rules.
  - Nightly turns qualified choices into a visible pattern fact ("Often plans study in the evening"; key `pattern|slot|<list|all>|<part>`, `value.group` `slot:<list|all>`).
  - Assistant: read-only `find_time` (≤ 3 spaced gaps, `findTimes`) and `fit_day` (`fitDay` over the day's untimed open tasks, Today's set for today; `through` (≤ day+6) loops by day, carrying what didn't fit unless past deadline, `includeUnscheduled` offers undated tasks from day one, returns `days[]`; chat shows cards, Place is the person's tap), plus `takesAbout`/`took` on task projections (`durationHints`, Full).
- **Routes:** `GET /ai/memory[?cursor=]` (30 facts, newest first; cursor = last fact's `lastSeenOn`, `createdAt`, `id`), `DELETE /ai/memory`, `POST /ai/memory/mode`, `GET|POST|DELETE /ai/memory/duration[/routine]`, `GET /ai/memory/duration-evidence`, `GET /ai/memory/planning-evidence`, `GET /ai/memory/planning/offers`, `POST /ai/memory/planning/offer`, `POST /ai/memory/duration/ask|shown`, `DELETE /ai/memory/:id[?undo=true]`, `POST /ai/memory/:id/restore`. `tests/evals/memory.eval.ts` holds the live gates (`pnpm eval:memory` iterating; `pnpm eval:full` repeated validation).
- **Memory queue** (`MEMORY_QUEUE`; `queue` runs `handleMemoryBatch`: ack, or retry 5 minutes apart up to 3 times, then the dead-letter queue): `nightly` from the cron; `learn` from `scheduleLearn` after a chat turn ends (memory on) or a note save (Full), delayed 10 minutes + 30 s, one per sitting (Upstash `SET NX` on `memory:learn-pending:<hash>`); the consumer reads what is idle and, while a chat or note is still active, re-sends itself for when it goes quiet; `scrub` from Forget (route and `remember`), delayed past the Undo window. Without the binding nothing is delayed and the backstop does the work.
