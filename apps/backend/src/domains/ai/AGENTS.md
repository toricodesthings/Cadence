# Assistant Core — Agent Instructions

Part of the backend: `apps/backend/AGENTS.md` §9 summarizes the AI domain. Memory, decisions and tools have their own guides (`memory/`, `../decisions/`, `tools/`).

## Routes

`POST /chat` (streamed, persisted; a new message or approval answers), `POST /steps` (Suggest steps, `steps.ts`: 3–7 steps from the task's title, first 1,000 note characters, list and existing steps as structured output from the chat model; admitted (`admitChatTurn`, shared with chat) and settled like a turn; 8 s → 504; stores nothing), conversation CRUD (delete takes its images), `GET /usage`; images: `POST /` upload (WebP-only, 1MB, dedup per user + conversation), `POST /:id/report`, `GET /:id` own image, `DELETE /:id` while unsent

## Core

- `ai.route.ts` — `POST /chat` streams a turn (`createAgentUIStream`/`createUIMessageStream`, AI SDK v7), persists messages, supports resumable streams and `stopStream`. A request carries a new user message or `approvals`: answers apply to the stored last reply (`applyApprovals`, never a client copy), the SDK runs what was approved, and the same reply continues. Replayed history turns open calls into declined ones (`settleUnanswered`). Settings/metrics overlap turn persistence; ordinary history loads once. Validated continuations skip snapshot/recall construction; new turns prepare while history commits. Images overlap resume initialization, which finishes before the transaction publishes its pointer; if initialization fails, the turn streams without resumption. A first turn with `surface: "weekly_reset"` is titled `Weekly Reset · <Mon, Nov 9>` (the user's day) with no title model call.
  - **Logging:** each turn logs one `ai_turn` info line from `onEnd`: model, `surface`, outcome, steps, tool calls, tokens (incl. cache reads/writes), `costUsd`, `servedModel`, timings from the request's arrival, and bounded content-free `run-diagnostics.ts` records (unique run id, root release, preparation spans, model attempts, tool durations); unknown usage/cost stays null. `ai_title`, `ai_embedding`, `ai_memory_extract` and `ai_memory_match` log their own lines with the same fields. Every OpenRouter call sends `user` = hashed user id. Run diagnostics are log-only, sampled, not a ledger.
  - **Spend:** `costUsd` (summed per step by `addStepSpend`) and `servedModel` are saved in the assistant row's metadata (never streamed) beside `metadata.titleSpend`; Admin sums both. Continued replies overwrite that metadata, so it isn't cumulative billing (memory's calls are logged, not stored per row).
  - **Conversations:** `GET/PATCH/DELETE /conversations[/:id]` (patch also takes `learn`, memory's per-chat switch); `DELETE /conversations/archived` (images from storage first) is registered before `/:id`.
- `agent.ts` — builds the agent (`getAgentInstance`; fixed `REASONING_EFFORT` since a change invalidates the cache; no temperature override).
  - **Models:** `model-router.ts` (leaf module, no agent imports) owns both model ids. `pickChatModel` uses `AI_CHAT_MODEL_BASIC` only for a short, single-line, image-free message matching a `BASIC_INTENT` (small talk or how-to, never the user's data) with no `COMPLEX_CUE`, and only while the thread (`ai_conversations.model`) has used nothing else; otherwise `AI_CHAT_MODEL`. Unrecognised stays standard, a thread never drops back (each model has its own prompt cache), and a failing basic model falls over to standard. `chatModelSettings` pins each provider route (`provider.order`: Anthropic for `anthropic/*`, else DeepInfra; fallbacks on), never `:nitro` (it hops providers and their caches).
  - **Caching:** Claude caches only behind explicit breakpoints: OpenRouter's top-level automatic `cache_control` plus one on the system prompt (`chatInstructions`; tools render first, so tools + system cache together). Other models cache implicitly (`tests/unit/ai-prompt-cache.test.ts` checks the wire body). `DEFAULT_CACHE_VARIANT` = production 5m static/5m tail; 1h variants are evaluation-only (`AI_EVAL_CACHE_VARIANT`: `5m-5m`, `1h-5m`, `1h-1h`; each conversation keeps its variant). Each assistant message's metadata gets `promptHash` (prompt blocks + help files + tool names/descriptions/schemas).
  - **Approval:** writes execute on the server; `toolApproval` (`approvalFor` in `safety/approval.ts`) decides which wait for a tap: Ask = every write, Auto = only `needsTap` (any `delete_*`, removing subtasks, whole-note rewrites, >5 tasks or captures), Full = only a `delete_*` while the recent context holds an image (`hasImages`, read at call time); reads, `capture_to_inbox` and `ask_user` never. Approvals are HMAC-signed with `TOOL_APPROVAL_SECRET`, so an edited or forged one fails closed.
  - **`ask_user`** (`tools/ask.ts`, 2–4 options) ends the turn (`stopWhen` `askedUser`); the reply is the next message. A `field` question ("Which matters most today?" / "Which is heaviest?"; also matched by wording when `field` is missing) is held back (`asked: false`, turn continues) per `@cadence/domain/field-ask`: the next message settles it (`settleFieldQuestion` in `turnSettings`: naming an option answers, anything else is a miss; 7 days after a miss, 30 after two) in server-owned `settings.assistant.fieldAsk`.
  - **Reasoning:** history passes through `dropUnsignedReasoning` then `dropForeignReasoning` (`persistence/message-mapper.ts`), so unsigned reasoning never reaches the provider and a model switch never replays the previous model's thought signatures.
  - **`said` check** (`tools/said.ts`): chat drafts' priority and effort need a `said` quote: whole words of `ctx.userTexts` (the person's recent messages) carrying a cue for the field, or the whole message answering that field's question (`answeredField`). Otherwise they're dropped into `ignored` (an `update_tasks` left empty writes nothing). A quoted effort is stored `manual`; MCP (no `userTexts`) skips the check. `memory/task-hints.ts` adds `effortGuess` to assistant reads.
- **Prompts are files, git is the only source:** every model-facing text lives in `src/prompts/`, one folder per concern: `assistant/{base,voice,user,surface}/*.md` (system-prompt blocks, order in `domains/ai/prompt/prompt-blocks.ts`), `assistant/title.md`, `assistant/steps.md`, `memory/` (`extract.md`, `consolidate.md`), `decisions/` (`placement.md`, `did-you-mean.md`, `priority-said.md`, `effort.md`, `reset-disposition.md`), `help/` (the guide). No inline prompt text in `.ts`. Edit and push; the deploy ships them. `.md` imports as text (wrangler `rules` + vitest `md-text` plugin). An unknown `{{placeholder}}` throws (composer tests catch it). Only raw user values (names, custom instructions, snapshot, memory) are fenced; instructions never. There is no prompt rollout flag.
  - **Composition:** `composePrompt` returns `{ instructions, turnContext }` so provider prefix caching holds. `instructions` = base + memory policy when enabled (stable per memory mode, cached with the tool definitions). `turnContext` = voice (+ `workload-high.md` when adaptive tone and burnout > 70) · custom instructions · Environment (names, emoji, approval mode from the chat request, workload, zone, minute-precision clock) · the request's `surface` block (`surface/weekly-reset.md`) · Today at a glance, or on the Weekly Reset surface The week ahead (`loadWeekAhead`: 7 days of `weekRoom` minutes, ≤ 5 deadlines a day, Fixed and routine counts) · memory (profile and this turn's recall, or one line saying it's off).
  - **Snapshot:** Today at a glance is `loadSnapshot` in `turn.ts`: today's schedule, overdue, routines, newest captures and events within 7 days, read through shared tool projections with small caps. Chat prefetch shares its bounded routine rows across isolated section transactions; later tools read fresh.
  - **Replay:** `withTurnContext` appends the context as a text part to the model's copy of the user message and keeps it on that row's `metadata.turnContext` (`setTurnContext`, in `onEnd`), so later turns replay it byte-identical (`turnContexts`: stored rows only, never a client copy; a continued reply keeps its valid original; `validateStoredContexts` checks current consent and exact current fact lines under RLS, omits invalid context from replay and rebuilds the current continuation). `toClientMessage` keeps it off `GET /conversations/:id`. Except for consent/fact invalidation, replayed history must only grow: rewriting an earlier message breaks the provider prefix cache (and replayed reasoning) from there on.
- **Cadence guide:** `prompts/help/*.md` (one file per topic) served by the read-only `get_cadence_help` tool (`tools/help.ts`, topic enum). Links are in-app only: routes, `?settings=<tab>`, or ids from tool results. The guide and primer call projects Lists and document Capture completion, notes, ordering and Undo. A user-visible change that makes a help file or the primer (`prompts/assistant/base/cadence-primer.md`) wrong edits it in the same change; `tests/unit/ai-help.test.ts` checks every link against the known routes and Settings tabs.
- **Images (`images/`):** a turn carries `cadence-image:<uuid>` file parts only (`input-guard`: WebP references, ≤ `AI_IMAGES_PER_MESSAGE`, no filename), persisted as-is. Before `admit`, `resolveTurnImages` checks the ids are the caller's in this conversation (else 400 `IMAGE_NOT_FOUND`) and counts new sends; re-sends are free. After `compactOldReads`, `hydrateImages` turns images in recent turns (from `recentStart`) into data URLs (one R2 read each) and older or expired ones into a text stub; memory extraction and the saved reply keep the references. Objects live at `ai-images/{sha256(userId)}/{id}.webp` with no metadata; only the `ai_images` row links a user to one. The 24h image quota is one more dimension in the admit script (429 `AI_IMAGE_LIMITED`); 8 unsent uploads at most (429 `AI_IMAGE_PENDING_LIMIT`).
- **Time** (the root AGENTS.md model): every server path takes the zone from `userZone(tx, userId)` (`users.time_zone`; AI turns and `PUT /me/time-zone` sync it from the device first). `userClock` (`turn.ts`, shared with MCP) gives the prompt local wall-clock time with offset and weekday, and tools `ctx.timezone` + `ctx.today` (`todayIn`). Tasks store days as `date` (`due_on`, `end_on`, `hidden_until`) and timed values as instants plus the task's `zone`. Tools emit days as stored and instants via `toZonedIso`; `taskDay` (`@cadence/domain/task-recurrence`) is `due_on ?? dayOf(scheduled_start, zone)`. Overdue excludes series and Fixed; workload signals are computed on read (stale after 24 h, by the assistant's turn prep and `get_user_metrics`).
- **Redis (`platform/redis.ts`, Upstash REST over HTTPS only):** `getRedis(env)` gates stream-resumption (in-flight SSE chunk log + abort flag) — returns `null` if unconfigured/insecure, and every resumption path must no-op gracefully on `null`. `getRateLimitRedis(env)` is a separate accessor for the usage budget: `admitChatTurn` (`safety/admission.ts`) checks the global daily spend cap, then reserves; `onEnd` settles a finished turn to its metered usage, a stopped or failed one to its summed `finish-step` usage plus the reserve once the model started (a failure before any output is refunded), and anything thrown after admission before streaming refunds the reserve. A Stop snapshot keeps only `text`, `reasoning` and `step-start` parts and only creates the row (`onlyIfAbsent`; the producer's save is never overwritten). A turn on a thread whose stream is still live in Redis answers 409 "A reply is already on its way." (the thread row is locked while persisting); a turn that fails after its stream was published closes it as `error` and clears the pointer; a resume of an `active` log silent for 60 s closes (chunk TTL 5 minutes). `ai_stream_error` logs the provider's error code/type, never its body. Redis is a *cache*, never the source of truth — Postgres is. Built per-request (Workers rule), never a module global.
