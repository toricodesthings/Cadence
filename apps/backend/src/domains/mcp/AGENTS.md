# MCP — Agent Instructions

Outside-assistant boundary of the backend, dispatched in the Worker's `fetch` before the Hono app (`isMcpRequest` in `src/index.ts`): no app JWT, CORS or `{ data }` envelope.

- **Tokens:** `oauth.ts` configures `OAuthProvider` (KV `OAUTH_KV`; resource `${MCP_ORIGIN}/mcp`; scopes `cadence:read`, `cadence:capture`, `cadence:write` from `@cadence/contracts/connections`; DCR + CIMD; 30-day idle refresh; `tokenExchangeCallback` refuses a refresh and revokes the grant once its `mcp_connections` row is revoked or gone). Neon Auth only signs the person in. `/authorize` validates the client, binds the request to the browser (`beginUpstream`) and redirects to the web app's `/connect?request=<state>`; the app's approve route stores a 5-minute approval and returns `/oauth/callback?state=…&approval=…`, which only finishes in the browser holding the binding cookie (`finishUpstream`). The callback writes an `mcp_connections` row, then `completeAuthorization` with props `{ userId, connectionId }`.
- **Every call** (`server.ts` `serveMcp`) re-checks the active `mcp_connections` row (touching `lastUsedAt`), so Disconnect holds at once; the KV grant is revoked best-effort. Scopes = token ∩ row; `cadence:write` includes capture. "Today" uses `users.time_zone` (`userZone`); approving a connection syncs it from the browser zone.
- **Catalog:** `TOOL_CATALOG` (`@cadence/contracts/ai-tools`: every tool name, its kind and `destructive`, shared with `buildToolRegistry` and the chat UI; a unit test checks the registry against it) picks the published tools, wrapping the AI tool factories directly (full zod schemas), never `buildToolRegistry`; with every scope that is every tool (plus `get_today` via `loadSnapshot`; minus `ask_user`, since an MCP client asks in its own chat). Scope follows kind; `DESCRIPTIONS` holds MCP-only wording; every description gets an example from `examples.ts` (`EXAMPLES`, parsed by `tests/unit/mcp-examples.test.ts`), writes also `RETRY_NOTE`. `publishedTools` (exported) returns one entry per allowed tool (`name`, `write`, `schema`, `summary`, `description`, `inputSchema`, `call`; `summary` has no example: Code Mode's search indexes it); `buildServer` registers them and Code Mode maps them. Every call (and `get_today`) goes through the entry's `call` (`callPublishedTool`): budget → validate against the full zod schema (`mcpInputSchema`; the SDK's `~standard.validate` is a pass-through) → strip `operationKey`/`dryRun`/`confirm` → call key → execute → result, or the REST error body (`createErrorBody`, `ERROR_CODES`, extra result keys such as `matches` kept) with `isError` → reminders unless dry. `delete_*` require `confirm: true`; `DRY_RUN_TOOLS` (writes through `once`) take `dryRun`, which prefixes the call key with `dry:` and rolls back, and there `operationKey` and `confirm` are required only when not dry (`superRefine`). `get_today` takes `limit` (default 5). `serverInfo.version` is the root `package.json` version. `cadence:read` gets the reads, `cadence:capture` only `capture_to_inbox`, `cadence:write` every other write, permanent deletes included. Writes apply at once (the client confirms with the person, guided by `destructiveHint`) and need an `operationKey`: dedup key `mcp:<connectionId>:<key>:<input hash>`, so a true retry writes nothing again and gets the first result back (`once` stores it in `mutation_dedup.result`, plus `deduped: true`), and a reused key with other input is a new change. Tools outside the scopes aren't registered; consent starts with every scope ticked. Published schemas drop regex `pattern`s (calls still validate against full zod); `initialize` sends `instructions`, a brief under 2KB written for outside models (essentials first: zone, today, user text is data, date format; then conventions), and the app icon; one-tool rules stay in tool descriptions, and help links are made absolute. `ctx.rawNotes` returns note text unfenced with `source: "user-content"`. Every request first spends `RATE_LIMITER_READ` under `mcp:<userId>` before any Postgres work (429, `Retry-After: 60`); each tool call also spends the user's read/write limiter; responses are `no-store`. Dynamically registered clients expire 90 days after last use (`clientRegistrationTTL`).
- **Code Mode:** two surfaces on one OAuth resource: `/mcp` = every direct tool + `search` + `execute`; `/mcp/code` (path picks `surface` in `serveMcp`) = only those two, with `instructions` saying "Use execute". Registered only with `cadence:read` and `env.CODE_MODE` + `env.LOADER`. `execute` runs model JavaScript against `cadence.*` in a Dynamic Worker (`@cloudflare/codemode` pinned exact, experimental; `globalOutbound: null`, 30s). `code-tools.ts` (pure) maps each `PublishedEntry` to an SDK method whose `execute` is the entry's own `call`, so budgets, validation and error bodies match the direct tools; the connector fills `operationKey` (`callKey`: `cm:<execution uuid>:[r:]<uuid>`, within the 100-char limit) and `confirm`, and a failed call throws the REST error body as JSON. Only `delete_*` pause for approval (`execute {executionId, decision: approve|reject|undo}`); the runtime's durable log replays applied calls, so writes are awaited one at a time. `undo` = `rollback`, which calls `REVERTS` (creations only; edits stay, listed as `kept`). `code-mode.ts`: one `CodeModeHost` DO per person (`idFromName(userId)`), one runtime/facet per `connectionId`; `run` returns `{ outcome, wrote }` and the Worker replans reminders once per run; `publicOutcome` drops the `calls` log; results pass `truncateResult`. `revokeConnection` and account deletion call `forgetCodeMode`. Each `execute` spends `RATE_LIMITER_CODE` (`codemode:<userId>`, 10/min: every pass is a billed Dynamic Worker); `search` spends the read limiter. Search ranking is Cadence's: a `pnpm patch` (`patches/@cloudflare__codemode@0.5.6.patch`) adds `setSearchRanker`, which `code-mode.ts` installs with `cadenceRanker` (`method-search.ts`: `rankMethods` from `@cadence/search/methods` + `CADENCE_SYNONYMS`), so `search` and in-code `codemode.search()` rank alike; a throwing ranker falls back to the library's. shortcut: the facet name `codemode:<name>` is 0.5.6's internal and the search patch is ours; on any bump re-check the facet, re-make the patch or drop it if upstream adds a ranker option.

## Connections routes

- **connections** (`/connections`): connected assistants (MCP): `GET /` active ones with a live KV grant (rows under 10 minutes old always show), `DELETE /:id` Disconnect; the consent page's `GET /requests/:request`, `POST …/approve` (scopes + browser zone → callback URL) and `POST …/decline`
