# Push, Reminders & Live Sync — Agent Instructions

Part of the backend: `apps/backend/AGENTS.md` §13 covers the other background jobs and why nothing may wake Postgres on a short timer.

**Reminders** (`domains/push`): `ReminderClock` (`reminder-clock.ts`; one SQLite-backed Durable Object/person, binding `REMINDER_CLOCK`) holds a plan derived by `plan.ts`: one RLS read of settings, devices, tasks, routines + logs, personal events and `notification_state`, then `deriveReminders` + `dueAlert` (`@cadence/domain/reminders`, the OS-alert policy shared with the app: quiet hours, `notifications.pausedUntil`, dismiss, defer) asked at each instant the answer can change (alert, deferral, quiet-hours or pause end) over 7 days. The alarm is the next alert.

- **`alarm()`:** no Postgres query; dedupes each `(occurrence, device)` in DO storage for 3 days; retries a failure each minute ≤ 3 times while timely; drops a `gone` device at once; merges what it sent into storage re-read after sending (a rebuild may land mid-send). A throwing alarm or failed rebuild re-arms after 5, 15, 60, then 240 min; a failed rebuild also marks the plan `stale`, so the next alarm rebuilds before sending. The first build seeds dedupe from `push_deliveries` (the old cron's last day; read only for that; `push_user_ids` unused). Device outcomes (`lastSuccessAt`, `failureCount`, 404/410 deletes, 10 failures drop) are written at the next rebuild.
- **Rebuilds** (`replanReminders`, `waitUntil`, never throws) follow every successful non-GET `/api/v1` request (`replanAfterWrites`, except `/ai/*` other than `/ai/memory/*`, `/events`, `/search`), each MCP write, the end of a chat turn whose tools wrote, and the plan running out (a push-device person who never writes gets one a week). An endpoint handover (`push_release_endpoint` returns the old owners) rebuilds the old owners' clocks. Account deletion calls `forget()` (a rebuild finding no `users` row forgets too, so nothing of a deleted account stays). `PUT /push/devices` (a device's hello on each start) replans without a ping.
- **Sending:** no transaction open while calling push services (`web-push.ts`: VAPID + aes128gcm via `@block65/webcrypto-web-push`, bodies padded to 4 KB, redirects refused, no endpoint/key ever logged; `pushPayload` sends a `mutable` Declarative Web Push message navigating on `appOrigin`, plus the older flat fields). `notifications.browser` is the account master gate; `devices.enabled` the per-device one.
- **Live sync:** same object holds the person's sockets (Hibernation API; `GET /api/v1/live`, `apps/backend/AGENTS.md` §4): JWT in `Sec-WebSocket-Protocol: cadence.live, <jwt>`, or a reconnect ticket `t.<userId>.<secret>` the clock handed a JWT socket (7 days, newest 20 in DO storage, checked by the clock, no Neon Auth call; its id must be a UUID and it spends the caller's IP budget, `live:<ip>`, never that person's). A refusal is an accepted socket closed with `4401` bad token, `4429` rate-limited or `1011`; `4001` on account deletion. Every `replan` first bumps `liveVersion` and sends content-free `{v}` (independent of VAPID and Neon) to each socket except the writer's: sockets are tagged with the page origin offered as a third subprotocol, and requests carry it as `X-Cadence-Origin`. Background writes after a response (`suggestPlacement`, `suggestEffortGuess`) ping everyone via `pingLive`. Without VAPID the clock keeps only `liveVersion`, no account id; `ping`→`pong` is answered without waking the object.
- Task metrics (`platform/metrics.ts`) silently track reschedule count, first-scheduled, completed-at and created-to-done duration — internal only, no public API.

## Routes

- **push** (`/push`): Reminders on devices: `GET /config` (public VAPID key, null = push off) · `PUT /devices` registers the caller by its `installId` (stable per browser profile or app install, so a changed endpoint stays one row) with a `kind`, a `label` and an optional subscription — endpoint must be https on a known push service, keys are size-checked, and `push_release_endpoint` hands an endpoint between accounts; a device without a subscription (the desktop app) is still listed · `GET /devices` the account's devices (never endpoints or keys) · `PATCH/DELETE /devices/:installId` switch one on/off or forget it, from any device · `POST /test` one push to the caller's own device, ignoring quiet hours (409 when that device has nothing to push to). 503 `PUSH_UNAVAILABLE` without VAPID keys; max 15 devices
